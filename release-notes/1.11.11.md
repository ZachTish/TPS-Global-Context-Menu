# TPS Global Context Menu 1.11.11

This patch makes TPS List fallback note-tag filtering faster and more internally consistent without changing any released result or workflow.

## What changed

- A note-tag predicate now obtains one supported Obsidian `MetadataCache.getFileCache` snapshot and reuses it for both frontmatter tags and body tags.
- The released implementation queried the same note twice for each evaluated tag predicate.
- The patch adds no persistent cache, custom invalidation, state, retry, fallback, monkeypatch, or private API.

## Compatibility and migration

- This is a backward-compatible patch release.
- Frontmatter tags, body tags, `#` and non-`#` forms, case normalization, duplicate removal, ordering, missing-cache behavior, tag aliases, filter operators, settings, commands, public APIs, and note data remain unchanged.
- A deliberately rotating metadata-cache harness now returns one coherent generation instead of combining frontmatter from one generation with body tags from the next.
- No settings or note-data migration is required.
- Minimum supported Obsidian version: 1.10.0.

## Measured effect

Actual released and candidate `TpsListView` classes were compared directly.

- Eleven representative string and object predicates produced identical results.
- Seven full fallback-scan scenarios produced identical files and ordering.
- Metadata lookups for one tag predicate fell from two to one, exactly 50% of tag-specific reads.
- Mixed scenarios save one lookup for every evaluated tag predicate while non-tag and file-only scenarios are unchanged.
- Across seven 200,000-iteration informational runs, median elapsed time changed from 115.253 ms to 107.827 ms, a 6.44% reduction. The deterministic lookup reduction is the acceptance metric; this isolated timing is not a claim of a whole-application speedup.
- The final bundle is 45 bytes smaller than the exact 1.11.10 artifact.

## Validation

- Exact 1.11.10 was pinned at commit `8c244900035338dbe1335b6bf80d83ecfa8ff882`.
- Its complete 555-check declared suite, TypeScript check, and build passed with runtime deployment suppressed.
- The new regression fails against the released implementation because it performs two lookups and can blend rotating cache generations.
- The candidate focused TPS List suite passes 31/31, including frontmatter/body merging, duplicate and case normalization, missing metadata, rotating snapshots, and the exact one-read contract.
- The exact versioned release tree passes 556/556 declared checks, TypeScript, and the mandatory separate production-mode build.
- In Obsidian 1.12.7, the released and candidate builds both rendered exactly two rows in the same synthetic TPS List view: one frontmatter-tagged note and one body-tagged note; the untagged control remained excluded.
- Runtime-owned `data.json` and `recurrence-session.json` remained byte-identical across deployment, reload, and UI verification. Production was not accessed.

## Known limitations

- This optimizes the supported synthetic fallback note scan; it does not remove that compatibility path.
- The impact is concentrated in TPS List note views whose fallback filters evaluate tags. Other filters and native Base processing are unchanged.
