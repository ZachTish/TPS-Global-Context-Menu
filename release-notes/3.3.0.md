# TPS Global Context Menu 3.3.0

New native food logs no longer need a whole-vault source scan to reserve their identity when used with **Health 3.2.1+**.

This minor release adds `nativeRecords.createFresh(kind, properties, options)` and `capabilities.freshIdentityCreates` to API v6. GCM allocates a cryptographically random UUIDv4 using Web Crypto and returns the persisted ID. Callers cannot select/reuse an ID, plan token, expected path, or protected system property. This route relies on standard UUID uniqueness rather than searching every file for its newly minted ID. Known-owner checks, in-flight reservations, exclusive plans, property validation and non-overwriting file creation remain.

The original `create`, resolve/update/reidentify and identity-plan routes retain authoritative source checks for supplied/existing IDs, including stale metadata and malformed/nonstandard YAML. Fresh creation does not falsely certify the global index or wait for an already-running verification. If secure random generation is unavailable, it uses the existing verified creation path. No private metadata-cache API is used.

No settings, defaults, schema or existing ID migration. Minimum Obsidian **1.10.0**. Feature-detect both the method and capability. Install **GCM 3.3.0 and Health 3.2.1** together for the food-save fix.

## Validation

- GCM: **101 focused native-record tests**, **1,228 full-suite checks**, and **160 additional checks**, all passing. Tests cover a cold 10,000-note vault representing 30 seconds of serial I/O at 3 ms/read, zero verification reads for fresh creation, a pending scan, protected properties, caller-ID rejection, known conflicts, in-flight reservations, exclusive plans, storage failures/retry cleanup, secure-random fallback and strict detection of nonstandard YAML identities.
- Health: **480 tests passed, 0 failed, 1 optional live USDA test skipped** without its credential. Fresh/older-GCM paths, returned IDs, unchanged nutrients, error propagation and absence of a second write after failure are covered; existing tray duplicate-click/partial-save checks pass.
- Installed **Obsidian Plugin Test Vault** QA explicitly cleared GCM's authoritative source cache and marked the index unverified, then called the full Health food-save path twice. The first save, including a reusable food note, took **585 ms**; the next took **102 ms**. Native entry creation took **107 ms** and **41 ms**, respectively. Both made **zero vault-wide verification reads**. The pre-fix cold save measured **6,824 ms with 9,044 source reads**.
- Persisted UUIDs matched Health's returned IDs. Half of a 200-calorie serving remained 100 calories. Fixtures were archived directly from Inbox to `_archive/QA-food-fresh-final-20260923`; probes and temporary folder overrides were restored. Both Health and GCM settings remained byte-identical. No provider calls, outbound automation or production access.
- TypeScript and mandatory separate final builds passed for both versioned artifacts. Both final builds reported `target=test` with unchanged bytes relative to installed QA. Named-vault reloads verified Health 3.2.1, GCM 3.3.0, and the fresh-create capability/method. Runtime/source artifact hashes match.

Timings above are desktop test-vault measurements. The 30-second test models serial storage delay; physical iPhone timing is not claimed. Existing-ID edits/reconciliation and older-GCM fallback retain their verification behavior. Ordinary storage delays from the operating system or other queued work are separate from the removed vault-wide scan.

Tested in the test vault and ready for the user's **BRAT pull of both releases**. Publication does not install the updates in production.
