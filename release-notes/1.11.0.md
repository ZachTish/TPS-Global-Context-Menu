# TPS Global Context Menu 1.11.0

## What changed

- Custom fields now support seven composable value-source modes: Manual only, Vault values only, Entities only, Manual + vault, Manual + entities, Vault + entities, and Manual + vault + entities.
- **Accepted kinds** accepts multiple comma- or newline-separated Kind identities. A field configured with `project, area` queries the generic entity index for Project OR Area records and excludes unrelated Kinds.
- Entity-backed choices work across note and line menus, task editing, `@@`, TPS List, and TPS Table. They remain available for every compatible property type, including fields such as relational Status that would otherwise use a native typed editor.
- Settings persist Accepted-Kind edits while typing, preserve an existing source combination while the text is being edited, and canonicalize the saved Kind list without introducing a new persisted schema field.
- TPS Table and TPS List keep configured and generic writable cells property-owned, including empty cells, instead of navigating to the containing note.
- Notebook Navigator smart sort now assigns every note a deterministic category while enabled buckets exist. The first matching bucket wins, and unmatched notes receive the category after every configured match instead of losing their sort key.
- Icon and color outputs independently use the first nonblank matching rule. Reordering, enabling, disabling, or deleting rules reconciles existing notes, the preview identifies the winning rule, and Sort includes an explicit **Apply all notes** repair action.

## Compatibility and migration

- This is a backward-compatible minor release: it adds composable relational sources and multi-Kind constraints while retaining existing persisted keys and note formats.
- The persisted `acceptsKind` value remains a string. Multiple Kinds are stored canonically as a comma-separated value, so existing single-Kind settings remain valid.
- Legacy **Vault values** maps to Manual + vault. An older Accepted-Kind field with no explicit source defaults to Entities only.
- Existing out-of-Kind links and literal values remain visible and editable until changed; no note-data migration runs automatically.
- Minimum supported Obsidian version: 1.10.0.

## Validation

- The integrated focused gate passed 127/127 tests, and the final Accepted-Kind persistence plus line-routing gate passed 33/33 tests.
- TypeScript and the complete declared `npm test` suite passed after the final runtime changes.
- The mandatory separate production-mode build passed and reported the test runtime unchanged because it already contained the same final artifact.
- Obsidian 1.12.7 was reloaded in the test vault. Smart Sort displayed **Apply all notes** and the unmatched-note fallback contract.
- The live custom-field editor showed Accepted kinds `project, context, person, team, client` and all seven value-source choices.
- An empty Related Entities cell opened `Search project, context, person, team, client entities…` with both note and line candidates from those Kinds. An empty Projects cell opened `Search project entities…`. Both remained in the Base and were canceled without selecting a value.
- Runtime-owned `data.json` and the permanent relational fixtures remained byte-identical after UI verification.
- Production was not modified. This test-vault-validated release is ready for the user's BRAT pull from its matching numeric tag and public GitHub release.

## Known limitations

- The Kind identity field registers an entity; relationship fields use Accepted kinds to choose which registered entities they accept.
- Existing values outside the current Kind constraint remain stored and visible. The constrained picker governs new choices rather than deleting data.
- Entity line choices require addressable Markdown task, bullet, or ATX-heading records. Ordinary paragraphs are not indexed as line entities.
