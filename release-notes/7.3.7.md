# TPS Global Context Menu 7.3.7

Backward-compatible fix for heading-link suggestion ownership. A retained
heading cursor no longer makes sidebar, modal or global-search input scan the
vault. Suggestions require the active focused Source/Live Preview editor;
keyboard and mouse acceptance also require the original editor and file.
Stale popups cannot consume unrelated Arrow, Enter, Tab or Escape keys or insert
a link into the previous note.

Text-change searches use Obsidian's public, after-commit `editor-change` event,
including changes that produce no keyup. Only ArrowLeft/Right/Up/Down, Home/End
and PageUp/PageDown keyups may search; the existing editor/file/cursor context
rejects a repeat search while the popup's cursor is unchanged. Typing searches
once instead of again on keyup, popup arrows keep the chosen suggestion without
rescanning, and Escape stays closed after keyup. Navigation still works with no
popup. Modified and composing keydowns remain editor/IME-owned; modified cursor
movement still refreshes, even if its modifier is released before the arrow.

Captured input only dismisses an ineligible popup. The old unowned keydown
timeout is removed, preventing a queued refresh after unload and avoiding
pre-commit CodeMirror reads without a replacement timer, debounce or cache.
Matching, ordering and Markdown link formatting are preserved.

No settings, API, schema or minimum-version change; minimum Obsidian is 1.10.0.
This fix adds no background normalization, automatic vault mutation or
note-content migration.

The GCM List tests also stop reading the retired standalone TPS Kanban
repository's view, main and stylesheet. Only those external reads and their
retired-source assertions were removed; no supported GCM List test was skipped
or deleted, and GCM's active shared Kanban-named utilities remain intact.

## Validation

- Baseline 7.3.6: one keydown/input/keyup sequence in each of three unrelated
  input surfaces triggered three full inventories and 12,000 metadata reads
  with a 4,000-note in-memory vault. Fixed: zero inventories and metadata reads.
- The initial regression set failed 15 tests against 7.3.6. Focused heading
  keyboard and mouse selection already passed and remain supported.
- Follow-up ordering regressions demonstrated that simply deleting the timeout
  could miss the final heading when captured input preceded the editor commit
  and no keyup followed. After-commit events now cover that sequence with and
  without a preceding keydown, without any deferred refresh.
- Nine additional before-failing sequence regressions cover duplicate typing
  scans, Escape reopening, popup-arrow rescans, navigation modifiers and
  composition ownership. A typed letter's editor-change/keyup sequence in the
  4,000-note fixture now performs one inventory/4,000 metadata reads instead of
  two/8,000. All 37 focused heading tests pass with no failures or skips.
- `node scripts/qa-heading-link-input-order.mjs`: all six browser scenarios
  pass. Real CodeMirror 6.38.6 capture sees `# H` before its MutationObserver
  commits `# Heading`. The old route needs a preceding keydown timer; a
  capture-only variant misses the committed heading. The after-commit route
  searches once with or without keydown and with no keyup. This harness
  simulates Obsidian's callback according to its public after-commit contract;
  popup rendering is stubbed and physical IME input is not exercised.
- `node --test scripts/test-tps-list-view.mjs`: all 55 active List tests pass
  after removing the retired-repository dependency, with no failures or skips.
- Final versioned `TPS_NO_DEPLOY=1 npm test`: 1,588 passed, zero failures or
  skips. Supplemental `npm run prepretest`: 210 passed, zero failures or skips.
  The test-run build succeeded with runtime deployment suppressed. TypeScript
  and `git diff --check` also pass.

## Installed test-vault evidence and boundaries

- Before the final keyup refinement, a programmatic host-boundary probe of the
  installed compiled builds used the actual 14,223-note test vault. The 7.3.6
  unrelated-input sequence performed three inventories, 42,669 metadata reads
  and three renders (approximately 412 ms); 7.3.7 performed zero of each. Its
  focused heading probe still performed one inventory, 14,223 metadata reads
  and one render. These are service/probe results, not foreground click-to-paint
  or physical-device latency measurements.
- An actual Obsidian `editor.replaceRange` operation emitted the public
  `editor-change` event with the already-applied `# Heading` text and saved the
  source without a keyup. The window was hidden and the editor was unfocused,
  so this confirms the host event boundary, not focused-popup or IME behavior.
  The first fixture received the configured GCM title frontmatter; a rerun with
  an authored title preserved the expected body exactly. Fixtures were archived
  and the settings hash was unchanged.
- Separate final production-mode build passed and deployed only to Obsidian
  Plugin Test Vault. A named-plugin reload confirmed 7.3.7; all four installed
  artifact hashes match the final source build. Settings files remain unchanged.
- The final installed host-boundary probe again made zero inventories, metadata
  reads or renders for unrelated input. The eligible heading search still made
  one inventory and one render across 14,229 notes. Its typed-key keyup added no
  search, Escape remained closed, and popup-arrow selection changed and stayed
  selected without rescanning. Focus/editor and popup rendering are mocked in
  that probe; it is not foreground keyboard or physical-device validation.
- The final artifact's actual Obsidian editor-event check again observed applied
  text without keyup and preserved the saved fixture exactly. Its own tab was
  detached and note archived; settings stayed unchanged.

These checks do not establish that all navigation stalls are fixed. Physical
mobile/Windows latency, focused popup presentation and actual device IME/keyboard
acceptance remain separate. Test-vault validation does not establish production
installation; the user's BRAT pull is the production handoff.
