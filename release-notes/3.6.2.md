# TPS Global Context Menu 3.6.2

Backward-compatible performance fix for redundant work during startup, navigation and note creation. Patch release; minimum Obsidian remains **1.10.0**. No settings, schema, API or data migration.

## Changes

- Calendar navigation counts skip reading plain-note bodies when Obsidian's metadata already proves they contain no checkboxes. Real tasks and notes without metadata keep the existing parser.
- Startup recurrence checking rejects notes without a recurrence rule before reading authoritative source. Recurrence candidates retain source and template protection.
- Navigator appearance rules skip unchanged output before protection reads and the serialized mutation queue. Actual changes still recheck exclusions and recompute against current source at the atomic writer.
- Removed the second forced creation-rule replay at 3.8 seconds and redundant active-note filename timers. Existing create/template settlement and debounced filename synchronization remain the owners.
- Retired parent reconciliation no longer emits file-change/render notifications for an empty result.

No new caches, watchers, retry loops, repair passes or extra settings. Existing configured automation remains available; this release does not make every creation route or cold index constant-time.

## Validation

Desktop Obsidian 1.14.2, **Obsidian Plugin Test Vault**:

- `npm test`: **1,260 passed**, zero failures, including TypeScript/build.
- `npm run prepretest`: **171 passed**, zero failures.
- Focused regressions cover 1,000 unrelated notes, repeated unchanged rules, actual edits, exclusions changing at the write boundary, source preservation and empty parent maintenance.
- Separate final `npm run build`: passed and deployed only runtime artifacts to the test vault.
- Named test-vault disable/enable reload verified 3.6.2. Runtime settings remained byte-identical.

Installed startup-candidate probe: 128 existing synthetic files with scoped nonrecurring metadata made **128 raw reads before, zero after** (65 ms versus 2 ms). This measures the recurrence candidate pass, not whole-application boot time.

Combined navigation sample with GCM 3.6.2, Navigator 7.0.2, Health 3.7.2 and Calendar 0.16.1: four switches between two synthetic notes reduced identity inspections **72,849 → 448** and measured open durations **15/550/504/19 ms → 20/29/24/20 ms**. Maximum observed timer delay decreased **2,900 → 904 ms**. The test window was backgrounded with timer throttling enabled, so the 904 ms timer delay is not evidence of a remaining CPU stall. A visibly focused repeat measured opens of **42/11/15/11 ms**, **594 identity inspections**, no observed long tasks, and maximum timer drift of **18 ms**. These are small sequential samples, not production/iPhone guarantees. Test-vault background automation remained disabled; configured automatic rule behavior is covered separately by the focused tests. The production navigation profile used its actual enabled configuration but production artifacts were not changed.

Real Calendar-to-GCM creation used the shared registry, created an Inbox note in **59 ms**, and completed its configured preview handoff. The initial title, valid frontmatter and immediate editor body change remained intact after 4.5 seconds. Calendar's isolated source-ownership tests and the combined installed flow are documented in Calendar 0.16.1's release notes. Physical iPhone and live Templater execution were not exercised.
