# TPS Global Context Menu 1.29.0

TPS Global Context Menu `1.29.0` makes Linked context durable and deterministic, adds a non-destructive parent/child ignore policy, broadens tag entry, scopes completed-task hiding, and keeps note scheduling independent from time tracking.

## Linked context

- **Workflows → Child notes → Linked context order** sorts incoming context by source path A → Z or Z → A. Excerpts within one source retain physical document order, and modification time is never a sort key, so checkbox/status/property interactions do not make cards jump.
- A view-scoped observer recovers a detached panel when Obsidian replaces its Reading View or Live Preview mount during scrolling. Recovery is coalesced and revalidates the active file, mode, settings, source revisions, and mount before committing one replacement.
- Changes, renames, and deletions of linked source notes invalidate dependent panels. Existing panels remain mounted until a complete current replacement is ready.

## Parent/child ignore policy and tags

- **Ignore matching parent/child notes** adds one disabled-by-default exact frontmatter key/value rule. Matching is case-insensitive after trimming and supports scalar values or any matching scalar list member.
- Matching notes are excluded from discovery, panels, new parent/child links, linked-checkbox/property mutation, derived-status synchronization, and relationship automation. Existing body links and frontmatter relationships are not deleted or rewritten, and become active again when the rule no longer matches.
- GCM add-tag fields accept comma- or whitespace-separated values across note, task, bullet, TPS List, and TPS Table tag actions. Values are normalized and deduplicated before the existing atomic, stale-safe mutation runs.

## Reading-view task hiding

- **Hide completed task lines** can now apply to **Reading view only** or retain the earlier **Reading view and Live Preview** behavior. Source mode is never hidden.
- Complete and won't-do mappings plus migrated `[>]` rows use the same scope inside Linked context. A terminal single-line card hides as one unit; heading/note excerpts retain their nonterminal content and hide only terminal task rows. Existing exclusions and temporary reveal state still win.

## Time tracking

- A note-linked session no longer creates, changes, or deletes note-level `scheduled`, `timeEstimate`, or end metadata. This also protects authored scheduling when the tracked note is the session-start Daily Note itself.
- Task-linked sessions continue to synchronize schedule/duration on the exact task line. Every running or manual session still creates or reuses its stable `## Time Tracking` / `###` workspace in the session-start Daily Note.

## Compatibility

- This is a backward-compatible minor release. Existing linked-context placement/open behavior, parent/child relationships, tag storage, task-hiding exclusions, timer records, and task-line scheduling remain compatible.
- New defaults preserve prior behavior: source-path ascending order, parent/child ignore disabled, and completed-task hiding in Reading View plus Live Preview when hiding is enabled.
- No bulk note or settings migration runs. Minimum supported Obsidian version remains `1.10.0`.

## Known limitations

- Linked context currently offers source-path A → Z and Z → A ordering only; excerpts from one source always retain physical document order.
- The parent/child ignore policy evaluates one exact frontmatter key/value pair. It does not rewrite or remove existing relationship metadata or body links.
- The new settings do not add item-history events, migrate existing relationships, or perform a bulk tag rewrite.
