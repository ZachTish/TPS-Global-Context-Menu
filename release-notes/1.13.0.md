# TPS Global Context Menu 1.13.0

## Intent

Make TPS Home configuration self-contained and make Daily Note Home substitution responsive, event-driven, and safe under rapid setting changes.

## Changes

- Added **Use TPS Home for Daily Notes** under Home & daily notes. Disabling it restores date-backed Home leaves to Markdown Reading view; standalone TPS Home remains available.
- Removed the four built-in Home Base-path text fields from Settings. Calendar, Food tracker, Activity log, and Open unscheduled tasks now expose **Choose Base** / **Change Base** in Home edit mode.
- Configured built-in Base paths are authoritative. Custom missing paths fail visibly instead of silently selecting another Base; only canonical Food/Activity defaults retain their provider-owned creation path.
- Removed Home's forced Calendar day-count preservation so TPS Calendar Base can adapt to the actual Home panel width.
- Removed the 600 ms whole-workspace Daily Note scan. Supported workspace and vault create/rename/delete events feed one serialized reconciliation drain. Date-backed Home leaves retain their exact `TFile` identity through file and folder renames, including repeated renames and path reuse by another file; failed transitions retain their own intent for one bounded immediate retry and later supported events. Every queued leaf is revalidated immediately before mutation so a newer user navigation or a closed leaf is not overwritten.
- Renaming an open Markdown note into Daily Notes converts it; renaming a date-backed Home updates its exact path/date or restores normal Markdown/native handling when moved outside Daily Notes. Deleted backing files become standalone Home, delayed Sync-created files rebind unresolved Home state, and config-drift/non-Markdown backing files restore through Markdown or their native view. Startup-disabled restoration uses only temporary lifecycle listeners while layout is pending, then removes them after restoration.
- Home Base pickers now admit only exact lowercase `.base` files, matching Calendar Base's public renderer contract. Existing shared file pickers retain their prior case-insensitive behavior. Per-setting serialized writes and compensating persistence prevent rapid or post-write-failed choices from splitting Home UI, memory, and disk.
- Added layout-ready restoration for startup-disabled persisted Home leaves, deterministic post-picker focus/scroll restoration, scoped focus-visible styles, and wrapped 40-pixel phone edit controls.

## Compatibility and migration

- Backward-compatible minor release; no command, API, note, or Base migration.
- Existing `homeCalendarBasePath`, `homeFoodBasePath`, `homeWorkoutBasePath`, and `homeOpenTasksBasePath` values remain authoritative and editable from Home.
- A one-time, non-destructive settings normalization persists missing or previously normalized Home paths and `enableDailyNoteHome`; existing valid values are preserved and no user action is required.
- Minimum supported Obsidian version: 1.10.0.

## Known limitations

- A built-in card whose configured custom Base no longer exists shows its unavailable state until a replacement is chosen in Home edit mode.
- Daily Note Home conversion depends on Obsidian's supported workspace and vault events. A transition rejected twice is retained for the next supported event rather than retried indefinitely; no periodic fallback scan remains.
