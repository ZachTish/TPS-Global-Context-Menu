# TPS Global Context Menu 10.2.1 — Native Bases menus

A native Kanban card could show only Obsidian's file actions because GCM's DOM allowlist did not recognize the card. Core's file-menu event already supplies the exact file. GCM now routes native file-link and Bases selection events directly to its existing exact-file menu builder. The native-menu path retains existing ownership marking, duplicate-action handling and inline-menu-only configuration. Stale explorer or Navigator selection cannot replace the selected file set.

This is a backward-compatible patch. No settings migration, note migration, new background service, scan, observer or writer is introduced. Foreign menu hosts retain their existing default behavior. The retired TPS Kanban plugin is not restored.

## Validation

- Full `npm test` passed: 1,970 test executions, zero failures. Five actual registered-callback tests cover native single-file and multi-file events, inline-only mode, stale ambient state, folders, source ownership and 2,000 repeated event routes without vault work/DOM discovery. The actual menu-builder integration verifies native ownership marking and repeated-augmentation suppression.
- Separate final `npm run build` passed and deployed to `Obsidian Plugin Test Vault`; GCM was unloaded/reloaded there. The final documentation-only build was byte-identical to the UI-verified artifacts.
- Actual native Kanban card context menu on Obsidian 1.14.4 displayed the correct title and GCM actions, with native actions retained under More options and duplicate Delete suppressed. All 98 synthetic notes and GCM data.json remained byte-identical. Fixtures were moved to the test vault's archive.
- Native multi-selection has callback/builder regression coverage, but its physical UI gesture and iPhone acceptance are unverified. No external provider automation was enabled.

Minimum Obsidian version remains 1.10.0. Native Kanban availability depends on the installed Obsidian version; this release was checked on 1.14.4. Tested in the isolated test vault and ready for the user's BRAT pull. This release is not directly installed in production and is not a Calendar performance fix.
