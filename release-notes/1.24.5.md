# TPS Global Context Menu 1.24.5

TPS List now keeps untagged and otherwise unmatched items at the edge selected in that Base view's grouping settings.

## Changes

- **Items without a group → Top / Bottom** is now authoritative over saved manual lane ordering.
- Manual lane order continues to arrange populated groups without retaining a stale position for the unmatched lane.
- The selected placement is reapplied after task-specific lanes are synthesized, covering task-tag grouping as well as ordinary unmatched rows.

## Compatibility and migration

- Minimum Obsidian version: 1.10.0.
- No note schema or global plugin setting changes are required.
- Existing TPS List Base views retain their current per-view placement choice; views without a choice continue to default to Bottom.

## Validation

- Focused regression coverage validates Top and Bottom placement when an older saved manual order includes the unmatched lane.
- The complete declared test suite, TypeScript check, and separate production build were run against the final versioned artifact in the isolated Obsidian Plugin Test Vault.
- The deployed test-runtime files byte-match the release artifacts. UI automation was not run because the active Obsidian app was the production vault; production was left untouched.
- Production was not inspected or modified.
