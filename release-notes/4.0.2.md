# TPS Global Context Menu 4.0.2

Completing a note no longer runs the same checklist decision twice. Previously the status wrapper checked the checklist and then called the shared property writer, which checked it again. Choosing Ignore could prompt again; notes without open items were also scanned twice.

- Keeps the configured checklist decision in the existing shared property writer. Direct mapped-status edits remain protected.
- Records an accepted checklist decision when it finishes, so time spent answering does not expire the existing external-status recognition window before the save. The existing four-second expiration remains unchanged.
- Preserves Cancel/Open behavior, parent-check ordering, multi-file no-prompt behavior, write guards, and current-source/body preservation.
- No new state, listener, timer, cache, retry, recovery system, settings, schema or API.

Backward-compatible patch. Minimum Obsidian: **1.10.0**.

Validation: thirteen composed regressions, six failing before their corresponding corrections; 87 focused, 1,380 declared and 209 supplemental checks pass with zero failures/skips. Tests execute real status/checklist/frontmatter implementations with mocked host storage and modal choices, including Ignore/Cancel/Open, completing/canceling items, mapped keys, guard/concurrent edits, parent cancellation, unchanged bursts, disabled/multi-file behavior and a simulated ten-second response with subsequent expiration. TypeScript, separate normal build/deployment and named reload passed in Obsidian Plugin Test Vault; data.json was preserved.

Installed API completion with all consumers enabled on a plain note and an already-checked checklist: handler/scan counts fall from two each to one; target raw reads from 5/4 to 4/3. Both keep one source modification and one notification, preserve body bytes and complete correctly. Cached-read counts varied from 3/2 to 4/5; no overall timing improvement is asserted from these small samples. Four fixtures were archived and seven settings files preserved. Actual modal gestures, physical iPhone, cold launch and native-performance parity are not claimed; production was not deployed.

Tested in the test vault and ready for the user's BRAT pull once published. Production installation and user/device acceptance remain separate.
