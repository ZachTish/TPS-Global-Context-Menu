# TPS Global Context Menu 1.45.0

Native Markdown records no longer create a unique Obsidian tag for every generated item. GCM now writes stable identity through the configured ID and schema properties only, while `tags` remains reserved for meaningful user and workflow classification.

## Property-only record identity

- New records always write property identity. A saved tag-writing profile is converted to the property writer during settings load without rewriting notes, and its exact tag prefix remains available as a read-only legacy alias.
- **Consolidate native record storage** removes recognized legacy identity tags and writes the current ID, schema, kind, title, and enabled timestamp properties. Paths, stable IDs, bodies, ordinary tags, and unrelated frontmatter remain intact.
- Built-in `tps/record` identities and saved custom tag prefixes remain readable for delayed Sync arrivals. Legacy tag aliases are pinned instead of being evicted by property-name history.
- The public `nativeRecords` API is now version 4. `getStorageProfile()` is the property-only write contract; tag profiles exposed by inspection are historical read evidence only.

## Safer mutations and recovery

- Native create, update, resolve, rename, and consolidation operations fail closed for malformed or conflicting evidence, duplicate or blocked stable IDs, case-duplicate system keys, and concurrent explicit-ID creation.
- Reserved identity tags are reconciled independently from legacy title mappings. Agreeing tags are removed; malformed, ambiguous, or disagreeing evidence blocks mutation instead of being guessed or overwritten.
- Legacy property cleanup is exact-profile scoped, so a user property that merely shares an old alias name is preserved. Current writer fields own title and timestamp precedence; unique legacy timestamps fill only missing current values.
- Native-record updates and Notebook Navigator automation now mutate only owned frontmatter fields while preserving unrelated YAML ordering, comments, quoting, multiline values, BOM and newline style, and Markdown body bytes. Proven native records keep their identity/title/tag fields protected even while global architecture mode is temporarily set to Legacy.

This is a backward-compatible minor release with no record schema, command, path, or minimum-Obsidian migration. Existing property records require no action. Minimum supported Obsidian remains 1.10.0.

Known limitation: historical tag-only IDs with a valid `hex-` segment retain the released deterministic decoding required for unsafe IDs. Without a property identity, an originally literal safe ID beginning with `hex-` cannot be distinguished from that legacy encoding.
