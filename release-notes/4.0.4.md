# TPS Global Context Menu 4.0.4

Folder moves and deletions now discover attachment-property companions once per operation. Previously GCM rebuilt the identity index, then repeated the same Markdown enumeration and companion reads to collect the records under the affected folder.

- Collects affected records during the existing index rebuild, and finishes global identity discovery before mutating any record.
- Preserves duplicate-ID rejection, malformed-record reporting, current-source merge guards, concurrent user edits, moving-folder identity handling and retained history.
- Adds no cache, watcher, timer, retry, setting, schema or public API.

Backward-compatible patch. Minimum Obsidian: **1.10.0**.

Validation: five new operation-count regressions fail before the change and pass afterward. Coverage includes a 1,000-note unrelated vault, 20 unchanged requests, duplicate identities outside the affected folder, removal of stale identity evidence, concurrent edits at the writer and malformed managed companions. All 52 focused, 1,393 declared and 209 supplemental checks pass with zero failures/skips; TypeScript, separate normal Test deployment and named reload pass.

Installed nested-folder moves reduce GCM discovery scans from four to two; Navigator’s shared tag/property scan remains. Three before and after folder moves with eight tagged notes, two text attachments, an image and six reference notes preserve note/image bytes, non-link text, twelve resolved links and the eight current tag paths. First moves rewrite the six references; later moves correctly retain shortened links. Seven settings files are unchanged. All synthetic files are archived and diagnostic wrappers are removed.

Limits: installed API checks ran visible but unfocused, with other consumers enabled and the current native-records configuration; there were no matching legacy companion records in those moved folders. Active companion mutations and concurrent/conflict paths are tested with the real service and mocked host storage. Actual pointer latency, native-performance parity, cold process startup and physical iPhone are not established. Initial authoritative companion discovery after reload remains a full-vault read and delayed queued folder work for roughly 4.4 seconds in a separate diagnostic; this patch does not fix that first-use scope. No whole-vault speedup percentage is claimed.

Tested in Obsidian Plugin Test Vault; ready for the user’s BRAT pull once published. Production installation and user/device acceptance remain separate.
