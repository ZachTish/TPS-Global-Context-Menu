# TPS Global Context Menu 4.0.1

Property edits now notify other consumers once per committed change, and the title property panel refreshes correctly when the inline menu is disabled.

- Removes the context menu's redundant whole-selection notification and forced refresh. Failed and unchanged targets no longer receive an extra success broadcast.
- Preserves explicit configured rules, independent rule-write notifications, source attribution and existing attachment refresh ownership.
- Fixes the existing display refresh owner to include property-only views in immediate and deferred refreshes. A view tracked by both collections refreshes once; typing and changed-file protections remain intact.
- No new listener, cache, timer, retry, repair, settings, schema, API or migration. GCM 4.0.0's selected-file authority contract is unchanged.

Backward-compatible patch. Minimum Obsidian: **1.10.0**.

Validation: eight regressions, six failing before their corresponding corrections; 73 focused, 1,367 declared and 209 supplemental checks pass with zero failures/skips. The notification tests compose real menu/bulk/frontmatter implementations with mocked host boundaries. Display tests execute the actual refresh/deferred methods with mocked DOM helpers and timers. TypeScript, a separate normal production-mode build, test-vault deployment and named reload passed; data.json remained unchanged.

Installed test-vault API callback checks confirmed eight writes/eight notifications instead of nine calls/sixteen path occurrences. The subsequent display check found and reproduced an independent stale-panel defect even with the former direct forced refresh. After correcting the shared view enumeration, single- and three-note changes update the mounted property-only Reading panel; an unchanged repeat emits nothing. Six fixture bodies and seven settings files were preserved and fixtures archived. All consumers remained enabled; no provider was enabled. This is rendered DOM/AX correctness, not actual context-menu pointer latency. The narrow test layout prevented useful full-panel screenshot acceptance. Physical iPhone, cold launch and overall native-performance parity remain unverified.

Tested in **Obsidian Plugin Test Vault**, ready for the user's BRAT pull once published. Production installation and user/device acceptance are separate.
