# TPS Global Context Menu 3.6.6

Patch release: prevent startup file announcements from becoming new-note work, and retain titles entered while automatic initialization waits. Minimum Obsidian remains **1.10.0**.

## Behavior

- Ignore pre-layout `create` announcements in the Daily Note invalidation and generic creation listeners. Obsidian sends these for existing files during initialization; startup metadata and the existing explicit startup owners remain responsible for discovery. Cold readiness waits for the existing public `resolved` event without scanning the vault on each per-file callback. Hot reload retains its initialized snapshot; if that runtime flag is unavailable, it waits for the next public resolution. Actual modifications during loading and new files after layout readiness keep their current-source checks.
- Recheck title eligibility against current source in the existing atomic frontmatter writer. Missing/template-title initialization cannot overwrite a title entered after its initial preflight. Moved or renamed files reject a stale filename candidate.
- Write only title/alias properties through the existing source-preserving writer, keeping unrelated formatting, comments, line endings and body text. Current native/workflow identity and tag exclusions still veto automatic title writes. The scheduled-date/template exception and meaningful aliases are preserved.
- Label derived title synchronization as automation, while retaining its file-update/index notification. Explicit Edit Title and preview saves retain their existing canonical user-action writer.

No settings, defaults, migration, new cache, watcher, delayed replay, shared API version or automatic repair. Duplicate case variants of owned title/alias keys fail closed instead of being consolidated. The existing `onlyIfHasFrontmatter` preflight does not provide a new guarantee when the entire frontmatter block is removed concurrently; that separate source-structure contract is unchanged.

## Validation

- The startup identity regression failed on 3.6.5 with **2,001 raw reads for 2,001 startup create announcements**, then passed with **zero**. Genuine pre-layout modification and post-layout creation/modification each retained one current-source refresh and correct identity despite stale metadata.
- The generic-listener regression failed with **1,000 template gates, title and timestamp calls**, **1,001 rule schedules** and one attachment-create callback during startup. The corrected listeners perform zero of that work, and actual post-layout note/attachment creation keeps the same owners.
- Real FileNamingService plus FrontmatterMutationService tests reproduce authored-title overwrites and verify current source at `vault.process`, exact-byte rejection with comments/BOM/CRLF, stale filename candidates, case variants, normal/missing/template titles, scheduled exceptions, aliases, current native/workflow identity and exclusions. Repeated already-authored titles enter no write queue and perform no raw reads or modifications.
- The initial installed candidate was **rejected before publication**: raw startup reads fell from 10,787 to 444, but its readiness fallback caused 2,547 Markdown enumerations and 26,627,309 metadata lookups in a 15-second capture. This exposed a previously masked whole-vault scan on every per-file metadata callback. The failed reports are retained; these counts are not accepted release results.
- The added actual-lifecycle regression (`initialized` undefined, then true before public `resolved`) reproduced **4,003 enumerations and 8,010,003 metadata lookups**, plus premature readiness, for 2,001 files. It requires **zero** enumerations/lookups/readiness announcements until `resolved`, then one recovery announcement. Existing hot reload, post-startup edits and concurrent-generation protections remain tested.
- Initial validation passed 105 focused, 1,293 declared and 187 supplemental checks, but did not model this intermediate initialization phase. The corrected source passed **105 focused, 1,293 declared and 187 supplemental checks**, with zero failures/skips, under Node **24.19.0** and npm **10.9.2**. TypeScript and the separate normal build passed and deployed to the test vault. A named disable/load-manifest/enable reload plus foreground renderer restart verified the final artifact; installed acceptance results are below.

No production access, deployment or performance-parity claim. Physical iPhone and full production latency are not inferred from desktop synthetic tests. The tested artifacts below are the BRAT handoff; production installation and user acceptance remain separate.

## Installed test-vault acceptance

Final foreground warm-renderer captures retained a separate timing run and operation-count run. Raw startup reads fell from **10,787 to 413**, with **nine** Markdown enumerations before and after; metadata lookups were 321,967 before and 317,965 after. The final run observed public metadata resolution and had no harness errors. It did not reproduce the rejected candidate's 26.6-million-lookup scan storm. These counts cover all enabled plugins, so the remaining reads are not attributed exclusively to GCM.

First visible synthetic body on two frames was **2,853 ms**, versus 2,860 ms in the earlier timing capture. This single warm comparison does **not** demonstrate an end-to-end startup improvement. A separate Health/GCM classification rebuild still blocks the main thread for approximately **397 ms** and remains under investigation. This was not a cold process launch, native-Obsidian comparison or mobile measurement.

Actual UI input through Navigator New note → editable preview → enter title and Return → enter body → Dismiss preview passed. Exactly one file was created, one rename occurred, title and filename agreed, and the body remained intact. The title/body saves caused two modifications, with no outside note mutations. Original navigation, search and note state were restored; temporary fixtures moved directly from Inbox to `_archive`. All seven measured plugin settings hashes stayed identical to the preceding baseline. Startup instrumentation was removed.

Tested in the isolated test vault and ready for the user's BRAT pull after this public release. Production has not been inspected or updated for this patch.
