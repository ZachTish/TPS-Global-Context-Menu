# TPS Global Context Menu 1.9.0

## What changed

- Custom fields now include **Kind (Note identity)**. Every configured Kind field contributes its frontmatter key to one global entity index, so values such as `kind: project` register their Markdown notes as project entities without hardcoded Kind values.
- Any non-Kind custom field can declare **Accepts kind**. Its editors then show only indexed notes with that Kind and store canonical Obsidian note links. Scalar fields store one link; list fields store multiple links and deduplicate by note target.
- The constrained entity picker is shared across note menus, stacked properties, linked-subitem pills, inline properties, task quick editing and task menus, `@@`, and empty or populated TPS List and TPS Table cells. Base-cell activation is keyboard accessible and does not also select or open its row.
- `plugin.api.entityIndex` provides immutable synchronous queries, ID/path lookup, dimension-value discovery, revision-aware caching, change subscriptions, invalidation, and generic dimension registration. The Obsidian-backed index builds lazily and updates for metadata, create, modify, rename, delete, and immediate GCM frontmatter mutations.
- Entity-index rebuild and invalidation notifications are atomic. Routine metadata resolution stays incremental, arbitrary dimension names are own-property safe, duplicate identities cannot leave stale paths, and table-cell writes preserve Markdown indentation and deliberate spacing.

## Compatibility and migration

- This is a backward-compatible minor feature release.
- Existing custom properties whose key or ID is `kind` are normalized to **Kind (Note identity)** when settings load. Their values are preserved, and Kind identity is kept out of task-line editors because it describes the containing note.
- Existing values remain intact when **Accepts kind** is added, including links that do not match the new constraint. The constrained picker controls future selection without destructively migrating stored data.
- Minimum supported Obsidian version: 1.10.0.

## Validation

- All 383 declared tests passed at version 1.9.0, including entity-index queries and cache invalidation, duplicate identities, prototype-named dimensions, multi-link editing, empty Base cells, and nested-task indentation preservation.
- TypeScript and the required production-mode builds passed. The final separate build was byte-identical to the deployed 1.9.0 test artifact.
- Obsidian 1.12.7 reloaded the final plugin in the isolated Obsidian Plugin Test Vault. The live settings UI exposed **Kind (Note identity)** and **Accepts kind** without changing saved settings.
- Runtime-owned `data.json` retained SHA-256 `6f832cdce0a73ec7404c8a6f91f52cc8fb28b7199801fbec278d8d45ffae507d`.
- Production was not accessed. This release is ready for the user's BRAT pull.

## Known limitations

- Version 1.9.0 indexes Markdown notes and frontmatter. Structural task, header, and bullet `kind` values remain Base row-shape filters rather than selectable registry identities; line-backed entities need a future stable block-reference contract.
- Constrained pickers intentionally provide no free-text or implicit note-creation escape hatch.
