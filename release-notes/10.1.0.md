# TPS Global Context Menu 10.1.0 — Discover every vault property

Custom fields now shows saved definitions plus every currently cached top-level frontmatter key in the vault. Previously unconfigured fields appear alphabetically as **Not defined**. Expand a card and choose **Define property** to use the existing label, type, scope, option, and visibility editor. Search and type filters cover both groups; Add field remains available before the collection.

Opening settings never saves a definition or writes a note. Blank, numeric, boolean, list and structured values are included; structured members are not flattened. Basic types are suggested; mixed/structured/empty values start as Text. Newly defined fields start with both GCM menu visibility switches off. Existing definitions, values, IDs, ordering and scopes are preserved. Navigator visibility remains owned by Navigator and is available on discovered cards as well.

- Opening Custom fields performed **one Markdown metadata inventory / 21,126 cached metadata lookups**, zero note-body reads, zero note mutation attempts, and zero settings writes. Opening its card/filtering reused those rows. Defining a field deliberately saved configuration and rerendered the collection. No background inventory, watcher, cache or startup hook was added.
- The inherited settings layout/control preservation tests passed; native buttons, search, single-card disclosure and existing responsive CSS are reused. Physical iPhone acceptance is **not verified**. No production timing or cold-start improvement is claimed.

## Compatibility and limitations

Minimum Obsidian **1.10.0**. Additive minor release; no schema migration or note changes. Discovery uses available cached metadata when the collection renders: if Sync/metadata indexing has not finished, reopen the route after it finishes to refresh. Object-valued keys are discoverable, but this release does not introduce an object editor. Existing optional Navigator visibility requires its API. Source is published with the tested artifacts; production is unchanged and installation is the user's BRAT pull.
