# TPS Global Context Menu 1.11.3

This patch aligns the tagged source with the already tested TPS List efficiency improvement that was present in the preceding feature-release artifact.

## What changed

- TPS List builds its full task-to-lane render index once per render.
- After empty synthetic lanes are added, the renderer reuses that task index instead of repeating the same full-vault task build.
- The optimized `main.js` is byte-identical to the public 1.11.2 feature artifact; 1.11.3 makes the tagged source and release metadata accurately describe those shipped bytes.

## Compatibility and migration

- This is a backward-compatible patch release.
- Task identity, task order, lane synthesis, note grouping, parent relationships, settings, and stored data are unchanged.
- No migration or settings change is required.
- Minimum supported Obsidian version: 1.10.0.

## Validation

- All 514 declared tests passed at version 1.11.3, including a focused equivalence test that verifies one task build, unchanged lane keys, unchanged task identities and order, and one full-vault visit.
- The required separate production-mode build passed and deployed byte-identical source/runtime artifacts to `Obsidian Plugin Test Vault`.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**. TPS List rendered its three expected lanes and two synthetic task rows.
- Runtime-owned `data.json` retained SHA-256 `955b97d05a4a473a1ee98696cde354f8fbbcf4f566ccb4c5ffcdb74ae8244eeb`.
- Production was not accessed. This release is ready for the user's BRAT pull.

## Known limitations

- The improvement removes one duplicate synchronous task build; it does not add persistent indexing, caching, or invalidation state.
- Performance gains scale with the number of task candidates and are intentionally not claimed for small views.
