# TPS Global Context Menu 1.51.0

This release separates template discovery from automatic-write policy so the configurable `template` tag is no longer a hidden global ignore rule, and it adds an explicit custom-kind capability for trusted native-record consumers.

- The configured template tag still identifies templates in TPS pickers and is still removed exactly from newly generated Daily Note and note-level recurrence instances. Identity in Tag, Property, or Templater-folder mode no longer blocks unrelated automatic changes by itself.
- **Global auto-write exclusions** now includes an **Excluded tags** vault-tag chooser and supports exact top-level YAML tag entries with `tag:<tag>` and `#<tag>`. The chooser updates that same exclusion list instead of adding another persisted setting. Matching is case-insensitive and exact: `template` does not match `template/example`, and body hashtags are ignored. Existing path, folder, wildcard, `name:`, and `re:` entries are unchanged; a literal path beginning with `#` can be disambiguated with `path:`.
- Tag exclusions use current Vault bytes and mutation-boundary frontmatter. An unreadable or ambiguous source fails closed only when a valid tag exclusion needs to be evaluated.
- **Rule exclusions** supports the same exact tag syntax for Navigator presentation and semantic tag rules. The Global policy applies to automatic writes; explicit manual rule actions remain available unless the Rule exclusion itself matches.
- The public version-1 `templates.canAutomaticallyMutate*` API shape is unchanged and now reports explicit Global exclusions rather than template identity. Existing TPS consumers need no companion update.
- Title and filename synchronization no longer silently skips an ordinary note merely because its name contains the word “template.”
- The version-6 `nativeRecords` API now advertises `capabilities.customKinds: true`. Strict lowercase/hyphenated custom kinds use deterministic `<kind>-records` folders and receive the same atomic create, inspect, resolve, list, update, re-identify, rename, and archive behavior as built-in kinds. Existing built-in paths and API methods are unchanged.

There is no settings or note migration. To exclude tagged templates from automatic TPS mutations, choose the tag under **Rules & fields → Navigator rules → Automation and safeguards → Excluded tags**, or add its canonical `tag:template` entry under **Global auto-write exclusions**. Minimum supported Obsidian remains 1.10.0.

## Validation

- The complete declared suite passed 1,245/1,245 tests with zero failures and zero skips. Focused template-exclusion and custom-kind coverage passed 138/138, followed by TypeScript and diff checks.
- The final versioned build deployed to the isolated **Obsidian Plugin Test Vault**; the mandatory separate production-mode build then reported the runtime byte-unchanged. Source `main.js`, `manifest.json`, `styles.css`, and `styles-ui.css` byte-match that runtime.
- The named test vault reloaded enabled GCM 1.51.0 with no captured developer-console errors. Read-only settings QA confirmed **Excluded tags**, its **Choose tags** control, and distinct `#template` and `#template/example` suggestions without selecting a tag or changing settings.
- The test runtime's `data.json` and `recurrence-session.json` hashes remained unchanged. TishOS v0.2 and the production vault were not accessed.

## Known limitations

- Exact tag exclusions intentionally do not include descendants: `template` does not match `template/example`.
- A literal path beginning with `#` must use the explicit `path:` prefix.
- Source/frontmatter-only variants of the templates API can evaluate tag exclusions but require a file-aware call to evaluate path exclusions.
- Consumers must check `nativeRecords.capabilities.customKinds` before relying on custom kinds.
