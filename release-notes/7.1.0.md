# TPS Global Context Menu 7.1.0 — Configured Daily Notes and shared record paths

GCM now recognizes Daily Notes using the configured `dailynote` classification and the custom **Scheduled** field's key. A nested list value and a renamed date property work for named Daily Notes, reconciliation, and inherited task dates. A template-less Daily Note, or a Daily Note template without frontmatter, starts with the configured classification rather than an automatic `dailynote` tag. The existing legacy tag is used only if no Daily Note mapping has been configured. GCM-owned creation fills the configured Scheduled key.

Older Daily Note markers and the historical `scheduled` property remain readable. Conflicting dates, mixed classifications, and a shared list path without independent subtype evidence still fail closed. The candidate index updates when the configured Scheduled key changes. The Daily Note fix adds no background writer or automatic note repair. Minimum Obsidian remains **1.10.0**.

Record classifications now support an optional configured identity property/value beside a kind-list writer. Multiple internal types can share one list path, while their configured field identifies each type on create, inspect, resolve, and after a cold index. GCM writes that field for new native records, and its `frontmatterKinds` API uses the same setting for encoding, decoding, matching, and snapshots. This is generic: the path, key, and value all come from GCM settings. The settings UI exposes **Shared-path identity property/value** on the selected kind-list mapping. It rejects duplicate identity pairs; a missing or conflicting identity is not guessed from path order. Explicit legacy aliases remain readable.

Changing the identity setting previews affected notes and asks for confirmation. It updates selected record frontmatter and the mapping in one recoverable transaction; cancellation changes nothing, and ambiguous records, a concurrent edit, or a destination-field conflict block the change. Confirmed custom-property key/value migrations also update matching kind-list and identity mapping references. Adopting a new kind-list path from older classifications remains a separate migration. This release adds no automatic repair, vault scan on note open, or built-in Finance/Health taxonomy. `nativeRecordKindPropertyKeys` gains an optional `discriminator: { key, value }` member on kind-list mappings; existing mappings and legacy aliases remain supported. The settings destination map, default route, mobile layout, and persisted route state remain unchanged.

## Validation

- Focused kind classification, native-record, mapping-settings, and date-format suites: 209 checks, zero failures. Daily Note creation and identity cases also run in the declared suite. These cover alternate list paths/date keys, template-less creation without an automatic tag, ambiguous shared paths, mixed kinds, conflicting dates, index invalidation, every planned shared record group, scalar-to-list migration, cold-index resolution, confirmation, cancellation, concurrent edits, and rollback.
- Full declared suite: 1,500 checks, zero failures. Its build ran with deployment suppressed. A separate final build deployed GCM 7.1.0 to the Obsidian Plugin Test Vault; the installed plugin was reloaded and its version and shared-path identity controls were verified in the UI. The temporary QA mapping was removed, and the runtime settings file was byte-identical afterward.
- Physical iPhone and production-vault behavior remain unverified. This public release is for the user's BRAT pull; the TishOS v0.2 vault migration is coordinated separately.
