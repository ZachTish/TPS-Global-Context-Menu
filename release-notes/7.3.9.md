# TPS Global Context Menu 7.3.9

Test-vault-validated, backward-compatible performance patch.

## Changes

Mobile bottom-clearance measurement now belongs to the surfaces that consume
it. Previously each menu-ensure pass enumerated every element in the document,
checked ancestors and read computed styles, even with inline menus disabled.
Normal enabled mobile menus also did this work although their pane-mounted
58px/safe-area positioning ignores the shared offset.

The existing measurement now requires a connected hover Base or non-pane
reading/live menu. First hover and fallback-menu mounts request clearance
immediately after inserting their element, before positioning or awaiting
rendering. Keyboard and layout updates retain the same consumer check. The
obstruction calculation, visibility/exclusion rules and resulting offset are
unchanged when a consumer exists. Connected-but-hidden consumers deliberately
continue measuring; there is no visibility heuristic or stale-result cache.

Keyboard-overlay touchstart/pointerdown callbacks now have removable references
and are removed with the same capture phase during teardown. Their active
behavior is unchanged; reloads no longer retain those callbacks.

This is a backward-compatible patch with no settings, schema, note mutation,
migration or public API change. It adds no watcher, timer, cache, index, retry
or repair. The separate 900ms retained title/link sweep is untouched. Minimum
Obsidian remains 1.10.0.

## Evidence and validation

- Seven strict tests failed against 7.3.8 before implementation. Twelve
  unchanged passes over 10,000 ordinary DOM elements incurred at least 120,000
  computed-style reads before the correction, with ordinary inline menus
  enabled or disabled. Both cases now assert exactly zero whole-document
  inventories, style reads, rectangle reads, ancestor checks and offset writes.
  The lightweight connected-consumer selector still runs.
- The nine new cases also cover detached consumers, unchanged hover/fallback
  clearance and every existing obstruction exclusion, current geometry across
  keyboard transitions, zero-obstruction reset, desktop behavior, first
  reading/live fallback mounts, first/remounted hover rendering and unaffected
  top/bottom Base mounts.
- Five keyboard setup/teardown cycles retain zero touch, pointer, focus,
  viewport or window callbacks. Capture-phase matching and active
  overlay-interaction behavior are verified.
- Focused mobile suite: 12 passed; adjacent navigation/source-mode/mobile
  suites: 55 passed. Direct TypeScript no-emit and diff checks pass.
- Independent source review found no blockers and independently reran all
  12 mobile checks successfully.

These tests execute actual source methods with modeled DOM/Obsidian boundaries.
They establish operation counts and ownership, not browser layout timing,
foreground input-to-paint, physical swiping/typing, mobile IME behavior or
Windows performance. They do not establish that every multi-second navigation
stall has the same cause.

- Final versioned `TPS_NO_DEPLOY=1 npm test`: 1,597 passed, zero failures,
  cancellations or skips. Includes TypeScript and production-mode build;
  deployment explicitly reported `target=none`.
- `TPS_NO_DEPLOY=1 npm run prepretest`, started only after the full suite
  completed: 214 passed, zero failures, cancellations or skips. No timer,
  assertion or test concurrency setting was changed.
- Separate `TPS_NO_DEPLOY=1 npm run build` after the final README edit:
  TypeScript and production-mode bundling pass; deployment reports
  `target=none reason=TPS_NO_DEPLOY`. All four hashes match the preceding
  full-suite build. The Test manifest was independently checked at 7.3.8;
  no deployment or reload was performed.
- Separate normal production-mode build deployed byte-changed main.js and
  manifest.json only to the Test vault. A targeted disable/loadManifest/enable
  reload confirmed 7.3.9; runtime settings stayed byte-identical.
- Before/after probes extracted the exact loaded 7.3.8/7.3.9 method text and
  re-evaluated it unchanged in isolated modeled document/viewport/Platform
  fixtures. Twelve calls with 10,000 ordinary elements made 120,000 style reads
  before and zero after, both without consumers and with only pane menus.
  All three real-consumer classes preserved the modeled 102px → 132px clearance
  and keyboard transitions reset to zero correctly. Five setup/teardown cycles
  retained five touch and five pointer callbacks before, zero after. Real host
  globals, methods, menus and settings were untouched by this isolated probe.
  It does not establish actual mobile first-mount or physical keyboard behavior;
  first-mount owner ordering is covered by the source regression tests.
- Installed desktop smoke checks with Health 4.2.3 and Navigator 8.2.2 covered
  three display-only Daily Macros/Activity fixtures, six Live Preview tab
  switches and remounts. Widgets remained connected, no Health render errors
  or navigation note-mutation attempts occurred, settings remained unchanged,
  observers were restored and exact-byte fixtures were archived. The hidden,
  unfocused host cannot establish physical input-to-paint latency or Reading
  rendering. An ordinary workspace-state save during idle was not a note write.
- A final documentation rebuild retained the validated hashes below.

Production installation and physical-device acceptance remain separate.
