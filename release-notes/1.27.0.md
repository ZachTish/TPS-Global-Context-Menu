# TPS Global Context Menu 1.27.0

TPS Global Context Menu `1.27.0` makes TPS Table and TPS List a consistent, typed, stale-safe Bases surface for native notes and synthesized Markdown tasks, bullets, headings, and line records.

## TPS Table and TPS List

- Text, number, datetime, snooze, selector, list, tag, link/entity, checkbox, Kind, recurrence, Folder, and formula values now use one explicit display, comparison, grouping, and editing contract across both views.
- Typed sorting compares numbers, dates, booleans, lists/tags, links/entities, text, and formula results by semantic value. Both view types add **Items with multiple values**; the backward-compatible default shows a multi-value row in every matching group, while combined mode keeps it in one deterministic lane.
- TPS Table filters are strict and fail closed. Invalid syntax, unsupported evaluated operators or methods, unavailable indexes, and formula failures exclude the affected row and surface a visible diagnostic instead of silently including it.
- Filter-derived creation combines the whole-Base and active-view roots, preserves ordered branch selection, writes the exact authored property keys, validates the complete prospective task/bullet/heading/note, and refuses an unverifiable write.
- Configured property keys are matched case-insensitively after trimming edge whitespace only. Punctuation and interior whitespace remain meaningful, settings flag blank or duplicate exact keys without migrating saved definitions, and new definitions receive unique defaults.
- Repeated exact-key inline carriers are aggregated for display, exact-member filters, sorting, grouping, editors, and lane drops. A successful edit preserves unrelated list members and rewrites only the edited property into one balanced canonical carrier, including comma-bearing or nested wikilinks.
- Table range/toggle selection now creates a canonical task-only batch. Bullets, headings, generic records, and mixed selections remain scoped to the clicked row, and both views discard selections whose rendered occurrence or exact source revision no longer exists.
- TPS List task rows have native desktop pointer drag and mobile long-press drag between writable lanes. Touch activation waits 550 ms with 10 px movement tolerance, scrolling cancels before capture, all temporary drag state is cleaned up, and the drop re-resolves one unique exact source line before mutation.
- Configured Folder fields represent the current containing-note folder and are read-only for synthesized lines. Bare Kind remains the additive union of structural and explicitly authored identity. TPS List narrowly reconciles native note results for those two GCM semantics without taking ownership of native search or guessing through unsupported filters.
- Native-checkbox and GCM status changes share completed-date reconciliation. Exact-line editors, menus, delete/move routes, and drag/drop refuse stale, missing, or duplicate source revisions instead of selecting a nearby row.
- TPS Table reuses revision-keyed parsed Markdown across unchanged rerenders, cancels superseded work, and bounds cold source reads to eight concurrent files. Totals explicitly exclude every `file.*` and `line.*` metadata alias in addition to dates, IDs, units, and mixed columns.

## Compatibility, migration, and known limitations

- This is a backward-compatible minor release. It adds one optional per-view configuration value, `multiValueGrouping`, whose default is `separate`; existing Bases retain their current fan-out behavior without an edit.
- There is no automatic note-data or settings migration. Existing repeated carriers remain byte-for-byte unchanged until that exact property is edited or used as a writable lane target.
- Whole-note recurrence is intentionally read-only in TPS List cells so a direct field write cannot bypass GCM's canonical recurrence series/template lifecycle. Task-line recurrence remains editable through the guarded recurrence modal.
- Folder, formula, source-path, and other virtual metadata values remain read-only. TPS Table multi-row mutations remain task-only; non-task rows retain their guarded single-record actions.
- TPS Table still renders ordinary DOM rows with native scrolling rather than virtualizing very large result sets.
- Minimum supported Obsidian version remains `1.10.0`. No breaking public API change is introduced.
