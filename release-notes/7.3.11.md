# TPS Global Context Menu 7.3.11

Test-vault-validated BRAT handoff. Backward-compatible native-record
metadata-indexing performance correction. Publication is separate from the
user's production installation; production remains untouched.

## Change and boundaries

`indexFile` now shares one existing operation-local profile inspector and one
prepared configuration across applicable-profile selection, recoverable-ID
collection, combined matching, invalid-evidence checks and final inspection.
It stores the accepted final envelope without inspecting it a second time.
The former calls created separate inspection maps, repeating classification of
the same exact prepared profile and repeatedly serializing the same settings.

The existing evidence/readable/current-kind logic is extracted into a private
helper. Public `inspect` still checks current settings and returns detached
profile objects. All identity/ambiguity, custom classifications, read aliases,
legacy/migration, timestamp fallback, canonical-calendar and duplicate blocking
semantics remain active. The next file and metadata event prepare independently,
so in-place nested settings changes between files/events are immediately seen.
Match-set merging still copies frontmatter; reuse never crosses source inputs,
events, atomic mutation callbacks or authoritative refreshes.

There is no persistent cache, API addition, watcher, asynchronous startup,
heuristic skip, repair, schema migration or note write. Synchronous setup still
walks all Markdown metadata. Health and Controller's separate startup scans are
not removed. Authoritative source verification remains a distinct async route
with disk reads and its existing generation/mutation guards; its first-use cost
is not addressed by this patch. Patch version is appropriate because settings,
public API, stored schema and minimum Obsidian 1.10.0 remain unchanged.

## Focused evidence

- Three 10,000-note actual cold-setup tests failed against published 7.3.10:
  ordinary notes made 20,000 prepared-configuration accesses and valid records
  made 30,000 instead of one per file. The fixed tests require 10,000 and retain
  the existing configuration-generation cache (one resolution per fixture).
- Ordinary classifier evaluations: 130,000 to 30,000. Canonical records:
  150,000 to 30,000. Twenty-six mapped kinds: 1,110,000 to 270,000. Every exact
  prepared profile, including a null result, is evaluated once per file.
- The classifier's raw-to-envelope copies fall from 60,000 to 10,000 for
  canonical records and 110,000 to 20,000 for mapped records. This counter
  excludes other object spreads and match-set merge copies.
- Each fixture keeps one inventory, 10,000 metadata accesses, zero source
  reads/writes, all correct indexed IDs/kinds/titles and unchanged source data.
  A fourth control changes a nested mapping during the next metadata fetch and
  again before a later metadata event; both new mapping/status/title values
  remain visible, and removing identity removes its previous index ownership.
- All 146 focused native-record tests pass without failures/skips; TypeScript
  no-emit passes. Independent read-only review found no blockers and ran 60
  relevant identity/mutation/cold tests, all passing.
- A separate in-memory comparison of published/proposed source preserves
  complete record envelopes, canonical fields, ID/asset ownership, blocked
  paths and recoverable IDs for 609 index operations across seven settings
  scenarios. Coverage includes malformed/ambiguous keys and tags, current and
  legacy aliases, migration readers, tag/list/scalar/hierarchy mappings,
  canonical calendar IDs, repeated edits and identity removal.
- Isolated actual-source synthetic setup on this Mac: ordinary ~154 to 125ms,
  canonical ~514 to 272ms, mapped ~2,272 to 1,205ms. Mapped configuration
  signature serialization falls from 30,000/56,340,000 characters to
  10,000/18,780,000. Instrumentation is included; these are synchronous service
  timings, not foreground rendering, installed startup or physical-device
  acceptance. No live application or production source was profiled.

## Final validation

- Final versioned `TPS_NO_DEPLOY=1 npm test`: 1,609 passed, zero failures,
  cancellations or skips. TypeScript and the production-mode suite build pass;
  its deployment output confirms `target=none reason=TPS_NO_DEPLOY`.
- Explicit sequential `TPS_NO_DEPLOY=1 npm run prepretest`: 218 passed, zero
  failures, cancellations or skips. This supplemental gate is not automatically
  chained by npm's ordinary test lifecycle.
- A separate production-mode `TPS_NO_DEPLOY=1 npm run build` passes after the
  README update, with `target=none reason=TPS_NO_DEPLOY`. Test runtime settings
  remain byte-identical.
- A normal final production-mode build deployed only main.js/manifest.json to
  the explicitly guarded Test vault. Targeted plugin reload confirmed loaded
  7.3.11; all four installed artifact hashes match the tested candidate.
- Identical actual loaded constructor/setup replay compares 7.3.10 and 7.3.11
  in isolated services over three 10,000-note synthetic inventories. Prepared
  profile accesses fall from 20,000 ordinary / 30,000 canonical / 30,000 mapped
  to 10,000 in every fixture. Calls to the public `inspect` wrapper fall from
  10,000 / 20,000 / 20,000 to zero, and public profile-copy wrapper calls fall
  from zero / 20,000 / 20,000 to zero. Private evidence/current inspection
  still runs; these wrapper counters are not the source classifier/copy counts
  above. Records remain exactly zero / 10,000 / 10,000, with every returned
  ID/kind/title verified and every input metadata object unchanged.
- Every installed fixture retains one inventory, 10,000 metadata accesses,
  one configuration resolution, zero source reads/writes and the same five
  modeled event listeners. The real service's maps/prepared profile and real
  settings remain unchanged. An initial probe guard incorrectly expected six
  mocked listeners rather than the actual five; correcting that assertion
  required no plugin/runtime change and did not indicate a runtime failure.
- The one installed mapped pair is 2,342.2ms before / 1,193.9ms after. It
  measures synthetic synchronous setup on a hidden/unfocused desktop host,
  not full cold-process startup, foreground input-to-paint, physical phone or
  Windows performance. It excludes the distinct async authoritative disk-read
  verification and other plugins' startup work.
- The shared 13-phase desktop Live Preview smoke checks pass through six tab
  switches and two remounts with observed Health widgets retained, zero phase
  errors, Health render errors, measured long tasks or note-mutation attempts.
  Three UUID fixtures are exact-byte archived and plugin settings remain the
  same. One core workspace adapter write occurred at idle, not a note writer.
  Reading mode, physical mobile/Windows behavior and production installation
  remain unverified. These checks do not establish that every loading/swiping
  delay is resolved.

The required separate ordinary post-documentation build preserves the same
tested bundle and runtime files. No physical mobile or Windows latency claim is
made; this is the public BRAT handoff, not production installation.
