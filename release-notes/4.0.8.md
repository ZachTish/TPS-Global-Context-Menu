# TPS Global Context Menu 4.0.8 — Faster custom property settings

Opening **Rules & fields → Custom fields** no longer builds every collapsed editor or scans values for fields you have not opened. Editors are built by their existing disclosure action. Collapsing a card preserves its mounted controls and unapplied drafts; opening a different card retains the single-open-card behavior. Manual-only and entity-only previews skip unused vault discovery. The Accepted kinds hint no longer initializes the entity index just to list known kinds; the accepted-kind field remains editable with the same behavior.

Settings, defaults, filters, order, save/migration actions, public APIs and storage formats are unchanged. Configured vault previews retain existing discovery, ordering and cache behavior. No new cache, timer, watcher, settings state or repair pass. This is a backward-compatible **patch**, requiring **Obsidian 1.10.0** or later.

Validation:

- Four new regressions fail against the original implementation; a further before-failing assertion covers the eager known-kind hint. Final 79 focused and 1,435 full declared tests pass, zero failures/skips/cancellations. TypeScript and the separate production build pass.
- Installed 4.0.7 before: two trusted foreground page opens took 910/879 ms; each made 15 Markdown inventories and 169,815 metadata lookups. Final 4.0.8: 47/25 ms and zero inventories/metadata lookups/raw reads/write attempts. DOM size drops from 12,274 elements to 390 for the same 57 configured properties.
- First Priority/Tags expansions: 26/35 ms, no scans, only the selected editor mounted. Unapplied key text survived collapse/reopen without saving; restored afterward. Enter collapsed the focused card. Closed cards remained unbuilt on route return. All nine final captures stayed foreground, completed at least 800 ms of settling and observed no long tasks.
- Named GCM-only reload verifies 4.0.8. Eight monitored plugins' settings/artifact sets are unchanged during final QA; diagnostic hooks, temporary draft and settings window are removed, prior view restored. No notes or provider actions were created. Final documentation build preserves the verified artifact bytes.

Limitations: the source-method tests mock DOM/settings controls while using real option helpers. Installed checks use the actual desktop Settings window and configured fields. These small warm samples establish this settings improvement, not whole-vault/native parity, cold startup or physical iPhone speed. Existing horizontal overflow in expanded property editors remains a separate layout issue; no stylesheet change or narrow-mobile acceptance is claimed.

Tested in **Obsidian Plugin Test Vault**, ready for the user's BRAT pull. Production has not been deployed or inspected for this fix.
