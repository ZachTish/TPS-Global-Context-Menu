# TPS Global Context Menu 3.6.9

Backward-compatible context-menu performance fix. Minimum Obsidian remains **1.10.0**.

File menus resolve parents and children once per construction and reuse those results for both counts and submenu contents. Previously the child count and hidden submenu each scanned all relationship candidates. Reopening the menu still reads fresh relationships. Labels, empty states, navigation/unlink actions, supported attachments and ignore rules are unchanged.

No retained cache, index, delayed behavior, metadata policy, settings, APIs, schemas or migration change. One child relationship scan remains; this patch does not claim general vault speed or native Obsidian parity.

## Validation

- Two new regressions failed on 3.6.8, proving duplicate resolution and four child scans across two menus. They now pass, preserving labels/content for Markdown and attachment children and current data on the next menu.
- All 39 focused menu-builder, parent/child-ignore and Notebook Navigator bridge checks pass.
- Final versioned validation under Node 24.19.0/npm 10.9.2: **1,314 declared checks and 193 supplemental checks pass**, with zero failures/skips. TypeScript and the suite build pass with `TPS_NO_DEPLOY=1`. The separate final normal build deployed 3.6.9 to the test vault, and a named disable/load-manifest/enable reload verified that version. The final documentation-only build is byte-identical.
- Three installed 3.6.8 menu openings each called the child resolver twice. Paired durations were 198.4 + 181.8 ms, 196.9 + 181.1 ms and 190.9 + 184.3 ms, with 93,579 metadata lookups per pass. Navigator materializes the submenu outside the initial GCM menu facade, so both resolver calls were measured independently. This is menu-construction work, not rename-save latency; three after-build openings each made one resolver call taking 203.0, 197.9 and 197.4 ms, with 93,579 metadata lookups each. Paired resolver work therefore fell from 375–380 ms to 197–203 ms; the duplicated pass is absent. These are instrumented operation durations rather than physical click-to-paint measurements.

- Actual CUA parent and child menus retained their count of one, their matching navigation/unlink entries, and empty-state entries on the opposite side. Relationship values and note bodies were preserved. Seven involved settings files remained byte-identical; original note/search state and wrappers were restored. The functional fixtures were archived directly from Inbox to `_archive`.
- A first timing probe measured only the initial GCM facade. Navigator materializes the submenu afterward, so those two preliminary samples did not capture both scans; the complete three-sample comparison above wraps the child resolver independently. The before monitor later expired after its three samples and restored its hooks/state; no expired setup timing is used as a rename-save measurement.

Tested in Obsidian Plugin Test Vault and ready for the user's BRAT pull. Production remains untouched. Physical iPhone and production acceptance remain separate. The remaining single whole-vault relationship scan and Navigator's post-rename file-type refresh are outside this patch. No dependency versions changed; the dependency helper reported an existing moderate advisory.
