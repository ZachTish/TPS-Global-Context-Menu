# TPS Global Context Menu 11.2.0 — Indexed food-serving choices

Adds **Choices from linked note** to existing whole-note GCM selectors. Choices come from one linked note's indexed text/list property or an enabled plugin's pure provider. Health 10.2.0 supplies food-serving choices. Use the inline property, collapsed badge, or native Base row context menu. An explicit selection rechecks current target and source revisions at the existing atomic write boundary.

## Configuration and compatibility

Update both Health 10.2.0 and GCM 11.2.0, then use GCM **Properties → Custom fields → Install / refresh** (Install TPS task and Health fields). Managed Food becomes a single entity selector, Amount consumed stays numeric, and Unit uses **Choices from linked note → Food servings**, linked through the configured Food property. Existing custom definitions retain the importer's preservation rules; configure their Unit source explicitly when needed. No startup migration or note rewrite occurs.

GCM's generic provider API is `api.linkedPropertyChoices = {version: 1, providers: {name: {label, sourceProperties, getChoices}}}`. Health owns serving interpretation, GCM owns choice presentation and explicit writes. Missing links/definitions/providers are explained; existing incompatible units are preserved. Native Bases owns its cell editors: dependent choices are available through the row's GCM menu, not a replacement cell widget. This feature applies to whole-note records, not legacy inline logs.

No new Health settings destination, custom food dialog, persistent index, network query, poller, maintenance writer or global serving listener. GCM's existing five destinations are preserved; linked controls live inside the existing field editor. Only generic sources show Choices property. Native controls and the existing responsive styles are reused without new CSS or persisted navigation state.

Minimum Obsidian version: 1.10.0.

## Validation

- Complete declared suite: 1,998 passed, zero failures or skips. Separate final production build passed. Focused tests cover indexed lookups, conversion parity, missing/incompatible sources, generic text/list choices, stale source/target rejection, open-editor precedence, event bursts, selector disposal and existing menu routes. Atomic race cases use host stubs; native installed save/readback is separately verified.
- Deployed and reloaded in **Obsidian Plugin Test Vault**, Sync disabled, normal enabled consumers retained. Actual inline picker and native Base row menu show compatible units. Explicit unit selection saves correctly. Editing Amount consumed in the native Base recalculates its row and summary: 355 ml of a 355 ml / 95 kcal serving yields 95 kcal; after an explicit mass-based selection, 355 g of a 50 g / 95 kcal serving yields 674.5 kcal. Historical stored macro snapshots remain untouched.
- While the picker stayed open, changing serving metadata refreshed choices. Renaming and moving the food preserved resolution after Obsidian's normal link update. Switching the food from volume to mass displayed the incompatible existing ml value without changing it.
- All five GCM settings destinations inspected after reload; generic/source-provider conditional controls and focus checked. No settings were saved. Temporary in-memory test configuration was restored, synthetic fixtures archived, both data.json SHA-256 hashes unchanged, enabled states preserved.
- Focused, visible installed first picker: **58.8 ms** to two animation frames after modal insertion; repeat **59.2 ms**. Each ran one serving calculation, zero vault scans/body reads/writes and no observed long task. Earlier 11.1.0 plain-text editor sample: 63.2 ms. These are two desktop samples, not a statistical benchmark or a phone speed claim.
- A 1,000-event unchanged/unrelated metadata burst caused zero serving calculations, vault scans, reads or writes in the measured interval. Typing into an unrelated synthetic note after closing the picker caused zero serving calculations. Filtering caused zero serving calculations; two unrelated cached reads occurred across the longer all-consumer observation interval. Explicit edits retain normal consumers: the observed save interval included two vault scans by existing consumers; the linked-choice path itself contains no vault enumeration.

Tested in the desktop test vault and ready for the user's BRAT pull. Production was not deployed or inspected for this feature. Physical iPhone acceptance and narrow physical-device layout remain unverified.
