# TPS Global Context Menu 1.16.0

## Intent

Give note-backed rows in TPS Notebook Navigator's Types browser the same exact, canonical whole-note actions as the note
they represent, without coupling GCM to Navigator internals or changing other entity-row menus.

## Changes

- A lifecycle-safe bridge registers through TPS Notebook Navigator's public `menus.registerRowMenu(...)` API and only
  accepts built-in GCM note entities under Notes or a dynamic Kind.
- Right-click, mobile long-press, and **More actions** resolve the exact current Markdown `TFile` and reuse GCM's canonical
  whole-note menu builder. No ambient selection, guessed source, or duplicate note-action implementation is used.
- Checkbox/task, bullet, heading, loading/error, and third-party provider rows remain excluded; their existing owner menus
  are unchanged.
- Cross-realm file snapshots are accepted only when path and creation time still match the vault's canonical file.
  Deleted, replaced, non-Markdown, stale, or ambiguous targets fail closed.
- Menu construction is buffered transactionally, so a failing canonical builder cannot leave a partial foreign menu.
- The registration follows TPS Navigator startup, hot reload, API replacement, settings refresh, and unload. A malformed
  replacement cannot tear down a working registration, stale lifecycle messages cannot remove a newer one, and upstream
  Notebook Navigator IDs/events are never used.
- **Inline menu only** remains authoritative and suppresses these context-menu additions.

## Compatibility and migration

- Backward-compatible minor release; no settings or note-data migration.
- Minimum supported Obsidian remains 1.10.0.
- The bridge is optional and runtime-only. GCM behaves normally when TPS Notebook Navigator is absent or incompatible.

## Validation

- Fifteen focused bridge and exact-line context-menu assertions pass, covering row eligibility, exact current-file
  targeting, cross-realm identity, delete/recreate refusal, host lifecycle replacement, failed-registration preservation,
  transactional construction, settings refresh, and unload.
- The complete declared GCM suite, TypeScript, and deployment-suppressed production build pass for the versioned candidate.
- Live Obsidian 1.12.7 test-vault QA after reload confirmed a Note row in TPS Navigator's Types browser receives GCM's
  canonical whole-note actions, while a Checkbox row retains the task-specific menu without duplicated note actions.
- Runtime-owned `data.json` retained its original inode, size, timestamp, and SHA-256 hash through build, deployment,
  reload, and QA. Production was not accessed or changed.

## Known limitations

- This bridge intentionally adds whole-note actions only to note-backed built-in Entity Index rows. Line entities retain
  their line-specific GCM menu, and third-party providers must register their own actions.
- A foreign TPS Navigator API that does not expose `menus.registerRowMenu(...)` is ignored without polling or fallback
  mutation.
