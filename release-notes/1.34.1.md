# TPS Global Context Menu 1.34.1

TPS Global Context Menu 1.34.1 repairs line-item inline-property rendering when Obsidian or another renderer splits or nests the generated DOM.

## Inline-property rendering

- Raw rendered fields are transformed only from text owned by the current list row or paragraph. A parent list item can no longer consume fields from nested children.
- Existing Dataview and Properties widgets are authoritative output and are excluded from GCM's raw-field fallback.
- Text-node seam handling assigns starts to the following node and ends to the preceding node, preventing partial deletions that left raw timestamps, `key:: value` text, or duplicate chips visible.
- Health food/workout grouping follows the same ownership boundary and cannot move a nested row's chips.
- A normal completed-task reconciliation now collapses duplicate `completedDate` carriers to one field while preserving the first existing nonempty timestamp.

## Compatibility and known limitations

- Backward-compatible patch with no new setting, API, or note schema.
- Reading decoration is presentation-only and never writes a note. Duplicate source metadata is repaired only when that task next passes through an existing status/checkbox reconciliation; this release does not bulk-rewrite the vault.
- Minimum supported Obsidian remains 1.10.0.

## Validation

- The full declared GCM suite passed at version 1.34.1. The focused inline-property, task-line, checkbox/status, and task-menu matrix passed 80/80.
- The mandatory separate TypeScript/production build passed, deployed only to the isolated test runtime, and a repeat build was byte-identical. Source and runtime `main.js`/`manifest.json` match exactly; the runtime hot-reload marker and recurrence state remained byte-identical.
- Obsidian 1.13.7 UI verification passed in the isolated test vault with nested completed tasks and nested bullets. Scheduled and priority chips stayed attached to their owning rows, duplicate `completedDate` output and raw timestamp fragments were absent, and no raw `key:: value` carrier remained visible. The existing **Show custom fields in inline UI** setting was enabled for the check and restored to `false`; the temporary QA note was moved to `_archive`.
- Production deployment or installation: **NOT PERFORMED**.
