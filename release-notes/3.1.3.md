# TPS Global Context Menu 3.1.3

Health food saves could reread and reclassify every Markdown note after any unrelated edit. Changes during that scan restarted the entire read pass. This backward-compatible performance patch keeps verified source envelopes and reconciles only changed paths, including provisional metadata updates.

- File creation, edits, renames, deletion and internal writes invalidate the affected source cache entries. Configuration changes clear the cache.
- Unchanged native identities and duplicate/conflict ownership stay indexed. Ordinary notes retain compact non-record markers. Only relevant parsed frontmatter is retained; note bodies are not cached here.
- Edits during a read invalidate that result, while other verified files survive the retry. Duplicate identities, unreadable sources, malformed identity evidence, stale plans and source-preserving writes retain their existing safeguards.
- Optional structured performance diagnostics report read count, passes, cached-file count and elapsed time without note content.

## Compatibility and limits

Patch release, minimum Obsidian **1.10.0**. No settings, frontmatter or API-version migration. Health uses the existing GCM nativeRecords API; the tested Health release remains **3.1.3**. No new Health release is needed for this fix.

The first authoritative verification after startup/reload or storage configuration changes still scans the whole vault. Final installed QA measured **7.734 seconds** for that initial 8,789-file scan. Later checks still enumerate files but avoid repeated reads and classification of unchanged identities. Continuous edits can require retries. Food-provider network delays and legacy Daily Note logging are separate paths and are not changed by this release. Desktop test-vault timings are samples, not latency guarantees; physical mobile acceptance remains user testing.

## Validation

- Focused native-record suite: **86 passed**. Includes 1,000-note and 1,000-record fixtures, interrupted reads, single-file changes, internal edits, rename/delete/replacement, late duplicates, metadata arriving with stale identities, source identity removal and configuration invalidation.
- `npm run prepretest`: **136 passed**.
- `npm test`: **1,214 passed**, zero failures/skips, including TypeScript and build.
- Mandatory separate final `npm run build`: passed; deployed only shipped artifacts to **Obsidian Plugin Test Vault**. The separate republish was byte-identical.
- Explicit test-vault GCM disable/enable with refreshed manifest loaded **3.1.3**. The installed Health `logFood` path created three actual native records after three unrelated note edits, with the complete vault participating in identity checks.
- Final food-save timings: **66 ms / 31 ms / 82 ms**; identity-check time **14 ms / 13 ms / 54 ms**; authoritative reads **1 / 2 / 2**. Each saved 50 g against a 100 g base and correctly stored 100 calories, 5 g protein, 15 g carbs, 2 g fat, 2.5 g fiber and 10 mg sodium. Both the returned record and actual file payload were checked.
- Diagnostic baseline on 3.1.2: one identity verification read **17,548 files across two passes** in **7.625 seconds** in the then 8,774-note vault. This was an identity-check baseline, not an end-to-end old-version food-save measurement. The initial read-cache-only candidate still spent 1.6–1.9 seconds per save rebuilding the index; the final changed-path reconciliation removed that reproduced CPU cost.
- Temporary QA destination was restored, all fixtures moved directly from Inbox to `_archive`, runtime probes removed, and persisted Health/GCM settings hashes remained unchanged. No provider requests or outbound automation were enabled; production was not accessed.

Tested in the test vault and ready for the user's **BRAT pull** of exact numeric tag **3.1.3**. Publishing does not install it in production or constitute user acceptance.
