# TPS Global Context Menu 3.3.1

New workout notes can be left with invalid YAML when appearance properties are repeated. This patch fixes the reproduced failure to recover byte-identical duplicate icon/color lines when the normal enabled appearance rules run (including opening a note). It supports configured appearance keys and preserves nested workout data, identity, timestamps, body, comments, BOM and line endings. Repeat application performs no write.

Only unambiguous scalar repetitions are repaired. Conflicts, case-different keys, structured/multiline values, anchors/aliases/tags, unrelated invalid YAML, excluded files and protected native fields remain untouched. No settings/schema migration, bulk rewrite, or Health runtime change. Health creation delegates the write to GCM; Health does not author these appearance fields.

## Validation and limits

- 26 focused source-preservation tests; all 1,232 full-suite checks and 160 additional checks passed, zero failures/skips.
- TypeScript and the separate final production-mode build passed and deployed only to Obsidian Plugin Test Vault. Named plugin reload verified 3.3.1; runtime bytes match every release artifact.
- Installed 3.3.0 reproduced failed recovery on a synthetic screenshot-shaped note. Installed final 3.3.1 removed exactly two redundant lines; strict YAML parsing recovered `kind: workout-session` and nested session data. Second application returned false. Live Preview rendered the body/workout card without the raw YAML error.
- Twelve rapid creation/opening trials with concurrent appearance and timer-style writes did not reproduce the original duplicate-producing step. Its iPhone/sync origin remains unconfirmed. This is a verified recovery fix, not proof that every creation or sync race is eliminated. Physical iPhone testing remains for the user.
- Health/GCM data.json files remained byte-identical; synthetic notes archived directly from Inbox to `_archive/QA-creation-20260925`. No production access, provider requests, timer activation or outbound automation.

Patch version: backward-compatible repair; minimum Obsidian 1.10.0. Tested in the test vault and ready for the user's BRAT pull. Publication does not mean installed or accepted in production.
