# TPS Global Context Menu 3.1.2

A single property edit could force two visible control rebuilds, notify API consumers twice, and clear all prepared Navigator presentation data. This patch consolidates the repeated work while preserving independent user actions and native view attachment.

- GCM event API subscribers receive one delivery per GCM-emitted file update, explicit action or Calendar refresh. Both raw workspace event names remain compatible; source attribution and distinct/nested actions are preserved.
- Metadata changes and parent refreshes use the shared per-file overlay batch directly. Removed the second forced debounce render and its loss of earlier files in multi-file edits.
- Note opening mounts menus without also queuing a redundant file refresh. Existing missing-host and mobile retries remain.
- Navigator projection updates the resolved file and tracked dependents; later metadata settlement no longer clears all prepared records. Initial settlement and create/delete/rename/settings/date invalidation remain.
- Retired reference-panel cleanup no longer creates an empty footer only to remove it immediately. Existing nonempty shared footer hosts are preserved.

## Compatibility

Backward-compatible patch. Minimum Obsidian **1.10.0**; desktop and mobile code paths retained. No settings, frontmatter or API-version migration. Consumers listening directly to both raw workspace event names still own their own duplicate handling; GCM's subscription API handles its own mirrored emissions. External producers' independent events are not time-window filtered.

That reused-pane behavior remains unresolved and is not claimed fixed. Physical mobile acceptance remains for user testing.
