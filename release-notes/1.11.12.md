# TPS Global Context Menu 1.11.12

This patch makes linked-subitem sorting faster and more internally consistent without changing any released order, feature, or workflow.

## What changed

- GCM resolves the configured custom sort field once for each sibling set and obtains one supported Obsidian `MetadataCache.getFileCache` snapshot for each eligible sibling.
- The released implementation resolved the same setting once per comparison and fetched both siblings' metadata again for every comparison.
- Two extension calculations that never participated in the returned ordering were removed from the comparator.
- The snapshot map exists only for the current sibling sort. The patch adds no persistent cache, custom invalidation, state, timer, retry, fallback path, monkeypatch, or private API.

## Compatibility and migration

- This is a backward-compatible patch release.
- Exact-key precedence, case-insensitive field matching, numeric conversion, non-numeric string comparison, missing-value placement, child/attachment grouping, status ordering, title ordering, stable equal-value order, hidden state, relation values, recursive children, and original `TFile` identities remain unchanged.
- Commands, settings, public APIs, note data, and every other released workflow remain unchanged.
- Missing metadata still behaves as a missing custom sort value and proceeds to the established secondary ordering.
- No settings or note-data migration is required.
- Minimum supported Obsidian version: 1.10.0.

## Measured effect

The actual compiled private method from exact public `1.11.11` and the candidate were exercised through the same harness.

- All 5,000 seeded randomized differentials produced identical order, hidden state, relations, recursive children, original file identity, and error behavior.
- Across those scenarios, metadata reads fell from 760,920 to 108,435 (85.749%), and configured-sort-field reads fell from 380,460 to 4,767 (98.747%).
- In 13 alternating runs over 20,000 siblings, metadata reads fell from 519,608 to 20,000 (96.151%) and sort-field reads fell from 259,804 to one.
- Median elapsed time in the final isolated benchmark fell from 84.515 ms to 48.486 ms, a 42.630% reduction. Deterministic call-count reduction and differential equivalence are the acceptance metrics; this synthetic upper-bound timing is not a claim of a whole-application speedup.

- Exact public `1.11.11` was pinned at commit `ebad05a29d01b0a5203fc077de068e1dfaa70507`.
- Its complete 556-check declared suite, TypeScript check, and build passed with runtime deployment suppressed.
- The new candidate gate fails against the released method because it performs repeated setting and metadata reads.
- The versioned candidate passes five focused actual-method gates covering edge values, exact/case-insensitive field precedence, numeric/string/missing values, stable secondary ordering, hidden state, relations, recursion, original file identity, empty/singleton budgets, thrown errors, one-snapshot enforcement, 5,000 randomized differentials, and the alternating 20,000-sibling benchmark.
- The versioned candidate passes all 561 declared checks, TypeScript, the suite's production-mode build, and a mandatory separate production-mode build.
- Both pre-deployment candidate builds reported `[runtime-deploy] target=none reason=TPS_NO_DEPLOY`. The mandatory deployment build then passed and atomically changed only `main.js` and `manifest.json` in the isolated `tps-global-context-menu` runtime; both stylesheet artifacts remained byte-identical.
- Obsidian 1.12.7 was reloaded in `Obsidian Plugin Test Vault`. A synthetic parent with children carrying `sort: 10` and `sort: 20` exposed **Link Children (2)** in the real GCM link menu, with the lower sort value displayed first. No menu action was selected and the three disposable notes were moved directly from `Inbox` to `_archive` after inspection.
- Runtime-owned `data.json` retained SHA-256 `955b97d05a4a473a1ee98696cde354f8fbbcf4f566ccb4c5ffcdb74ae8244eeb` and its original modification time. `.hotreload` likewise retained SHA-256 `7caebdb9e207a5fa31de20194bd27f380a44bcb3e302634f5598823218362556` and its original modification time.
- Production was not accessed.

## Known limitations

- The optimization is concentrated in linked-subitem sibling sets with a configured custom sort field; sibling sets without that field already avoid metadata reads for custom ordering.
- The existing deterministic secondary ordering remains intentionally supported when custom values are absent or equal.
