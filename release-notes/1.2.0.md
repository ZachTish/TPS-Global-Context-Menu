# TPS Global Context Menu 1.2.0

Capture now has explicit destinations for today's Daily Note and the current Markdown note, with optional insertion under an existing heading.

## User-visible changes

- Added `Capture: Today's Daily Note`, preserving the existing `home-quick-capture` command ID so saved hotkeys and command components continue to work.
- Added `Capture: Current note`, which targets the active Markdown file and reports a clear notice when no Markdown note is active.
- Preserved `Home: Capture to selected Daily Note` as a distinct contextual action for the day selected in TPS Home.
- Existing destination notes with headings show a `Place under` selector. `Note body` remains the default, followed by every H1-H6 heading in document order; duplicate same-level headings are numbered.
- Captures placed under a heading include its nested lower-level sections and stop before the next same- or higher-level heading. Plain Markdown and list captures retain valid block separation.

## Reliability and compatibility

- Heading discovery ignores YAML frontmatter and backtick/tilde fenced code blocks.
- The selected heading is re-resolved inside the atomic `Vault.process` mutation. Renamed, removed, newly ambiguous, or shifted duplicate headings fail closed without writing elsewhere.
- Capture write failures show a no-write notice and log only target/route metadata, never capture text.
- Capture input continues to reject new Markdown heading lines; this feature selects an existing destination section.
- Minimum supported Obsidian version: 1.10.0.
- No settings or data migration is required.

## Validation

- Focused capture, heading, and Home suites: 58/58.
- Complete declared suite: 257/257.
- TypeScript validation and the required separate production-mode build passed; the final build reported the isolated test runtime unchanged.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**.
- UI verification exercised both palette commands. Each modal showed `Note body` plus the fixture's H1/H2/H3 choices, and each capture written to a selected H2 landed after its nested H3 content and before the next H2.
- The final source artifacts are byte-identical to the isolated test-vault runtime. Both disposable QA notes were moved directly to `_archive` after verification.

## Known limitations

- `Capture: Current note` requires an active Markdown note; non-Markdown views are intentionally refused.
- The section selector targets existing ATX Markdown headings only. It does not create or rename headings, and capture text itself still cannot contain a heading line.
- If duplicate same-level headings shift while the modal is open, the write is refused so an ordinal choice cannot silently move to another duplicate section.
