# TPS Global Context Menu 1.36.0

## Intent

Let users conditionally hide a configured GCM property based on another logical frontmatter key/value without changing or removing the underlying data.

## Changes

- Added **Hide when properties match** to each custom-field editor under **Rules & fields → Custom fields**.
- A rule such as `kind=area` hides that configured field for matching notes/items across stacked/inline property surfaces and GCM context menus.
- Rules use case-insensitive frontmatter key and value matching and support equality, inequality, contains, not-contains, exists, and missing operators.
- Multiple lines are OR rules. For multi-selection, a match on any selected item hides the shared field/action so a batch write cannot cross an intentionally hidden scope.
- The rule affects presentation only. It never removes or rewrites the hidden property value.

## Compatibility and migration

- Backward-compatible minor feature; minimum supported Obsidian remains 1.10.0.
- Existing custom fields have no conditional-hide rules and behave exactly as before.
- The new optional `hideWhenProperties` setting uses the existing custom-field condition record shape; no note or Base migration is required.

## Validation

- The focused conditional-visibility and property-mode matrix passed 16/16, including case-insensitive matching, nonmatching notes, all three property surfaces, OR rules, and mixed multi-selection safety.
- The complete declared `npm test` suite passed against the final versioned source, including its production build.
- A separate mandatory `npm run build` passed. The deployed test-vault `main.js`, `manifest.json`, and `styles.css` are byte-identical to the final source artifacts.
- Obsidian 1.13.7 UI QA in the isolated test vault confirmed **Rules & fields → Custom fields → Status → Hide when properties match** renders with the `kind=area` example and supported syntax. Saved GCM settings and vault notes were not changed during inspection; production was not accessed.

## Known limitations

- Conditions evaluate the logical property record supplied by each GCM surface. For Markdown task or bullet line actions, inline fields are the line's logical property record; containing-note properties are not implicitly copied onto the line.
- Rules hide complete field controls; they do not redact the value from literal Markdown Source mode or Obsidian's native property editor.
