# TPS Global Context Menu 1.24.8

This patch makes the canonical system Daily Note creator consistently honor the configured template during startup and provider fallback.

## Root cause and changes

- Obsidian can expose an initialized Core Daily Notes options object whose template field is briefly blank while the saved `.obsidian/daily-notes.json` configuration already names a template.
- GCM treated any runtime string, including that transient blank, as authoritative and created a permanent template-less note for Calendar, Controller, Home, capture, or API callers.
- The saved template is now the durable automation source while the runtime value is blank. A nonblank runtime template still wins, a durably saved blank remains template-less, and an unavailable saved settings file leaves the blank unchanged.
- An explicitly disabled Core Daily Notes wrapper is ignored so an active Periodic Notes daily configuration can supply its folder, format, template, Core variables, and Templater processing.
- The existing single-flight, fail-closed template resolution and post-template normalization pipeline is unchanged.

## Compatibility and migration

- Minimum Obsidian version: 1.10.0.
- No settings, note schema, or public API migration is required.
- `dailyNotes.ensureForIsoDate` remains API version 1. TPS Calendar Base and TPS Controller consume the correction dynamically and do not require companion releases.

## Validation

- Focused Daily Note regressions cover startup recovery, durable blank settings, runtime precedence, missing persisted settings, disabled-Core Periodic fallback, extensionless templates, target-date variables, Templater settlement, and creation races.
- All 23 focused Daily Note regressions and the complete declared suite passed, followed by the mandatory separate production build.
- In reloaded Obsidian 1.13.6, `dailyNotes.ensureForIsoDate('2026-08-12')` created `Inbox/Daily/2026-08-12.md` from a temporarily configured Core Daily Notes template with the target date, normalized title/frontmatter, and complete template body.
- The original Daily Notes configuration was restored exactly, the synthetic template and notes were moved directly to `_archive`, and the final source artifacts byte-match the isolated test runtime. Production remains untouched.
