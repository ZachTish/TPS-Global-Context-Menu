# TPS Global Context Menu 1.10.0

## What changed

- Expanded **Kind (Entity identity)** from note-only identity to a generic note-and-line entity dimension. Markdown tasks, bullets, and ATX headings with a configured inline Kind field can now be selected alongside matching notes.
- Properties with **Accepts kind** filter every supported editor to the requested Kind. A Projects link/list field can expose only project notes and project lines; Contexts can independently expose only context notes and context lines; no Kind name is hardcoded.
- Line selections use canonical native block links. Existing IDs are reused, provisional lines receive a collision-checked ID only when selected, and stale, duplicate, deleted, moved, or reclassified candidates fail closed.
- TPS Table and TPS List now provide typed Tags and Scheduled cell editors alongside constrained entity cells. Tags search known vault tags and preserve the complete semantic tag set; Scheduled uses the normal TPS date/time workflow with `timeEstimate` and `allDay`.
- `plugin.api.entityIndex` is now version 2. `queryAsync()`/`ensureReady()` include content-backed line entities while synchronous `query()` remains note-only for backward compatibility. Locator, source, reference-target, and materialization APIs support safe line resolution.
- The generic entity index remains immutable, revision-cached, incrementally updated, and extensible through registered dimensions. Content scans retry transient read failures and publish coherent source replacements.

## Compatibility and migration

- This is a backward-compatible minor feature release.
- Existing Kind note/frontmatter behavior and synchronous note queries continue to work.
- Existing stored values are not rewritten when a constraint is added. Out-of-Kind links remain visible until the user changes them.
- Base structural row filters remain separate from Kind identity. A checkbox is not automatically a Kind `task` entity; a selectable line must carry the configured inline Kind field.
- Ordinary Markdown paragraphs are not line entities. A line must be a task, bullet, or ATX heading and must carry a configured indexed field.
- Constrained pickers intentionally provide no free-text or implicit entity-creation escape hatch.
- Minimum supported Obsidian version: 1.10.0.

## Known limitations

- Line entities are limited to Markdown task, bullet, and ATX-heading lines. Paragraphs, frontmatter lines, fenced examples, Canvas records, and non-Markdown files are excluded.
- GCM does not create a line Kind value from the constrained picker; the line must already have the configured inline Kind field.
- Constrained entity and tag pickers do not create arbitrary values. Existing out-of-Kind links are preserved but are not offered again.
- Ambiguous duplicate IDs and stale or reclassified lines fail closed.
- Automated mobile compatibility coverage passed, but this release was not physically exercised on an iOS device during the final 1.10.0 gate.
