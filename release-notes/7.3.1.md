# TPS Global Context Menu 7.3.1 — Stop completion-date backfills on metadata refresh

Opening Obsidian or changing an unrelated property could add a fresh completedDate to an older note whose status was already complete or cancelled. GCM's metadata-change listener reconciled every note with a completion status and missing date, even when the status had not changed. This patch removes that background writer from metadata, modify, rename, and delete events.

GCM's explicit whole-note status controls and status API still stamp completedDate when setting a completion status and remove it when reopening a note. Direct YAML edits and other plugins that change only status must write their own completion date if they need one. Existing dates are preserved; this release does not repair or delete previously added dates. No setting, API, data format, migration, or minimum Obsidian requirement changes. Minimum supported Obsidian remains 1.10.0.

## Validation

- Focused executable regressions cover 100 startup-style metadata and modify events with zero frontmatter writer calls, externally changed complete/cancelled statuses and rename events with zero date writes, and explicit GCM status edits that still add/remove dates. The old listener would have attempted completion-date writes for the completed notes in that burst; the new listener attempts none.
- The full declared npm test workflow passed 1,511 tests with zero failures, including TypeScript and its build. A separate final production-mode build deployed the same artifact to Obsidian Plugin Test Vault.
- In the foreground Test Vault on Obsidian 1.14.4, a named app reload showed TPS Global Context Menu v7.3.1 in Community Plugins. Two synthetic Inbox notes with complete and cancelled status and no completion date remained undated after creation, unrelated frontmatter edits, and rename. Their mtimes stayed unchanged after the edit event settled. They were moved directly to _archive; another app reload left both archived file hashes and mtimes unchanged. GCM runtime data.json and recurrence-session.json mtimes stayed at their pre-deployment values.
- These are mutation and file-integrity observations; no installed latency or UI-stall claim is made. The test used an app reload, not a cold process launch. Physical iPhone and production behavior remain unverified. The public release is ready for the user's BRAT pull and has not been installed in production.
