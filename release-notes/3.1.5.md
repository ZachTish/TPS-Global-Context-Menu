# TPS Global Context Menu 3.1.5

Reduce pauses during ordinary vault use by avoiding repeated timer-source reads and unnecessary layout checks when opening notes.

- Timer-status and scheduled-time maintenance share in-flight scans. Verified session data and verified absence of sessions are cached per file; note bodies and unrelated properties are not retained.
- Edits, imports, metadata changes, renames, deletion, file replacement/stat changes, property changes and GCM timer writes invalidate the relevant results. Reads overlapping changes retry against current sources. Read/YAML failures remain retryable rather than becoming cached negative results. Session arrays and records returned to callers are independent copies.
- Warm scans still enumerate eligible files, but unchanged sources are not reread. Companion-note classification runs only for timer candidates; archive/companion exclusions remain effective.
- Linked-subitem mode detection uses Obsidian's reported mode without computed-style/geometry reads. Cleanup removes old decorations from visible and hidden preview wrappers without measuring visibility or touching CodeMirror widgets. Rendering still chooses the visible preview wrapper when needed.

## Compatibility and limitations

Backward-compatible **patch release**, minimum Obsidian **1.10.0**. No new settings, defaults, API versions or note migration. Timer intervals, reload scheduling and production configuration are unchanged.

The first timer scan after loading still reads eligible notes. Warm scans still enumerate files; malformed/unreadable sources retry. Other indexing, menu rendering, editor features and external providers can still contribute latency. A separate Source/Live Preview transition interaction remains unresolved; this release preserves the existing mode-transition scheduling and decoration-retention guards. Measurements below are desktop test-vault component samples, not production/iPhone guarantees or proof that every typing/scrolling delay is resolved.

## Validation


- `npm test`: **1,217 passed**, zero failures/skips, including TypeScript and build. `npm run prepretest`: **148 passed**. Focused timer coverage includes 1,000 files, shared scans/independent returns, stale metadata, own writes, imports/rename/delete/replacement, configuration changes mid-read, stat-only changes, read/YAML recovery, and BOM/CRLF/YAML end markers. Opening tests cover reported-mode/DOM fallback, layout-free cleanup and preservation of editor widgets during preview cleanup.
- Installed timer baseline on 3.1.4: **1,203.2 / 788.3 / 753.6 ms** across **8,796 notes**. Final warm scans: **22.9 / 22.9 / 21.1 ms** across approximately **8,800 notes**, with identical normalized session results. Median improvement **34×** for the scan component. Two synthetic UI fixtures and associated runtime activity changed the overall file count slightly; no extra timer session remained in the comparison.
- Warm checks retained **three retryable source reads** per scan rather than caching failed/malformed inputs as permanent absence. A forced cold scan took **949.5 ms**. Initial scanning is still required.
- Installed append/update/remove checks used a closed synthetic timer record and verified each operation through the scan result immediately. The original fixture content was restored afterward; no active timer or outbound automation was started.
- Four editing-view opens made **zero calls** to linked-subitem visibility measurement in the final path. `openFile` resolution was **28.3 / 34.5 / 22.0 / 25.5 ms** versus **37.5 / 55.8 / 25.7 / 34.6 ms** initially. These small samples do not establish end-to-end opening speedup; asynchronous menu work still follows opening. The confirmed improvement is removal of the forced-style-read path identified in production diagnostics.

- Final installed fresh-note UI checks: Reading view rendered its linked-item checkbox, Live Preview rendered its editor widget, and fresh strict Source mode rendered no editor widget. The experimental mode-transition changes were excluded after a blank-widget interaction was reproduced; mode-transition scheduling and retention guards remain unchanged.
- Mandatory separate final `npm run build`: passed and republished byte-identical artifacts to **Obsidian Plugin Test Vault**. Explicit plugin reload loaded **3.1.5**. Test runtime artifact bytes matched source artifacts. Persisted GCM settings remained unchanged, temporary diagnostics were removed, debugger capture was stopped, both synthetic fixtures were moved directly from Inbox to `_archive`, extra QA tabs were closed, and the original tab was restored.

Tested in the test vault and ready for the user's **BRAT pull** of exact numeric tag **3.1.5**. This release has not been installed in production by this task and does not constitute user/device acceptance.
