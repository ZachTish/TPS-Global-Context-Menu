# TPS Global Context Menu 3.6.11

A saved title now appears as soon as Obsidian delivers its updated metadata. Previously, title-only saves refreshed the property menu while the inline title could wait for the 900 ms recurring display pass. The existing metadata listener now clears that file's title cache and refreshes only its open Markdown titles.

This is a patch release: filename ownership, native-record filename protection, focus guards and strict-source filename display are unchanged. It adds no watcher, timer, retained cache, file write, settings/schema migration or API version. The periodic pass remains for remounted mobile title/icons and rendered links. Minimum Obsidian: **1.10.0**.

## Validation

- Five new regression checks failed before correction. All 54 focused title, source-mode, open-refresh and event-batching checks pass. They cover multiple views, unchanged bursts with zero DOM writes, unopened files, active title editing and the existing metadata-event connection.
- Final versioned declared suite: **1,322 passed**, zero failures/skips. Supplemental suite: **193 passed**, zero failures/skips. Node 24.19.0/npm 10.9.2, TypeScript and the build-only suite build passed.
- Separate production-mode build deployed only shipped main/manifest into **Obsidian Plugin Test Vault**. Named GCM disable/loadManifest/enable verified 3.6.11. Other consumers remained enabled and no settings were changed.
- Actual foreground Edit Title/Save actions on three native task notes: visible updated title **340.4 / 586.7 / 671.2 ms before**, **49.3 / 38.6 / 39.0 ms after**. Saved data finished in **20.1 / 14.6 / 10.6 ms before**, **19.5 / 18.1 / 13.8 ms after**. Before, metadata was already updated and the subsequent recurring title pass caused the DOM change; after, the metadata listener caused that change immediately. No measured long tasks in these six captures.
- Each native sample made one frontmatter operation and one note modification, with no native global identity reads. The new refresh itself has zero file reads/writes/timers and makes no vault enumeration. Broader capture counts still include independent consumers (roughly 10,900 metadata inspections in the after samples and an independent 147-read burst in one). This patch does not remove that background work.
- An ordinary title edit still renamed its filename once and preserved its body. Its window lost foreground before final inspection, so its timing is excluded from the foreground comparison.
- All fixture bodies and native IDs were preserved. Five plugin settings remained byte-identical, prior view state was restored, hooks were removed and fixtures moved to `_archive`. Final documentation rebuild was byte-identical to the UI-tested artifacts.

Timing starts at the title writer and ends at the first animation-frame observation of the correct visible inline title. It does not measure physical input/compositor latency or establish plugin-free/native parity. Production and physical iPhone performance remain unverified. Core backlink rewrites and cold native identity verification remain separate costs.
