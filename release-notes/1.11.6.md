# TPS Global Context Menu 1.11.6

This patch makes reactive note-level `completedDate` synchronization lossless across multi-file metadata bursts while keeping writes serialized and fail-safe.

## What changed

- The vault-wide single-argument debounce is replaced by one trailing 400 ms keyed batch, retaining one pending entry for every changed Markdown file.
- Repeated events for one file still coalesce into one reconciliation; distinct files can no longer replace one another in the pending work.
- Batches run sequentially through GCM's owned frontmatter mutation service, avoiding concurrent vault/iCloud writes and removing this workflow's dependency on the global `fileManager.processFrontMatter` compatibility patch.
- Each queued file is resolved from the vault immediately before mutation, and live parsed frontmatter is rechecked before adding, normalizing, or removing `completedDate`.
- Rename, delete, replacement, unload, stale-cache, slow-write, cross-batch, and per-file failure cases are contained without allowing one file to block the rest.
- Completion detection now uses the shared canonical status contract, so configured aliases such as `done` behave consistently with `complete`.

## Compatibility and migration

- This is a backward-compatible patch release.
- No command, setting, API, note-data, or workflow was removed.
- Statusless dates remain untouched, scalar completed dates remain stable, completion-date arrays normalize to their last nonblank value, and reopened notes remove the date as before.
- No settings or note-data migration is required.
- Minimum supported Obsidian version: 1.10.0.

## Validation

- The exact released 1.11.5 event source passed 2 of 7 initial compiled-code batching and lifecycle checks.
- Under 1.11.5, 100 synchronous distinct-file metadata events produced one mutation for the final file and dropped 99. Under 1.11.6, the same burst produces 100 unique serialized mutations, while 100 events for one file still produce one mutation.
- The final expanded behavioral harness passes 11 of 11 checks, including live-frontmatter rechecks, owned-service routing, alias normalization, rename/delete/replacement handling, unload cancellation, per-file failure isolation, slow-batch lifecycle changes, and cross-batch serialization.
- All 533 declared checks, TypeScript, the suite's production-mode build, and the mandatory separate final `npm run build` passed.
- Obsidian 1.12.7 was reloaded with the final 1.11.6 artifact in the isolated test vault. The device remained in its existing `TPS: User` role, so a synthetic background-automation probe correctly stayed disabled; its three notes were moved directly to `_archive`.
- Runtime `data.json` remained byte-identical at SHA-256 `955b97d05a4a473a1ee98696cde354f8fbbcf4f566ccb4c5ffcdb74ae8244eeb`.
- Production was not accessed. This release is ready for the user's BRAT pull.

## Known limitations

- A failed file is logged and can reconcile on a later metadata event; the batch does not add an automatic retry loop for persistent read/write failures.
- Files in a large burst are processed sequentially by design to avoid parallel vault and iCloud writes.
- This workflow no longer relies on the global `processFrontMatter` patch, but that broader compatibility patch still serves other GCM workflows and requires a separate audited removal.
- The real-vault background mutation itself was not forced by changing the test device from its existing `TPS: User` role; compiled behavioral coverage exercises the complete nonvisual event path instead.
