# TPS Global Context Menu 11.1.0

Bulk list controls previously used only the first selected note. They now show every value across the selection, with the number of notes containing each value. Removing `entity` keeps `note` and unrelated values. The existing TPS Notebook Navigator file-menu bridge supplies its exact selection, so Navigator needs no runtime change.

## Behavior and compatibility

- Native menus show `entity — 2/4 notes` and `Remove entity — 2/4 notes`. Checkmarks mean all selected notes contain a value. Adding a list value appends it; removing one value affects matching notes; `Clear all values` explicitly removes the field.
- Floating/stacked list controls show counted removable pills. Bulk rows wrap and scroll vertically at narrow widths. Removal buttons have accessible labels and visible keyboard focus. The existing metadata refresh owner updates managed panels; removal does not immediately re-read stale metadata and reinsert a removed pill.
- Scalar choice menus include authored values missing from suggestions and show coverage. Scalar choices retain replacement semantics.
- Each note counts once per value, including duplicate authored list values and repeated selection entries. Missing fields count toward the denominator. Tag normalization and entity alias identities follow existing writers; text remains case-sensitive.
- List removal skips known nonmatching closed notes before entering the existing queue, then recomputes against fresh source at the existing atomic boundary. Other list members, bodies and user properties are preserved; exclusions and editor/source conflict guards remain authoritative.
- No settings/schema migration, new listener, cache, poller, repair writer or vault scan. No Navigator built-in tag action changes. Minimum Obsidian: **1.10.0**.

Full declared `npm test`: **1,985 tests passed, 0 failed, 0 skipped**. Separate final `npm run build`: passed. Focused regressions cover first-note absence, union/counts, partial versus all-note checkmarks, uncatalogued values, duplicate notes/values, tags/entity aliases, unchanged-file skips, removal idempotence and concurrent additions preserved at the writer.

Reloaded **11.1.0** in Obsidian Plugin Test Vault, Sync disabled, normal consumers enabled. An actual Navigator multi-selection/contextmenu populated GCM with all four notes. The native submenu was displayed with Obsidian's HTML menu renderer for screenshot inspection.

Installed operations verified:

1. `entity — 2/4 notes`; `note — 2/4 notes`; `task — 1/4 notes`, with no misleading all-note checks.
2. `Remove entity` changed only two matching notes; the other two were byte-identical. `note`, duplicate `task` members, bodies and unrelated properties remained.
3. Adding `entity` reached all four notes; reopening showed `4/4` and a checkmark.
4. The actual GCM panel component, hosted by the test harness at 390 CSS pixels, kept every removal button within its horizontal bounds. Clicking × removed only `entity` from all four notes without reintroducing a stale pill.
5. Explicit whole-field clear preserved bodies and unrelated properties.

Temporary in-memory QA property/display configuration was restored without saving. GCM private-state hashes remained unchanged. Synthetic notes were archived outside active Inbox. These are installed desktop checks and a narrow component-layout check, **not physical iPhone acceptance**. Native menus snapshot counts when opened; reopen after editing for updated counts.
