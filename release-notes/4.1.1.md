# TPS Global Context Menu 4.1.1 — Defer unused entity indexing

When Obsidian first reported resolved metadata, GCM rebuilt its note-entity index even if no picker or API caller had requested it. That enumerated every Markdown file and inspected almost every file's metadata. GCM now leaves an unused index cold. Its first query builds from current metadata; if a query occurred before metadata finished resolving, the first `resolved` event still repairs note records and restarts any active line index. Later broad `resolved` signals do not trigger an unused rebuild.

This is a backward-compatible patch with no setting, stored-data, writer, or public API change. Note-only queries and explicit line-entity pickers retain their behavior. The minimum Obsidian version remains **1.10.0**. It was tested in **Obsidian Plugin Test Vault** and is ready for the user's BRAT pull; production was not changed.

## Validation

- Focused entity-index tests passed **50/50**. Counted cases confirm zero Markdown enumerations, metadata lookups and body reads on idle first/repeated resolution; a first query builds once from current metadata, including pre-build changes and creates. Early note and line queries still receive one authoritative first-resolution rebuild without duplicate line entities.
- The final versioned declared `npm test` passed **1,447/1,447** with no failures, skips or cancellations. It includes TypeScript and an embedded build with deployment suppressed. A separate normal `npm run build` passed and deployed the tested `main.js` and `manifest.json` to the Test vault; `styles.css` was byte-identical. A final build after README edits reported unchanged runtime bytes.
- On installed 4.1.0 in **Obsidian Plugin Test Vault**, an isolated instance of the released class with the real dimension definitions and a capture-only event host ran the idle first-resolution path against **11,952** Markdown files. Each of three samples performed one enumeration, **11,951** metadata lookups and zero body reads; synchronous durations were **219.7, 159.5 and 162.7 ms**. The target document was visible, but DevTools held focus. These direct operation samples do not measure full startup, note visibility or production speed.
- A named GCM disable/loadManifest/enable in the exact Test vault confirmed that the live plugin object and registry both report **4.1.1**, with GCM enabled. Deployed files match the source hashes below; runtime `data.json` retained its prior SHA-256 (`a010fa519922568886b6eedfe49aa10371bb9a525d8d3bd9a312fbfa53b3e249`). The after-change operation count is demonstrated by focused service tests; installed after counts/timing and full startup/input-to-paint comparison were not completed. Physical iPhone behavior remains unmeasured.
