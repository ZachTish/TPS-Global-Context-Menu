# TPS Global Context Menu 3.1.0

Health's **Note library → Entry and session frontmatter key** now supports the same key as reusable entities/templates, or a separate key. For example, templates can use `entityKind`, logged Health records `entryKind`, and tasks `kind`.

Apply previews and confirms changes to only native Health food/activity entries, workout sessions and legacy workout exercise records, including archives. Templates and other TPS record types keep their keys. Cancel changes nothing. Switching back to the shared key is supported. No fallback aliases are introduced.

GCM owns the persisted per-kind key map, so it remains available when Health is disabled. Creation, reads, editing, reidentification and consolidation use the current key. Changing a Health record-type value carries its key binding to the new value; save failures restore the previous binding. Invalid destinations, stale settings/notes and ambiguous YAML stop migration.

Minor release: existing defaults and storage remain compatible, with an empty key-map default and optional nativeRecords API v6 capability. Update **GCM 3.1.0 first**, then Health 3.1.0. Minimum Obsidian: **1.10.0**. Settings destinations and disclosures remain unchanged; the new labeled input supports Apply/Enter and focus restoration.

## Validation

Full `npm test`: **1,202 passed, 0 optional skips, zero failures**. Plus 131 additional checks passed. TypeScript and a separate final `npm run build` passed; the deployment helper reported `target=test`. Final artifacts were reloaded in **Obsidian Plugin Test Vault**.

Using the installed Health settings, QA cancelled and then confirmed a two-record migration. The template and task remained unchanged, bodies were preserved, focus returned, and recovery cleared. A new record stored only the separate key; editing retained it. A second UI confirmation returned all three logs to the shared key. Original settings were restored and five synthetic fixtures archived. At a 388 px settings container, the control row had no horizontal overflow. Physical iOS acceptance remains user testing; no outbound automation was enabled.

Frontmatter is migrated; inline fields, Base formulas and per-view mappings are not rewritten. The existing recovery/rollback limitations for process crashes and concurrent edits on another device remain. No migration runs automatically on upgrade.

Ready for the user's **BRAT pull**. Production was not deployed or reloaded.
