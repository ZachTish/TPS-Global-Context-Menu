# TPS Global Context Menu 7.3.2 — Prevent stale property writes after rename or completion

The closed-note property writer previously read a source snapshot and later submitted a full `Vault.modify` write. Obsidian's adapter captures the write path before its serialized queue; if an automatic rename was already queued, the later write could recreate the old path. A concurrent completion could also be replaced by the older snapshot.

The existing writer now uses `Vault.process` and rechecks the same live file object, captured path, and exact current source bytes inside its atomic callback. A missing, replaced, or changed target fails before mutation, indexing, or success events. Asynchronous mutators execute once. There is no automatic retry, new queue, watcher, repair, deduplication, or migration. Existing duplicate notes are not modified. An explicitly refused action must be performed again against the current note.

Source-editor behavior and unchanged-property operation counts are retained. Successful closed-note writes preserve BOM, header line endings, and the exact body, including mixed line endings. Settings, APIs, note schema, and minimum Obsidian 1.10.0 are unchanged. This backward-compatible root-cause correction warrants a patch release.
