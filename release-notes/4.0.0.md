# TPS Global Context Menu 4.0.0

An edit to an already selected native record previously waited for the same vault-wide identity verification used by sync reconciliation. Selected-file reads and edits now inspect only the selected source. This removes the first-use global scan from Health activity/food/workout edits and Calendar direct event edits without creating another cache, watcher, timer, retry or repair system.

## Authority contract and compatibility

This is a **major release**: a `TFile`, existing path string or `{path, id?}` identifies a local target; its returned handle does not guarantee the absence of an unseen duplicate elsewhere. Known duplicate/blocked identities still reject the operation. A missing explicit object path or detached file object cannot redirect to another owner. Reads reject movement/replacement/stat or mapping changes; atomic source-preserving writes recheck the target and identity. Renames recheck source and destination after asynchronous folder preparation.

ID-only references, snapshots/listing, explicit-ID creation, identity changes and reconciliation plans keep full authoritative verification. Plans use that route even with path references. Consumers needing global ownership must pass an ID or use the existing snapshot/plan APIs. Controller's calendar sync already uses those APIs. NativeRecords API v6 method shapes remain compatible; the additive `selectedFileAuthority` capability identifies the new semantics. No settings or note schema migration, consumer release, or automatic deduplication is required. Existing caller-owned automatic-write exclusions remain in their owning workflows. Ordinary GCM Edit Title uses a separate writer and retains 3.6.16's committed-rename display fix.

Minimum Obsidian remains **1.10.0**. Tested on desktop Obsidian 1.14.2 with Health 3.8.4, Calendar 0.16.3, Navigator 7.0.8 and other installed consumers enabled; no outbound provider automation or production access.

## Validation

- 131 native-record checks, 1,359 declared-suite checks and 209 supplemental checks passed, zero failures/skips. TypeScript and separate normal Test deployment passed. Twelve new regressions exercise all selected reference shapes, a 100-read burst in a 1,001-file fixture, unseen vs known conflicts, missing/replaced/moved targets, changed mappings and concurrent body/identity edits. Six initial new cases failed before correction. Existing global identity, reservation, migration, stale-plan and source-preservation suites remain required.
- Named reload verified the final version with unchanged data.json. In actual foreground Health dashboard Edit/Save actions, first save took 3,652 ms before versus 11.6 ms after; repeated save took 3.2 ms before versus 8.2 ms after. Modal dismissal was 3,716/42 ms before and 57/65 ms after. These are two samples per build, not latency distributions or a claim that every warm action improves.
- First save identity-source reads fell from 11,131 to two. The after build performed zero global refresh calls and zero enumerations through save completion, with one target process/write. The repeat also read the selected source twice. Bodies and IDs survived; no outside target mutation or long task was observed. The native global source cache remained empty through both after saves.
- Separate installed API checks proved full global verification still runs: 11,135 source reads and two enumerations rejected a duplicated ID lookup, reidentification, known-conflict edit and missing explicit path. Synthetic sources remained byte-identical. No external event sync was executed.

Counts through operator dwell include unrelated enabled-consumer work (including a periodic 147-read burst in the baseline repeat). Only the after probe records a counts-at-save snapshot; compare native-service counts and save timings directly, not total phase reads as exclusive CPU attribution. No other consumer was disabled. Initial probe setup once refused foreground state before creating anything; only actual foreground Save samples are counted. Settings were unchanged across seven monitored plugins, all hooks removed, and fixtures archived directly. Health dashboard was opened for QA from an empty tab and restored afterward. Minimum-version devices, physical iPhone, true cold-process startup and the overall 80% native-performance target remain unproven.

Tested in Obsidian Plugin Test Vault and ready for the user's BRAT pull. Production installation and user/device acceptance remain separate.
