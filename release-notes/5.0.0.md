# TPS Global Context Menu 5.0.0 — Whole-note task authoring

**Create task** now creates one standalone Markdown task note. Initial status choices come from the normal Status field, independent of saved checkbox mappings. Saved Atomic line selections cannot restart line authoring: GCM forces Atomic note mode and disables task-line writers on load and save. Existing checkbox lines, historical child-link text, and old task data remain readable without an automatic migration or note-open scan. New child notes use frontmatter parent relationships without inserting checkbox-link lines into the parent; Daily Note opening no longer scans the vault to populate scheduled checkbox links.

The Tasks and Daily Notes settings pages retire the architecture choice, task parent, checklist promotion, linked child-checkbox rendering/mappings, task-line hiding and reveal persistence, item history, inline status reconciliation, Daily Note task-line moving/auto-population, TPS Base line-write fallback, `@@` inline set, and completion prompt status options. The remaining open-checkbox completion safeguard warns at the whole-note level with Open, Ignore, or Cancel; it cannot change checklist lines. GCM's checklist panel is read-only in Atomic note mode. The five-destination settings hub, default Rules & fields route, existing mobile layout, note-record root/layout, and note-level time tracking remain.

The public `tasks` API advances to **v4**. Its read-only line inspection methods remain for historical content, but create, update, status, checkbox, completion, field, move, and delete methods return an explicit unchanged error before task-line reads or writes. `taskLines` and `itemProperties` advance to **v2** with `supportsTaskLineMutation: false`; `taskRecords` advances to **v2** with `supportsPromotion: false`. Direct checklist-to-note and task-line-to-note promotion also reject. Integrations should create/edit whole-note tasks through `nativeRecords`. Controller and Calendar Base consumers should fail closed on the new capability; Notebook Navigator's older line action UI requires its corresponding whole-note cleanup. This breaking settings/API behavior warrants the 5.0.0 major version.

GCM's native-mode task-line context menus/editor hooks, TPS List/Table writers, Daily Inbox commands, AI-assisted line creation, recurrence and checkbox reconciliation, inline property edits, timer-created or timer-updated task lines, linked child-checkbox sync, child body-link insertion/removal, and unresolved-link cleanup are inactive. A shared Markdown-body boundary rejects residual GCM-owned line mutations. Ordinary Markdown note editing and note-level properties/relationships remain. Historical inline content, saved mapping keys, and session data are not rewritten. Minimum Obsidian remains **1.10.0**. Physical-iPhone acceptance remains separate; production installation remains the user's BRAT pull.

## Validation

- Focused zero-write regressions cover native API rejection, checklist/linked-child mutations, shared Markdown-body writes, TPS List/Table, standalone note creation, native entity queries, timer line writes, retired settings, and Daily Note population.
- The final declared `npm test` suite passed 1,475 tests with zero failures. The separate normal `npm run build` passed TypeScript/esbuild and deployed 5.0.0 to the Test vault.
- Hot Reload applied the new GCM settings UI. In the foreground **Obsidian Plugin Test Vault** window, Workflows → Daily notes and Tasks showed no architecture, task-line authoring, checklist promotion, line hiding, or scheduled-link population controls. The `Create task` command showed **Create task note** and created a standalone `_records/tasks` Markdown file with `kind: task`, `status: todo`, `title`, and `tpsId` frontmatter and no checkbox/body line. The synthetic QA record was moved directly to `_archive/QA GCM whole note v5.md`.
- Deployment preserved the existing runtime `data.json` byte-for-byte. On plugin reload, GCM saved the intended whole-note normalization: `dataArchitectureMode: native-records`, standalone task parent, Daily Note population off, and linked child checkboxes off. No runtime data file was copied from source or overwritten by deployment.
