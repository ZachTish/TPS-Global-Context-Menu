# TPS Global Context Menu 1.48.1

## Workflow-owned filename protection

- Generic title/filename synchronization now waits until it has derived a real mutation, then reads one authoritative Markdown snapshot immediately before the write or rename.
- A positive native-record cache entry remains the fast path. A stale negative cache can no longer override current `tpsId`/schema evidence, and malformed YAML that still contains configured current or readable legacy identity evidence keeps its workflow-owned filename.
- Existing run, workflow, workout, workout-plan, workout-session, and workout-exercise markers receive the same path ownership. This keeps TPS Health 0.30.0's date-first Legacy workout filenames and their saved titles from being rewritten as ordinary notes.
- Already-matching notes perform no extra authoritative read. Ordinary notes retain their existing title-derived filename behavior, and GCM never infers native ownership from the basename.

This is a backward-compatible correctness patch. It changes no setting, public API version, native schema, stable identity, command, body format, or existing path automatically. Minimum supported Obsidian remains 1.10.0.
