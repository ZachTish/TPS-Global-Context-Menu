# TPS Global Context Menu 1.17.0

## Intent

Make every GCM-owned Markdown-line query respect the document's real block structure, so task-shaped examples kept in frontmatter or protected blocks can never reappear as live Base rows, entity choices, card previews, or Task API results.

## Changes

- Added one shared document-level CommonMark scanner for TPS Table, TPS List, the Entity Index, card task previews, and Task API discovery/resolution.
- YAML frontmatter plus fenced, indented, HTML, and comment blocks are excluded before line type, inline fields, filters, formulas, hierarchy, or identity are evaluated. Legitimate nested list items and inline code remain supported.
- `plugin.api.lineMetadata` version 1 now exposes immutable `scanDocument(content)` records with exact physical indices, line numbers, text, and UTF-16 offsets. This is additive for existing callers and is the required discovery boundary for coordinated Calendar and Kanban releases.
- Entity materialization and Task API mutation re-resolution refuse a formerly visible item that moved into protected Markdown before the guarded write.
- TPS List scans and parses each cold source once, then derives open previews, complete rows, and overflow from that canonical task set. Its former second extraction/merge path is removed.
- Ordinary documents without possible protected-block syntax take an exact fast path; possible block syntax invokes the CommonMark parser. The candidate bundle grows only marginally because the parser was already present through GCM's Markdown editor dependencies.

## Compatibility and migration

- Backward-compatible minor release; no setting, Base, note, task, or stored-data migration.
- Minimum supported Obsidian remains 1.10.0.
- Install GCM 1.17.0 before TPS Calendar Base 0.4.1 and TPS Kanban 0.2.1. Those consumers intentionally fail synthesized line discovery closed when this scanner capability is missing or malformed.

## Validation

- Exact released 1.16.0 fails the new behavioral regressions by admitting protected task-shaped rows; the versioned candidate passes the focused scanner, Table, List, Entity Index, card-preview, and Task API suites.
- The complete declared GCM suite passes 708/708 tests, followed by TypeScript and a mandatory separate production-mode build in the isolated test vault.
- Test-vault reload and live cross-view QA confirm only eligible visible tasks appear in TPS Table, TPS List, Calendar, and Kanban while quarantined examples remain absent. Runtime-owned state remains unchanged; production is not accessed.

## Known limitations

- `scanDocument` deliberately exposes only eligible physical lines. Consumers that require synthesized line discovery must treat a missing, throwing, or malformed provider as unavailable rather than parsing the raw document independently.
- Native Obsidian note rows are unaffected; this boundary applies to TPS-synthesized Markdown line records.
