# TPS Global Context Menu 1.8.0

## What changed

- TPS List and TPS Table now resolve the active view and whole-Base filters into one branch-correlated creation plan. A simple All views kind can combine with active-view schedule, status, priority, tags, and other exact defaults.
- Ordered `or`/`any` alternatives are tried top to bottom and backtrack only when needed to satisfy a later constraint. The resolver never mixes defaults from unrelated alternatives.
- `+ New` can create checkbox tasks, plain bullets, generic headings (H1), and exact H1-H6 headings. Task statuses use configured checkbox mappings, tags accumulate, deterministic date windows choose a matching date, and scalar equality defaults become inline properties.
- GCM validates the prospective structural line against both effective filter roots before append. Contradictions, unmapped statuses, invalid explicit targets, and known nonmatches fail closed.
- The resolver has bounded search guards (64 concurrent states and 256 visited nodes) so complex filter trees cannot create an unbounded UI operation.

## Compatibility and migration

- This is a backward-compatible minor release.
- No settings migration or note-data migration is required.
- Minimum supported Obsidian version: 1.10.0.

## Known limitations

- Filters whose truth depends on unsupported runtime-only functions cannot always yield a deterministic creation default. GCM records partial validation and still refuses every predicate it can prove false.
- `exists()` without a semantic value does not invent arbitrary property content. Use an equality, ordered alternative, or bounded date predicate when creation must populate a specific value.
