# TPS Global Context Menu 1.11.5

This patch makes the time-tracking status bar reliably converge on the latest persisted timer state without turning event bursts into unbounded vault scans.

## What changed

- A public/event-driven refresh arriving during an authoritative status read now requests exactly one trailing read instead of being discarded.
- Bursts remain bounded: 100 overlapping refreshes perform the active read plus one necessary latest-state read, not 100 additional reads.
- One-second elapsed-time display ticks and overlapping setup/poll reads keep their existing coalescing behavior and do not schedule needless full status scans.
- Status-read failures are contained and logged instead of becoming unhandled promise rejections; a refresh queued behind a failed read still runs.
- Detach/re-setup lifecycle races cannot let an older asynchronous read mutate a removed or replacement status item.
- Successful pause, resume, stop, and clear actions use the Time Tracking service's existing post-persistence refresh, eliminating the previous redundant third scan. No-op actions still request reconciliation.

## Compatibility and migration

- This is a backward-compatible patch release.
- Commands, settings, plugin APIs, timer records, and note workflows are unchanged.
- No settings or note-data migration is required.
- Minimum supported Obsidian version: 1.10.0.

## Validation

- The exact released 1.11.4 implementation passed 2 of 6 new compiled-code concurrency and lifecycle checks. It discarded a refresh queued behind an active read, left the UI stale after a 100-refresh burst, exposed read rejection, and lost refreshes across detach/re-setup.
- The final 1.11.5 implementation passes all 6 checks. The same 100-refresh burst changes from one stale authoritative read to exactly two reads whose result is the latest state.
- All 522 declared checks, TypeScript, the suite's production-mode build, and the mandatory separate final `npm run build` passed.
- Obsidian 1.12.7 was reloaded in the isolated test vault. A synthetic note completed the full active → paused → resumed → stopped status-bar cycle, with each transition appearing immediately.
- The temporary storage mode and service-enable setting were restored. Runtime `data.json` returned byte-for-byte to SHA-256 `955b97d05a4a473a1ee98696cde354f8fbbcf4f566ccb4c5ffcdb74ae8244eeb`, and the QA note was moved directly from `Inbox` to `_archive`.
- Production was not accessed. This release is ready for the user's BRAT pull.

## Known limitations

- A burst can schedule one trailing authoritative scan; this is intentional because the active scan may have observed state before the persisted change.
- If an authoritative read fails and no refresh is already pending, the status bar retains its last rendered state until another event or the existing 30-second authoritative poll.
