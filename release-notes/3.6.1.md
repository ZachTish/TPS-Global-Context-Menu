# TPS Global Context Menu 3.6.1

A backward-compatible performance fix: opening or leaving unchanged notes no longer schedules checklist maintenance that competes with Obsidian's note-loading file queue.

## Changes

- Removed navigation/layout-triggered checkbox reconciliation, checklist-property updates and retired relationship-repair calls. Existing content-change events and explicit settings/synchronization actions remain the owners.
- Skip unchanged checkbox reconciliation before `vault.process`; recheck exclusions and recompute from the current atomic source when writing. Cached data is never used to overwrite a newer document.
- Skip authoritative protection/safety reads when checklist/completed-date metadata or a Daily Note's scheduled value already needs no update.
- Use live/cached text for read-only unresolved-link inspection, and skip delayed checks for notes no longer active. Explicit body mutations retain their fresh-read path.
- Add operation-count regressions for navigation bursts, 1,000 unrelated files, no-op mutations, actual edits, concurrent source changes, exclusions, Markdown examples and line endings.

No new settings, persistent caches, watchers, retries, automatic repair or data migration. Explicitly configured naming/title/presentation/Daily Note population actions retain their behavior and can still do work on open.

- Named test-vault plugin disable/enable reload loaded 3.6.1.

- Runtime settings remained byte-identical. Temporary in-memory QA settings were restored, original note selection restored and synthetic fixtures moved directly from Inbox to `_archive`.

### Installed before/after sample

Two unchanged synthetic notes, four switches with settling periods. Checklist-property maintenance and a template exclusion enabled temporarily in memory. Naming-on-open was isolated out to measure the affected maintenance paths; these are not all-settings production benchmarks. Read counts include core Obsidian reads. Both runs preserved note content.

| Measurement | 3.6.0 | 3.6.1 |
| --- | ---: | ---: |
| Raw `vault.read` calls during navigation | 20 | 8 |
| Cached-read calls during navigation | 15 | 8 |
| `vault.process` attempts during navigation | 3 | 0 |
| Explicit unchanged reconciliation: raw reads, two files | 2 | 0 |
| Explicit unchanged reconciliation: mutation attempts | 2 | 0 |
| Open durations, milliseconds | 495, 543, 12, 4077 | 54, 25, 17, 22 |

The timings are a small sequential test-vault sample subject to filesystem/background-load variance. The operation counts establish removal of unnecessary work; they do not establish an equivalent production/iPhone speedup or eliminate other plugins' costs. Physical iPhone testing remains user acceptance.
