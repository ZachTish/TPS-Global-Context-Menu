# TPS Global Context Menu 1.43.0

This backward-compatible minor release removes the fixed frontmatter contract for native-record system metadata. A vault may keep property identity, rename every system property, omit timestamp properties, or store schema/kind/stable ID in one configurable tag.

Existing property-based records remain readable. GCM preserves prior profiles as compatibility aliases and provides an explicit, fail-closed consolidation action; it never silently bulk-rewrites files.

Public `nativeRecords` API version 2 gives Health, Controller, and other consumers one canonical inspector, regardless of how the identity is physically stored.

Minimum Obsidian: 1.10.0.

Known limitations: native record bodies remain empty by design, so a non-empty title property is still required. Changing domain-data property keys such as `scheduled`, calories, or calendar UID fields is outside the system-identity profile; those fields carry the user's actual record data rather than GCM bookkeeping.
