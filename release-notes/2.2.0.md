# 2.2.0

GCM owns six configurable integration property names: external calendar identity (`externalId`), promoted-task source (`sourcePath`), imported `location` and `url`, missing-event detection (`tpsCalendarOrphanCandidateAt`), and cancellation date (`tpsCalendarCancelledAt`). Configure them in **Advanced → Integration property names**. Each editor has an explicit Apply action. The existing hub/default route and disclosures remain; no existing controls or commands are removed. Native Setting rows retain keyboard access and the existing narrow-layout styling.

The additive identity API `getNoteField(frontmatter, field)` / `setNoteField(frontmatter, field, value)` resolves these names; `getExternalId` and `setExternalId` use the same mapping. Canonical API field names and inline task tokens remain unchanged. `managedNoteFieldKeys` stores selections and `managedNoteFieldAliases` retains previous names. Earlier names are read case-insensitively, ordinary writes consolidate that field into its selected name, and conflicting alias values fail before mutation. Reserved core keys and cross-field name collisions are rejected. No startup scan or bulk migration is added. Update Calendar to 0.11.0 and Controller to 1.1.0 when using custom names.

New archives no longer add `archiveOriginalFolder`; their folder structure supplies restoration, with legacy metadata still read and cleaned by the existing restore action. Promoted tasks no longer add `sourceLine` or `promotionState`; failed promotion still preserves the record and reports its path. Existing task metadata is left untouched. Folder-path synchronization preserves authored `type` and `types` fields. This is a compatible feature release, not a bulk removal of existing note properties. Minimum Obsidian remains 1.10.0.

Validation on 2026-09-11: the final versioned declared suite reported 1,145 passed, zero failures/skips; TypeScript and the production build passed. The mandatory separate build deployed only shipped artifacts to the isolated test vault. Obsidian 1.14.1 reloaded GCM 2.2.0, Calendar 0.11.0 and Controller 1.1.0. Through the real GCM settings editor, a custom external-identity key persisted, legacy identity remained readable, and a synthetic note update wrote only the chosen key while preserving its body and authored type. The temporary settings were restored and the fixture moved directly to `_archive`. The six inputs have unique accessible names, can receive focus, and fit the narrow 600 px native settings window with stacked controls; this is desktop narrow-layout verification, not an iPhone test. Controller’s Open GCM settings button selected the correct plugin. No external calendar endpoint or production vault was used. Compatibility fallbacks, alias conflicts, repeated renames, no-bookkeeping archive restoration and the consumer API contracts have regression coverage.

Ready for the user’s manual BRAT pull after public publication. This release does not bulk-clean existing note metadata or add startup scanning.
