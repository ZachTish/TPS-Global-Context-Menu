# TPS Global Context Menu 7.3.12

Test-vault-validated BRAT handoff. Backward-compatible initial native-record
discovery and lifecycle correction. Publication is separate from the user's
production installation; production remains untouched.

## Change and boundaries

Only the initial metadata inventory is cooperative. It yields a real task after
at most 256 paths or 8 ms of observed work and keeps existing incremental event
owners installed before the first yield. One-shot scheduler/MessageChannel/
timer task boundaries introduce no poller or background execution guarantee.
Queued paths resolve their current file objects; newer accepted event sources
are not overwritten by older queued metadata. Each inspection retains the
current configuration signature, classification/alias and blocked-identity
semantics from 7.3.11.

Onload awaits one owned setup promise before publishing the existing native
API. An unload resolves paused setup as cancelled and invalidates each of the
five straight-line startup continuations, including the preexisting awaited
settings/service stages. A completed explicit synchronous rebuild can replace
initial discovery. An inspection/scheduling/replacement failure rejects the
same owned promise without automatic retry. Explicit settings, migration and
cache-miss rebuild callers remain synchronous.

Awaited selected-file rename reads now have transient Symbol ownership in a
WeakMap, storing no frontmatter or content. Metadata acceptance, modification,
later rename and disposal invalidate an obsolete read; its captured path and
current TFile are checked before indexing the result. Deletion/replacement,
identity removal and conflicting metadata cannot be overwritten by the stale
read. A replacement at the old path stays indexed while the legitimate new
target is indexed separately, including before its metadata is available.
The settled read clears only its own token.

Settings, commands, public API versions, note schema and minimum Obsidian
1.10.0 are unchanged. No note writer, migration, repair, persistent source
cache, watcher or retry is added.

The timing bound is checked between paths: one expensive path inspection or
the inventory call is not preempted. [Obsidian loads plugins before interaction](https://docs.obsidian.md/plugins/guides/load-time),
and onload still waits for complete discovery, so no claim is made that this
patch improves full cold-process startup or earlier cold UI readiness.
Relationship lookup, authoritative disk verification and other plugins'
startup work are separate. Physical mobile/Windows latency is unverified.

## Focused evidence

- All 175 actual-service native-record checks pass, with no failures or skips,
  and TypeScript no-emit passes. Independent read-only review confirms the
  three candidate source/test hashes and reports no blocking data-safety or
  lifecycle issue.
- Thirteen initial publication/scheduling/lifecycle controls failed against
  the previous implementation. The existing daily-configuration await could
  resume after unload and republish even before cooperative discovery; the
  lifecycle owner now prevents that stale continuation.
- The 1,025-note controlled inventory keeps one enumeration, exactly 1,025
  metadata accesses and zero source reads or writes. Its task continuations
  inspect at most 256 paths. A deterministic clock test yields after four
  controlled 2 ms metadata steps and repeats the elapsed-work bound, without
  asserting machine-specific timing. Scheduler, channel/closed-port and timer
  routes, and legacy mode, retain equivalent final record output.
- An additional rename review baseline had six failures and one disposal
  control pass: stale reads revived deleted records, overwrote replacement or
  completed metadata, cleared conflicting-identity blocking and restored
  removed identity; the old-path-reuse guard suppressed a valid renamed target.
  All these controls pass after the ownership correction. Adjacent controls
  cover cold metadata, modification, explicit rebuild, post-startup metadata,
  and a newer read token surviving an older read's finally.
- Actual onload/onunload straight-line source through first API publication is
  executed with no-op UI/dependency boundaries and the real native service.
  These tests do not exercise later UI setup or replace installed Test-vault
  lifecycle verification. Input metadata remains unchanged.
- A separate baseline/proposed actual-source corpus matches complete index
  state through 609 index operations across seven settings scenarios, retaining
  record envelopes, ID/asset ownership, blocked paths and unchanged inputs.
  Legacy/current aliases, mapped classification, repeated changes and identity
  removal retain their existing semantics.

## Final validation

- Final versioned `TPS_NO_DEPLOY=1 npm test`: 1,609 passed, zero failures,
  cancellations or skips. TypeScript and the production-mode suite build pass;
  deployment output confirms `target=none reason=TPS_NO_DEPLOY`.
- The first declared gate stopped on a source-shape assertion requiring
  Daily Note readiness immediately adjacent to API publication. That assertion
  now explicitly requires the new startup-owner guard between those calls,
  preserving readiness and lifecycle checks. Its focused test and the complete
  rerun pass; no test or assertion was omitted.
- Explicit `TPS_NO_DEPLOY=1 npm run prepretest`: 247 passed, zero failures,
  cancellations or skips. This supplemental gate is not automatically chained
  by npm's ordinary test lifecycle.
- A mandatory separate production-mode `TPS_NO_DEPLOY=1 npm run build`
  passes after the README update, with `target=none reason=TPS_NO_DEPLOY` and
  identical suite-build hashes.
- A normal final production-mode build deployed only changed main.js and
  manifest.json to the explicitly guarded Test vault. All four runtime hashes
  match the tested candidate, and runtime data remains byte-identical. The
  targeted installed warm-reload probe confirms loaded 7.3.12.
- The matched warm reloads preserve 2,733 GCM and 182 Health records, one
  GCM/one Health metadata inventory, 39 cached/two raw source reads and zero
  note mutations. Metadata lookups are 80,228 before and 80,229 after. Settings,
  saved data, enabled plugin set and original leaf are unchanged; instrumentation
  is restored without errors and no active workout was present.
- The longest Node heartbeat gap during these hidden/unfocused desktop reloads
  is 462.9 ms before / 297.2 ms after (idle about 20 ms). Reload return is
  661.5 / 742.4 ms and total Health readiness is 741.6 / 820 ms. Total completion
  is not faster. These samples include enabled consumers and stack sampling;
  one small read-only diagnostic CLI query also occurred during the after
  sample. The heartbeat is not a foreground frame/input benchmark or causal
  proof of physical-device improvement. Synchronous relationship metadata
  lookup remains separate and is not modified by this release.
- All 13 desktop Live Preview smoke phases pass, including six tab switches
  and two remounts, with observed 24 food/39 activity rows retained. No measured
  long tasks, Health render errors or note-mutation attempts occur. Three UUID
  fixtures are exact-byte archived and GCM/Health runtime data remains unchanged.
  The host was hidden/unfocused; a foreground attempt did not establish
  visibility. Reading mode, full cold-process readiness, physical mobile and
  Windows responsiveness remain unverified.

The mandatory normal post-documentation build must preserve these exact tested
artifact hashes; a byte-identical deployment needs no second reload. Production
installation remains the user's BRAT pull, and no claim is made that every
loading or navigation stall is fixed.
