# TPS Global Context Menu 1.50.0

This minor release gives TPS templates a visible, predictable lifecycle: the template source keeps one ordinary tag, while generated notes do not inherit it.

- Fresh or previously unsaved template-identity configuration defaults to **Tag** with the exact marker `template`. Explicitly saved Tag, Property, and Templater-folder modes and their saved values are preserved.
- A source note carrying that exact top-level YAML `tags` marker is protected from GCM-owned automatic TPS mutations. Current Vault bytes are checked at the mutation boundary so stale metadata cannot permit filename/title synchronization, timestamp or folder metadata maintenance, scheduled normalization, checklist/status reconciliation, semantic Navigator rules, native empty-note adoption, or automatic Daily Note population to rewrite the template. Deliberate user edits and explicit manual actions remain available.
- New Daily Notes created through GCM, Core Daily Notes, or Periodic Notes remove only the configured template marker after the template and any Templater create hook settle. The external path is limited to the exact configured Daily Note source and output path and performs no retrospective sweep. Note-level recurrence outputs are pre-stripped and verified untagged before the series advances. Cleanup is case-insensitive for that exact scalar/list member; the source stays byte-identical, unrelated tag formatting and order remain intact, `template/example` remains distinct, and `#template` in the Markdown body remains content.
- An unsafe or unreadable source fails closed instead of risking an automatic template rewrite. A blank or unavailable Templater folder matches no templates rather than the whole vault.
- The public `templates` API remains version 1 and adds `canAutomaticallyMutate(...)` mutation-boundary checks plus `prepareInstanceSource(...)` for compatible TPS consumers. Existing version-1 discovery methods and older consumers remain compatible. No existing note, template, tag, folder, or saved setting is retrospectively migrated, and minimum supported Obsidian remains 1.10.0.

Validation passed the focused template lifecycle and automatic-writer regressions, the complete declared suite with zero failures, TypeScript, diff checks, and the mandatory separate production-mode build. Obsidian 1.13.7 reloaded the isolated test vault with GCM 1.50.0 and the compatible Navigator, Calendar, Linter, and Controller builds. A real Daily Note copy removed only the exact marker, preserved `qa-template`, `template/example`, tag order semantics, and body `#template`, and left the tagged source byte-identical. Automatic Linter Save also left a protected source byte-identical. Outbound automation remained disabled, temporary notes were archived, and production was not accessed. This release is ready for a BRAT pull after publication.
