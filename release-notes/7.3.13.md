# TPS Global Context Menu 7.3.13

Test-vault-validated BRAT handoff. Backward-compatible startup ownership/readiness
correction. Publication and the user's production installation remain separate;
production is untouched.

## Change and boundaries

Interface, command and event registrations finish in onload without awaiting a
layout-started data job. One initial native metadata inventory and relationship
discovery start after layout. Native discovery retains its real-task bounded
slices and existing event/source ownership; relationship discovery remains a
separate synchronous cost. API publication waits for native completion, initial
history recovery, Daily Note configuration and the current replacement history
owner. Startup API requests report unavailable rather than exposing partial
maps. Late consumers use the existing availability event.

Native create/fresh create, asset reuse/lookup, selected resolution, identity
planning/application and task normalization wait before incomplete-map lookup
or identity reservation. Pre-layout create/metadata/rename events do not seed
accepted-source maps that would be cleared by the initial scan, and loading
discovery events do not become newly authored task drafts. Current file owners,
duplicate/conflicting IDs, nested classification and aliases retain their
existing behavior. Explicit synchronous rebuilds can replace initial readiness
only after their complete pass; failure rejects the same owner without retry.
Unload settles paused discovery as cancelled and prevents later publication.

History setup and re-enabling reuse native readiness and the existing journal
maintenance owner. Replaced epochs cannot open a store early, capture new live
task intents in pending invalidation or publish over unfinished recovery. A
public metadata resolved event captured before the settings await completes is
passed once to the late Daily identity owner. This preserves global identity
readiness on hosts without the private initialized flag; explicit rebuild
invalidates the proof and the existing later resolved listener owns renewal.
Daily configuration adapter-read readiness is a separate promise.

Public API versions, persisted settings, commands, note schema and minimum
Obsidian 1.10.0 are unchanged. No persistent cache/index, watcher, poller,
automatic repair or retry is added. Finances late registration and Controller
early private-maintenance readiness have separate owning releases.

[Obsidian loads plugins before interaction](https://docs.obsidian.md/plugins/guides/load-time).
Removing the inventory from that barrier does not remove all cold-start work:
the relationship seed, first authoritative-source verification, an individual
expensive path and other plugins' initialization remain separate. No whole-process
cold-start, foreground input-to-paint, physical mobile/Windows or Reading
performance result is claimed.
