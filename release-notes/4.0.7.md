# TPS Global Context Menu 4.0.7

Editing a note’s properties now preserves pending editor changes and lets Obsidian save the result before GCM changes the filename or announces completion. This fixes a reproduced CRLF case where an external property write conflicted with autosave, reverted the title and misplaced body text.

- Open Source/Live Preview notes use their current editor buffer and the public incremental MarkdownView setter. Obsidian preserves body input, selection and undo, and synchronizes its native Properties model.
- Pending property actions reject a conflicting header, switched/closed target or changed editing mode. Body typing during the action is retained.
- In-flight native saves are acknowledged using temporary target-file modify/delete listeners and cached saved content. The listeners and 30-second failure deadline end with the action; no polling, retry, alternate writer, repair, permanent watcher or new cache is introduced.
- Unchanged values no longer reserialize authored YAML formatting. Repeated open-note no-ops perform no raw reads or saves.
- Bulk edits display one failure summary. Committed-title filename errors propagate to the action; automatic filename maintenance keeps its existing error policy. Already committed property edits still announce their actual path on filename failure.
- Closed-file and source-preserving automation writers retain their existing routes. No settings migration, note remediation, schema or API change.

Backward-compatible patch. Minimum Obsidian: **1.10.0**. Tested host: **1.14.2**.

Validation: **1,430 declared + 209 supplemental checks pass**, zero failures/skips/cancellations, TypeScript, separate final normal build/deployment and named GCM reload in Obsidian Plugin Test Vault. The ownership harness covers real CodeMirror history/selection with mocked host storage, the in-flight save queue and Live Preview filter boundary. An actual Live Preview dialog exposed two candidate gaps—rejected custom-origin changes and stale native Properties—which were fixed by reusing the native incremental setter rather than adding synchronization logic.

Final installed validation with GCM, Navigator, Controller, Linter, Calendar, Health and Finances enabled:

- Three dirty Live Preview cases: small/long LF and CRLF body, title, filename and custom properties retained; one source write per action.
- Four two-view cases: LF/CRLF, pending input in active or secondary editor, mixed Live Preview/Source; native shared-buffer synchronization preserves both views.
- Eight lifecycle checks: an in-flight save, typing during an asynchronous action, changed header, Reading-mode switch, file switch, close, selection/undo/20 unchanged edits and Reading-only updates. The in-flight check deliberately holds one fixture write; the action waits before renaming and native follow-up saves retain both body edits. No-op burst counts: zero raw reads, writes and native saves.
- Actual foreground title-dialog typing/Save on first and repeated edits updates title and filename, preserves body content, and synchronizes the native Properties model. Entire title selection is confirmed. The two successful callback durations were 81.5/79.3 ms, one write each.
- Actual title-dialog filename-failure check uses a fixture-only injected core rename rejection. The saved title/body remain, the filename stays at its prior path, and one visible failure notice appears. This is not a real filesystem-error test.

Seven plugin settings files are unchanged. Synthetic notes are archived with byte verification; diagnostic hooks are removed and the prior leaf restored. API samples include hidden/unfocused windows; foreground callback timings are not click-to-paint distributions. Cold startup, physical iPhone, the minimum supported host runtime and overall native-performance parity remain unverified. This release does not establish the broader 80% performance target.

Tested in the Test vault and ready for the user’s BRAT pull once published. No production deployment or user/device acceptance is implied.
