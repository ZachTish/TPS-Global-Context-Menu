# TPS Global Context Menu 7.3.10

Test-vault-validated, backward-compatible performance patch, ready for the
user's BRAT pull after publication.

## Changes

The existing mobile 900ms title/link sweep now filters Markdown leaves with the
shared `isLeafVisible` predicate before inspecting title, icon or link DOM.
Previously every retained Markdown leaf traversed its rendered links on each
pass, including hidden or detached panes. All eligible split panes still run;
the sweep does not narrow work to the active leaf. Connection, rectangle and
computed-style eligibility reads finish across the batch before title, icon
or link operations.

Retained panes catch up on the next existing tick after becoming eligible.
Mobile remount behavior and newly available or renamed link targets retain
their existing sweep owner. Direct title refreshes, existing delayed remount
callbacks, metadata updates and Markdown postprocessors are unchanged. The
visibility helper checks connection, dimensions of at least 40×40, computed
display and visibility; it is not a viewport-intersection or foreground-focus
test. Authored aliases, focused inline-title editing, strict Source filename
display, disabled inline menus and native/legacy modes keep their behavior.

This changes no saved settings, defaults, public API, note format, mutation
route or migration. It adds no cache, watcher, timer, retry or repair. Minimum
Obsidian remains 1.10.0.

## Evidence and validation

Focused regression coverage executes the actual title service and shared
visibility predicate, plus the existing icon lifecycle methods. DOM, icon
painting, metadata and editor-mode boundaries are modeled. Hidden/detached
retained links do no title/link/icon work; every eligible split pane refreshes.
Tests retain catch-up, first and renamed link targets, delayed title/icon
replacement, aliases, focused editing, strict Source, disabled menus and the
independent metadata/postprocessor owners.

- Final versioned `TPS_NO_DEPLOY=1 npm test`: 1,609 passed with zero failures,
  cancellations, skips or todos. TypeScript and production-mode bundling pass;
  deployment explicitly reports `target=none reason=TPS_NO_DEPLOY`.
- Sequential `TPS_NO_DEPLOY=1 npm run prepretest`, started after the declared
  suite finished: 214 passed with zero failures, cancellations, skips or todos.
  No concurrency, assertion or timer settings were changed.
- Separate `TPS_NO_DEPLOY=1 npm run build` after the initial versioned README:
  TypeScript and production-mode bundling pass with `target=none`. All four
  hashes match the declared-suite build. The installed Test manifest remains
  7.3.9 at that stage; this gate performed no deployment or reload.
- A separate normal production-mode build deployed changed main.js and
  manifest.json only to the Test vault. Source/runtime artifact hashes match;
  `data.json` stays byte-identical. A targeted disable/loadManifest/enable
  reload confirms 7.3.10.
- Before/after installed probes replay the exact loaded sweep method on an
  isolated service with temporary real synthetic DOM and the loaded visibility
  helper. Workspace, metadata and title/icon owner are modeled. Across 12 ticks
  with two eligible, one hidden and one detached 1,000-link panes, link
  resolutions fall from 48,000 to 24,000; root/title-icon owner calls fall from
  48 to 24. With all panes hidden or detached, 48,000 resolutions fall to zero.
  The hidden pane catches up on its next eligible tick, while the detached
  pane remains untouched. Fixtures are removed and live methods/settings are
  unchanged. This does not measure physical mobile behavior or title/icon
  painting; those lifecycle controls are covered in the source regressions.
- Installed desktop Live Preview checks with Health 4.2.3 and Navigator 8.2.2
  pass all 13 phases, including first mounts, six tab switches and two remounts.
  Observed Health widgets stay connected, with zero measured long tasks, Health
  render errors or navigation note-mutation attempts. Three UUID fixtures are
  archived after exact-byte checks. Health/GCM settings remain byte-identical
  and diagnostic observers are restored. Ordinary workspace saves remain
  separate from note mutation counts. The host is hidden and unfocused;
  Reading rendering, cold application startup, disclosure/food actions and
  active workout interactions are outside this smoke test.
- The separate final documentation build passes TypeScript and production
  bundling after the last source/README edit. Test deployment reports unchanged;
  all four validated hashes and the settings hash remain identical, so another
  reload is unnecessary.

Operation counts establish work removed from the sweep. Modeled tests do not
measure browser layout timing, physical gestures or input-to-paint latency.
Installed hidden-host diagnostics cannot establish foreground mobile or
Windows responsiveness or prove every navigation stall shares this cause.
Production installation and physical-device acceptance remain separate.
