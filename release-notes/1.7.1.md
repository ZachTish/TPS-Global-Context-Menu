# TPS Global Context Menu 1.7.1

This patch release fixes TPS Table task actions that could not resolve a task when the context menu originated from a non-title property cell.

## User-visible changes

- Right-clicking a TPS Table task’s Status, Area, Project, Priority, Scheduled, Owner, or another property cell now opens the shared task menu for that row.
- Clicking the Title cell continues to open the exact task editor.
- Property values such as `working`, `work`, or `high` no longer replace the task title during source-line resolution.

## Resolution and safety

- TPS Table stamps each task row with the source path, one-based task line, canonical task title, and a compact fingerprint of the exact source line.
- A unique source-line fingerprint relocates safely when preceding lines shift.
- If the exact line changed, the resolver uses canonical-title fallback only when the title is unique. Duplicate or identical task rows fail closed instead of targeting an uncertain sibling.
- Title-less tasks resolve through their exact source-line fingerprint.
- Source-line fingerprints normalize LF and CRLF endings. Plugin-owned `data-task-line` metadata remains one-based; native rendered `data-line` metadata remains zero-based.
- TPS List, Kanban, Calendar, Markdown reading, and editor task resolution retain their existing descendant-text behavior.

## Compatibility and migration

- Minimum supported Obsidian version: 1.10.0. Desktop and mobile are supported.
- Existing settings and notes require no migration.
- GitHub Actions standalone builds remain unavailable because this contained layout imports the adjacent shared deployment helper.

## Validation

- All 319 declared tests passed, including focused source-line resolution, TPS Table, TPS List, task-menu routing/action, settings, Home, scheduled-format, and time-tracking coverage. The regression suite covers non-title property cells, exact one-based task lines, shifted unique tasks, duplicate-title and identical-line ambiguity, title-less tasks, blank native tasks, and LF/CRLF parity.
- TypeScript and the required separate production-mode build/deploy passed.
- Obsidian 1.12.7 was reloaded with **Reload app without saving** in the isolated test vault. Right-clicking both Status and Project on `Fix GCM filter cache` opened that task’s shared menu, and clicking Title opened the exact editor at `Examples/TPS Base Filter Lab/Data/Tasks/Work/Plugins/Tasks.md · line 14`.
- The editor and menus were closed without saving. SHA-256 checks confirmed the three example task notes and runtime `data.json` remained byte-identical. Production was not directly changed.
