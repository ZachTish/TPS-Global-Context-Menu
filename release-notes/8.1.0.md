# TPS Global Context Menu 8.1.0

GCM avoids eager retired-history startup work, prepares classification once per cooperative slice, and restores timers from one metadata inventory plus candidate/unknown sources. Later recovery reuses the existing session map and reads affected paths. Incomplete or malformed source evidence preserves known timers and blocks start, manual-session, stop, pause, edit and delete actions. The native Start command passes read-only input to the existing preparation owner.

The native API remains **version 6** with three additive capabilities:

- `indexedSnapshot`: synchronous indexed records and readiness, with no fresh source scan, authority token, identity reservation or mutation permission. Not-ready consumers retain their prior projection; authoritative `snapshot()` is unchanged. Metadata resolution never clears source-authority dirty state.
- `updateFromSource`: synchronous declared-field computation inside the existing protected current-source atomic writer. Canonical title and business fields can be updated together; undeclared/identity fields, async callbacks, stale configurations and conflicts fail closed. Unchanged/null results preserve source bytes and timestamps. Configured automation exclusions are rechecked at current source.
- `identityApplyCancellation`: an optional current-owner predicate fences later batch entries and atomic steps while returning the committed prefix. Existing three-argument calls remain compatible; no rollback or retry is added.

Unconsumed menu refresh work is rejected before scheduling. Deferred startup and tracker persistence cannot restart detached work; unload does not write an empty recurrence tracker. Existing startup/manual recurrence recovery remains with GCM, and unchanged calendar batches still perform no recurrence recovery.

This is a minor release relative to 8.0.0 because its API additions are backward compatible. **8.1.0 adds no new property or settings migration.** Upgrading from 7.3.12 or another pre-8.0 release also includes 8.0 removal of automatic editor-mode enforcement and its four settings keys (`enableViewModeSwitching`, `viewModeFrontmatterKey`, `viewModeIgnoredFolders`, `viewModeRules`). Note properties remain intact and manual editor controls remain available. No universal scheduler, persistent cache, repair loop or new polling is introduced. Minimum Obsidian remains **1.10.0**. Update GCM before Health 4.3.2; Controller 3.1.8 uses the indexed projection and batch-cancellation capabilities when available.

- A 4,049-note bootstrap with eight stored sessions and one mid-scan edit performs one inventory and nine cached source reads. Repeated queries and unchanged metadata bursts add no reads/inventories. Changed, missing or malformed evidence cannot authorize a mutation from stale metadata.
