# TPS Global Context Menu 3.1.4

Reduce unnecessary work during vault discovery and native-record indexing. This patch targets the cost of loading/indexing, without changing any reload schedule.

- Obsidian emits create events for existing files during vault startup. GCM now indexes those files without rereading their bodies as possible new Base task drafts or allocating a draft timer for each discovered file. Metadata arriving later cannot retroactively adopt those existing files.
- Real task drafts created after workspace readiness retain their existing adoption behavior, including after a plugin reload.
- Native-record inspection and index updates reuse prepared property mappings. Value-based invalidation tracks settings, nested aliases, kind-specific keys and migration-mode changes. Every inspection still evaluates current frontmatter and conflicting identity evidence; returned profiles are independent copies.
- Optional structured diagnostics report index counts and synchronous rebuild duration without note content.

## Compatibility and limits

Backward-compatible **patch release**, minimum Obsidian **1.10.0**. No new setting, default, note migration or API-version change. GCM consumers use the existing API; no Health or Navigator release is required for this change. Reload scheduling is unchanged.

This removes one source of startup work and reduces mapping preparation. Initial authoritative source verification, other plugins' indexing, timer-session scans and UI rendering still contribute latency. Desktop component benchmarks below are samples, not end-to-end reload measurements or an iPhone latency guarantee. Production installation and mobile acceptance remain user-controlled.

## Validation and measurements

- Focused native-record suite: **89 passed**. Includes 1,000 startup discovery events with zero draft reads/timers; existing-record indexing; delayed metadata after readiness; real new drafts; 1,000 inspections plus 1,000 index updates sharing preparation; current frontmatter, returned-profile independence, nested settings changes and migration transitions. Existing duplicate/conflict and source-preservation coverage passed.
- `npm run prepretest`: **139 passed**.
- `npm test`: **1,214 passed**, zero failures/skips, including TypeScript and build.
- Mandatory separate final `npm run build`: passed; byte-identical final republish to **Obsidian Plugin Test Vault**. Explicit GCM reload loaded **3.1.4**. Runtime artifacts matched the tested source artifacts; persisted GCM settings remained unchanged.
- Same **8,794 metadata inputs**, **2,558 recognized records**: 3.1.3 classification timings **681.7 / 610.9 / 598.0 ms**; prepared inspection profile timings **635.7 / 571.3 / 542.0 ms**. Median improvement **6.5%**, with identical serialized output hashes. This comparison measures classification, not draft adoption or the complete index/reload.
- Extending preparation reuse from the inspection method to the index builder: intermediate candidate index timings **1,732.7 / 1,579.6 / 1,558.8 ms**; final candidate **1,443.6 / 1,425.0 / 1,424.2 ms**. Median improvement **9.8% versus the intermediate candidate**, not versus 3.1.3. Both had **2,558 indexed records** and **1,197 blocked identity-evidence paths**; record/identity/conflict ownership hashes were identical. No conflict was silently accepted to obtain the speedup.
- An installed post-reload task draft created in Inbox was adopted with its ID, title and canonical path. Temporary destination restored; the fixture moved directly to `_archive`; temporary measurement globals removed. No outbound automation was enabled and no production artifacts/settings/notes were changed.

Tested in the test vault and ready for the user's **BRAT pull** of exact numeric tag **3.1.4**. Publishing does not install it in production or constitute user acceptance.
