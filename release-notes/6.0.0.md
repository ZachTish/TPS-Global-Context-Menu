# TPS Global Context Menu 6.0.0 — Obsidian Page Preview and native note opening

The shared **After creating a note** choice offers **Obsidian Page Preview**, **Open note**, and **Stay in current view**. Preview requests Obsidian's core `hover-link` Page Preview from a connected caller anchor on desktop; Obsidian 1.7 and later allow editing inside that core preview. Open uses the native Markdown editor in Editing mode, including when the destination leaf was previously in Reading mode. Stay leaves the current view alone. Mobile Preview and requests without a usable anchor fall back to Open. The current/new-tab destination applies to Open and that fallback. Saved `preview` remains `preview`, including Calendar's one-time preference import, and the default remains Preview. Creation still waits for its initial template and task preparation before presentation. A failed native open reports a Notice while acknowledging the created file, so a caller cannot accidentally create it again. [Obsidian's desktop 1.7.4 changelog](https://obsidian.md/changelog/2024-10-16-desktop-v1.7.4/) confirms core Page Preview editing.

GCM no longer ships its custom editable hover card, body writer, mobile card styling, or the third-party Hover Editor popover integration. **Force previews for Base links** remains: on supported Calendar, Kanban, TPS List, and TPS Table note links, the first plain click requests core Page Preview and a second click opens the note. With the setting off, clicks use native navigation. GCM's linked-context **Show hover preview** also requests the core Page Preview.

The public `ui` capability advances to **v2**. `presentCreatedNote` remains the post-create handoff and accepts optional connected `anchorEl` and real `event` for Preview; `getNoteOpeningSettings` reports all three choices and `shouldForceBaseLinkPreview()` reports the saved setting. The legacy `openEditableNotePreview` method remains only as a validated compatibility shim: it requests core Page Preview with native Open fallback and never creates a custom card or focuses a preview editor programmatically. Integrations should use `presentCreatedNote` for new notes and gate on UI v2. The removed custom editor contract makes this a major release. Note content and existing settings keys are preserved. Minimum supported Obsidian remains **1.10.0**. Physical-iPhone acceptance remains separate.

Core Page Preview must be enabled for Preview to appear. The public `hover-link` event does not report whether a popover opened, so GCM cannot detect a disabled Page Preview plugin and automatically switch that request to Open. Mobile Preview and requests without a usable connected anchor do use native Open. Core Page Preview does not expose GCM's former programmatic title/editor focus behavior.

## Validation

- Focused native-opening, legacy-API, settings-normalization, Base-click, and no-custom-card regressions pass.
- Full declared `npm test`: **1,476 passed, 0 failed**. A separate `TPS_NO_DEPLOY=1 npm run build` passed TypeScript/esbuild, followed by the normal `npm run build` deploying the versioned `main.js` to Obsidian Plugin Test Vault. Hot Reload applied the updated GCM settings and API.
- In the foreground Test vault, GCM settings showed Page Preview/Open/Stay and the saved Preview choice was restored after the earlier candidate had normalized it to Open. A real TPS Navigator toolbar click created `Inbox/Untitled 1.md` and showed Obsidian's core Page Preview. Clicking its body activated an editable text area; typing persisted in that exact new file while the previously open note stayed unchanged. Switching temporarily to Open and creating another note from a Reading-mode leaf opened `Untitled 2` in native Editing mode. Calendar Base 1.0.1 candidate QA also showed core Page Preview for a newly created event; with forced Base previews off, a plain event-link click navigated normally to its Markdown Editing tab. GCM's original Preview/current-tab/force-Base-off preferences were restored; all four synthetic GCM QA notes were moved directly from `Inbox` to `_archive`. No production vault was accessed. The enabled forced Base-click path is covered by source tests; physical iPhone and a disabled core Page Preview plugin were not tested in UI.
