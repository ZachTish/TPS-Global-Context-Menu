# TPS Global Context Menu 4.0.6

Deleted-file relationship cleanup now rejects unrelated parent/attachment values before entering the file writer. It also uses cached Markdown inspection for exclusions and body preflight, while real mutations still recompute against current content inside their existing atomic writers.

- Avoids no-op writer attempts for unrelated, ambiguous and differently resolved links.
- Reuses the cached source inspection unless cleanup itself changed frontmatter.
- Rechecks current path exclusions, tag exclusions and contents at both mutation boundaries, preserving concurrent user edits.
- Keeps the existing cleanup scope, parser, ambiguity rules, companion handling and serialized deletion queue.
- Adds no cache, watcher, timer, retry, repair mechanism, setting, schema or public API.

Backward-compatible patch. Minimum Obsidian: **1.10.0**.

Validation: eight added regressions cover a 1,000-note unrelated vault, 20 unchanged requests, current frontmatter/body edits, changing exclusions, ambiguous links, path exclusions and an existing malformed-checkbox link form absent from core metadata. Four new regressions fail before correction. The harness now models both actual raw and cached read APIs; the older read-count assertion and exclusion source checks were updated for cached inspection plus authoritative mutation boundaries. All **73 focused, 1,406 declared and 209 supplemental checks** pass with zero failures/skips; TypeScript and the separate normal Test build/deploy pass.

Installed unreferenced deletions, with all consumers enabled: **six frontmatter writer attempts → zero**, **142 raw reads → 136**, no note mutations or removed references, and the legacy companion index remains dormant. The existing 11,216-note candidate/body discovery remains. Full cleanup is awaited before recording results and restoring probes.

A separate installed deletion removes three references from two fixture notes, including a legacy link verified absent from core metadata. It preserves the remaining parent, alias, marker, surrounding text and unrelated attachment/note bytes, and enters only the matching frontmatter writer. Seven settings files remain unchanged. Fixtures are archived/trashed, hooks removed and the deletion queue fully settled. Named GCM reload and final artifact/settings verification pass.

Limits: after samples were hidden/unfocused; before samples were visible/unfocused. Cleanup timings of 868–940 ms before and 799–1,058 ms after do not establish a latency improvement or native parity. The substantial remaining cost is the current automatic whole-vault relationship cleanup, not the eliminated writer attempts. Core link metadata alone cannot replace its body inspection without losing the supported unindexed link form. Foreground gestures, physical iPhone and cold-process startup remain unverified. No production installation or user/device acceptance is implied.

Tested in Obsidian Plugin Test Vault; ready for the user’s BRAT pull once published. Production remains untouched.
