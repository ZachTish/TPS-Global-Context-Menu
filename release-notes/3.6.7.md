# TPS Global Context Menu 3.6.7

Backward-compatible patch: remove repeated classification work inside one record inspection. Minimum Obsidian remains **1.10.0**.

## Behavior

- Reuse the result for each prepared storage-profile object during one synchronous inspection of one frontmatter object, including null results. Identity evidence, readable-profile checks and the current-profile check retain their existing order and rules.
- Keep results local to the invocation. Later calls reread mutable input and current settings; standalone mutation checks use a fresh lookup for each source, candidate or persisted value.
- Preserve custom kind/title keys, arbitrary nested tags, property pairs, migration-only readers, conflicting evidence, duplicate case-insensitive keys, canonical calendar identity and timestamp/title conflict handling. Equivalent but distinct profiles remain separate.
- Keep timestamp fallback on the existing copied envelope and return detached profiles. No change to Health classification, indexing ownership, saved data, settings, defaults or shared API version.

The previous property-evidence result map now serves the whole synchronous inspection instead of just one validation helper. There is no retained record cache, new watcher, timer, background task, migration or repair behavior.

## Validation

- Four new operation-count regressions failed against 3.6.6 before correction; all six new regressions and the complete **115-check native-record suite** pass afterward.
- A 1,000-note no-match burst requires exactly 3,000 profile evaluations rather than 14,000. With seven nested-tag mappings, each unrelated note requires ten rather than 49 evaluations.
- A valid default native record requires four rather than 21 profile evaluations and two rather than 18 envelope copies. Seven mapped kinds require 15 rather than 83 evaluations and two rather than 17 copies. Property-pair food classification requires three rather than 23 evaluations/copies.
- Tests retain current custom kind/title storage, legacy custom identity/schema migration readers, duplicate profile objects, conflict rejection, timestamp fallback isolation, frontmatter edits, nested settings edits, separate source objects and returned-value mutation.
- The final versioned **1,293 declared and 193 supplemental checks** passed with zero failures/skips under bundled Node **24.19.0** and npm **10.9.2**. TypeScript and the mandatory separate normal build passed and deployed only to Obsidian Plugin Test Vault. A named disable/load-manifest/enable reload confirmed 3.6.7 with unchanged settings. Final documentation rebuilds must preserve the tested artifact hashes below.

These are operation counts for the actual classifier compiled into the test harness. They are not production, physical iPhone, cold-process startup or end-to-end performance guarantees. No production access or deployment. Public release and the user's BRAT pull remain separate from local candidate validation.

## Installed test-vault acceptance

A foreground warm-renderer timing capture recorded the full Health index rebuild at **149 ms**, versus **397 ms** with GCM 3.6.6 (about 62% shorter for that synchronous pass). The first visible synthetic body on two frames remained **2,870 ms**, versus **2,853 ms**. This does not establish an end-to-end startup improvement or native-performance parity. Both runs retained the Electron process/storage caches; neither was a cold process launch.

A separate instrumented count run exposed an existing Health lifecycle duplication: it performed two full rebuilds (151.9 and 133.9 ms) when metadata/layout events arrived in a different order. Consequently it used ten Markdown enumerations, 498 raw reads and 254 cached reads versus nine, 413 and 170 in the preceding run. The extra rebuild and its 85-source hydration remain a separate ownership issue; this release reduces each inspection's work and does not claim to eliminate every startup pass. No startup readiness scan storm returned, metadata resolved normally, and both capture harnesses reported no errors.

The installed classifier also passed nine synthetic, in-memory checks using the vault's current configured profiles: task, food-entry, food, recipe, workout-session, workout-exercise, activity-entry, calendar-event and a custom kind. Each retained identity and classification, ignored caller mutation of its previous result, and immediately reflected changed input on the next call. These checks did not write notes.

Original note state and all temporary profiling hooks were restored. The startup fixture was archived directly from Inbox, and the seven measured plugin settings files remained unchanged. The foreground guard rejected a separate title-API timing sample before its first edit, so that cancelled sample supplies no naming-latency evidence. The earlier 3.6.6 actual Navigator creation/title/body flow remains the functional UI coverage; this release changes its shared classifier, not that UI route.

Tested in the isolated test vault and ready for the user's BRAT pull after public publication. Production is untouched; physical device acceptance and the broader 90%-of-native goal remain outstanding.
