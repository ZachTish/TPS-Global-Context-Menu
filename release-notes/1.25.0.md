# TPS Global Context Menu 1.25.0

TPS Global Context Menu `1.25.0` makes Task API v2 the canonical task-block move transaction for GCM menus, drag-and-drop, and cross-plugin consumers. Daily Note moves can now preserve a migrated scratchpad record through an explicit policy instead of every consumer maintaining its own copy/remove behavior.

## Changes

- Add Task API v2 move controls for `sourcePolicy` and `resolution`. Existing callers keep v1-compatible remove-source behavior unless they explicitly request `migrate-if-daily-note`.
- With `migrate-if-daily-note`, write the authoritative full task block to the destination and retain the Daily Note source as `[>]` with `[migratedTo:: [[Target]]]`, stripping conflicting TPS identities from the scratchpad copy.
- Route GCM's own context-menu and drag moves through the same public transaction used by Controller.
- Revalidate the complete nested source block after the destination write, roll back safely when the source changes, and report partial commits explicitly when a guarded rollback cannot be completed.
- Add strict `exact-or-identity` matching for consumers that must not fall through to a fuzzy title match.
- Resolve Daily Note ownership across enabled Core Daily Notes, Periodic Notes, and persisted Core configuration, including the disabled-Core-wrapper startup case.
- Publish `tasksVersion` in the `tps:gcm-api-changed` lifecycle payload.

## Compatibility and migration

- `plugin.api.tasks.version` is `2`. Task API v1 call shapes remain accepted, and the default source policy remains destructive removal for compatibility.
- Consumers that need Daily Note migration semantics must require Task API v2 and send `sourcePolicy: "migrate-if-daily-note"` explicitly.
- Existing settings and note data require no migration. Existing moved-task records are not rewritten.
- Minimum supported Obsidian version remains `1.10.0`.
