# TPS Global Context Menu 1.7.0

This minor release adds one shared, explicit fallback write-note policy for TPS List and TPS Table line creation when the effective Base filters do not specify a destination.

## User-visible changes

- **Workflows → Tasks → When a Base has no write target** offers three choices: require an exact filter target, use today’s canonical Daily Note, or use one configured existing Markdown note.
- The safe default remains **Require a file.path/task.path filter**, so existing installations keep their prior fail-closed behavior.
- The policy applies to the currently writable synthesized task and bullet `+ New` routes in TPS List and TPS Table.
- Changing the policy or selecting a note saves immediately and preserves the Tasks settings route, scroll position, and keyboard focus.
- TPS List and TPS Table clear stale renderer ownership when Obsidian reuses a Base container. Native `+ New` accepts only the currently visible custom-view root, so switching views cannot route Table creation through a hidden List or fall through to native note creation.

## Resolution and safety

- Creation precedence is command override, then the effective active-view/whole-Base `file.path` or `task.path` target, then the configured fallback.
- An explicit but invalid, unresolved, missing, conflicting, or non-Markdown filter target blocks creation and never redirects into the fallback.
- `note.path`, `task.file.path`, and bare metadata fields do not claim the write destination.
- TPS List waits for the current persisted Base definition before resolving the fallback; TPS List and TPS Table both block creation when the relevant Base definition cannot be read.
- Today’s Daily Note uses GCM’s canonical Daily Note service at click time. TPS Table does not resolve or create it until after the user submits the title, so Cancel is mutation-free.
- A configured specific note must already exist and remain a Markdown file when creation runs.

## Compatibility and migration

- Minimum supported Obsidian version: 1.10.0. Desktop and mobile are supported.
- Existing settings and notes require no migration. Two additive settings are introduced with filter-required defaults.
- Heading rows remain display-only because a general heading filter does not yet define a safe heading level or insertion location. Existing rows continue to edit their own containing note.
- GitHub Actions standalone builds remain unavailable because this contained layout imports the adjacent shared deployment helper.

## Validation

- All 318 declared tests passed, including focused write-target, TPS List, TPS Table, native-create ownership, filter, settings, Home, scheduled-format, and time-tracking coverage. The suite covers precedence, conflicting and unresolved targets, Daily Note cancellation, persisted-filter races/read failures, immediate settings persistence, visible-root routing, and stale renderer cleanup. TypeScript and the required separate production-mode build/deploy also passed.
- Obsidian 1.12.7 was reloaded with **Reload app without saving** in the isolated test vault. UI validation wrote a task to the configured specific note, wrote a TPS Table bullet to today’s Daily Note, and wrote an explicitly targeted TPS List task only to its `task.path` note. Canceling Table creation did not create the absent Daily Note.
- The fallback was restored to **Require a file.path/task.path filter** after close/reopen/reload, with no configured fallback path retained. Disposable QA notes and Bases were moved directly from `Inbox` to `_archive`. Runtime state was not included in the release, and production was not directly changed.
