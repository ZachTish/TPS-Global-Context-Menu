# TPS Global Context Menu 4.0.11 — Avoid duplicate child-navigation checks

Opening a note with the parent/child navigation enabled can scan the vault to decide whether to show a Children button and count. The candidate enumeration and the following parent check both applied the same ignore rules, causing redundant metadata lookups for every unrelated note. The persistent navigation now lets the existing parent check apply those rules once, matching GCM's context-menu path. Children visibility/counts, ignored relationships, companions and parent links retain their behavior. There is no setting, cache, watcher, note rewrite, or migration.

This is a backward-compatible **patch**. Minimum Obsidian remains **1.10.0**. Tested in **Obsidian Plugin Test Vault** and ready for the user's BRAT pull; production has not been modified.

## Validation

- The focused real-resolver regression passes for 120 unrelated notes, a visible child, an ignored child, and an ignored parent. The declared `npm test` workflow passed 1,439 checks with zero failures, including its TypeScript/build stage. A separate final `npm run build` deployed the tested plugin to the Test vault.
- On the same installed Test-vault note with zero children, the direct child lookup made **70,372** `metadataCache.getFileCache` calls before and **35,191** after the fix. Instrumented synchronous time was **161.9 ms** before and **136.2 ms** after. DevTools was focused for both direct-method samples; these timings are not foreground UI latency, physical-iPhone results, or native-Obsidian parity.
- A synthetic note with a linked child showed `1 Child` in the Test UI after a guarded GCM reload. The parent title/body and child source remained intact, both QA notes were moved directly from `Inbox` to `_archive`, and runtime `data.json` remained byte-identical.
- Child discovery still enumerates the vault when navigation needs a fresh count; this patch reduces duplicate checks within that pass.
