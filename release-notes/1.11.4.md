# TPS Global Context Menu 1.11.4

This patch restores one-click entity editing in TPS Table and protects entity-backed list and Status fields across TPS Table and TPS List.

## What changed

- Populated and empty entity-backed TPS Table cells open the combined searchable Manual/Vault/Entity picker directly.
- The intermediate menu introduced in 1.11.0 is no longer part of the Table entity-cell path.
- Entity-backed list selections merge through the list-aware mutation route instead of replacing the entire list as a scalar.
- TPS List resolves custom-property ownership before workflow Status routing, keeping an entity-backed bare `status` relation separate from `task.status` and `checkboxStatus`.

## Compatibility and migration

- This is a backward-compatible patch release.
- Existing custom-property settings and stored values remain compatible.
- No settings or note-data migration is required.
- Minimum supported Obsidian version: 1.10.0.

## Validation

- 61 focused entity/property/status regressions passed.
- The complete declared suite, TypeScript, and the required separate production-mode build passed.
- Obsidian 1.12.7 was reloaded in the isolated test vault.
- Populated and empty cells in the permanent relational TPS Table, plus a relational property in TPS List, opened the project-only searchable picker directly on the first click while the Base remained active. Every picker was canceled without changing the fixtures or runtime-owned settings.
- Production was not accessed. This release is ready for the user's BRAT pull.

## Known limitations

- Entity-backed list cells add or clear values from the combined picker. Removing one existing list member remains available through the configured context-menu list actions.
