# TPS Global Context Menu 1.13.1

## Intent

Restore the deterministic Task API contract used by TPS Notebook Navigator and other cross-plugin integrations.

## Changes

- Task API file and path inputs are canonicalized through GCM's own vault before list, get, update, create, move, delete, or focus operations use them.
- Markdown targets are recognized structurally instead of by JavaScript constructor identity, so valid file objects originating in another Obsidian/plugin realm work correctly.
- An omitted `pathPrefix` now performs no prefix filtering. Obsidian's normalized empty-path value can no longer remove every task result.
- Explicit missing, folder, and non-Markdown create or move targets fail closed instead of redirecting to today's Daily Note or the source note.

## Compatibility and migration

- Backward-compatible patch release; Task API version 1 and its call shapes are unchanged.
- No setting, note, or Base migration is required.
- Minimum supported Obsidian version remains 1.10.0.

## Validation

- The focused Task API suite passed 8/8 checks, including compiled fake-vault coverage for path strings, foreign file-like objects, uppercase Markdown extensions, omitted and explicit prefixes, exact resolution/focus, canonical writes, and invalid-target refusal.
- The complete declared test suite and mandatory separate production-mode build passed against the final versioned source and deployed the tested artifact only to **Obsidian Plugin Test Vault**.
- In reloaded Obsidian 1.12.7, `tasks.list` returned 2 open and 3 total rows from the synthetic task fixture through path, Obsidian-file, and plain file-like inputs. TPS Notebook Navigator rendered both open tasks beneath their exact note; title activation opened `Inbox/Synthetic Task Sink.md` at zero-based line 5, and the provider checkbox completed the task and removed it from the open-only list. The task was then reopened through the same API, restoring the fixture's original SHA-256 exactly.
- TPS Notebook Navigator's temporary task-row setting was restored to disabled, persisted across an app reload, and its dependent controls and rendered provider rows disappeared. Production was not accessed.

## Known limitations

- The Task API still requires an exact existing vault path. It does not fuzzy-match filenames or task titles, and ambiguous stale task references continue to fail closed.
- TPS Notebook Navigator task rows remain an optional consumer feature and stay file-only when GCM is unavailable or the integration is disabled.
