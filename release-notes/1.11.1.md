# TPS Global Context Menu 1.11.1

## What changed

- The global/native context-menu Archive action and the persistent GCM panel now delegate to one immediate archive service.
- Archive moves Markdown, Base, Canvas, and other Obsidian files during the click. It requires only the effective archive folder; a configured archive tag is no longer a prerequisite.
- Markdown retains best-effort archive tag and `archiveOriginalFolder` metadata. If that metadata write fails, the file still moves immediately.
- Base, Canvas, and other non-Markdown formats never enter a frontmatter API.
- Relative source folders remain intact beneath the effective archive root, destination collisions receive a numeric suffix, repeated selections are deduplicated, and already-archived files are not nested again.
- Non-Markdown Unarchive can infer the original folder from the preserved archive-relative path.
- Markdown Unarchive removes its restore metadata only after moving. A failed move leaves the archive tag and original-folder record intact; if cleanup is refused or fails, GCM rolls the note back into the archive for a safe retry.

## Compatibility and migration

- This is a backward-compatible patch release.
- No settings or note-data migration is required.
- TPS Controller's two-stage `sourceFolder` remains the highest-priority first-stage archive destination.
- Minimum supported Obsidian version: 1.10.0.

## Validation

- All 11 focused archive behavior tests and the shared-surface settings contracts passed.
- TypeScript and the complete declared test suite passed.
- The mandatory separate production-mode build passed and deployed the final artifact to the isolated test vault.
- Obsidian was reloaded in the Obsidian Plugin Test Vault and the immediate Base archive flow was verified without changing production.
- Production was not modified. This test-vault-validated release is ready for the user's BRAT pull from its matching numeric tag and public GitHub release.

## Known limitations

- Non-Markdown files cannot store archive metadata. Their original folder is recovered from the relative directory preserved beneath the archive root.
- When a destination already exists, Archive keeps both files by appending a numeric suffix to the newly archived filename.
