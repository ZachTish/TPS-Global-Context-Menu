# TPS Global Context Menu 3.6.8

Backward-compatible property/title edit ownership fix. Minimum Obsidian remains **1.10.0**. Tested in Obsidian Plugin Test Vault and ready for the user's BRAT pull. Production is not updated by this release.

## Changes

- The shared Markdown frontmatter writer emits one files-updated notification after its optional filename operation, with the current path. A committed write remains observable if a subsequent rename fails. Rejected writes and unchanged edits emit nothing.
- Bulk property edits and Edit Title stop repeating the writer's notification. Explicit-action source attribution and automation semantics are retained.
- Markdown menus keep their existing event refresh; the bulk service removes its additional delayed Markdown refresh. Attachment targets retain their local refresh and source/companion event. Edit Title retains its immediate local refresh.
- Custom text property rows rely on the writer for title-driven renames, honoring Auto-rename off and failed/unchanged writes. The dynamic menu already excludes title properties; its unreachable duplicate rename block is removed.

No migration, settings, public API change, retained deduplication state, watcher, retry or automatic repair is introduced.

## Validation

- Before correction, seven of nine new composed operation-count regressions failed against 3.6.7. All nine pass after correction. They execute the actual title prompt, bulk edit, frontmatter mutation and filename services, covering final-path ordering, Auto-rename off, twenty-file non-title bursts, no-op/failure behavior, committed writes followed by rename rejection, source/surface attribution, automation and delegated attachment refresh ownership.
- Custom-property route regressions reproduced seven duplicate/unrequested filename checks before correction; all 16 menu/row checks pass afterward. Tests preserve the menu's title exclusion and ordinary text behavior.
- Final versioned validation under Node 24.19.0/npm 10.9.2: **1,312 declared checks and 193 supplemental checks passed**, with zero failures/skips. The initial full run exposed an outdated unit fixture that omitted the shared writer's event; the fixture now models that existing owner, keeps its one-event assertion, and the full rerun passes. TypeScript and the production-mode build passed with `TPS_NO_DEPLOY=1`. The separate final normal build deployed the final version to the test vault; a named disable/load-manifest/enable reload verified 3.6.8. A final documentation-only build produced byte-identical runtime artifacts.

## Installed acceptance

- Actual foreground inline-title click, replacement and Save/Return: one modify and one rename before and after, matching title/filename and preserved body. Files-updated notifications fell from **three to one**, emitted after the rename using its final path. Explicit-action count remained one. Menu refreshes fell from three to two; the additional refresh at approximately 350 ms was absent. The retained title refresh and event refresh were both observed.
- The measured save was 99 ms on 3.6.7 and 103 ms on 3.6.8. No long tasks or out-of-scope note writes occurred during either sample. These individual samples demonstrate reduced duplicate notifications, not an end-to-end speedup. Existing delayed metadata naming checks remain and were observed.
- Actual Navigator 7.0.5 toolbar New note action opened the configured preview with its default title selected. An immediate replacement title and body edit persisted with one creation, one rename and two modifications. The default was already preview/current-tab; no default was changed.
- Seven involved plugin settings files stayed byte-identical. Temporary listeners/wrappers were removed, the prior active note and blank internal search restored, and all owned fixtures were moved directly from Inbox to `_archive`.
- An initial test setup was cancelled before any title edit when the renderer was hidden. A later setup similarly waited for a search animation frame while the native full-screen test window was focused but `document.visibilityState` reported hidden. Exiting full screen restored visible rendering; the successful title-save sample was focused and visible. No timing from the suspended setup is used as title-save evidence, and no plugin workaround was added for the unconfirmed window-visibility cause.

## Limits

This patch removes demonstrated redundant work; it does not establish general latency or native Obsidian performance parity. The measured 3.6.7 Edit Title sample had one modify and one rename but three files-updated emissions. Installed baseline used the test vault's existing user role with background automation disabled and Auto-rename/title synchronization enabled; that configuration is not a production or Controller-role guarantee. Metadata-triggered naming checks and the separate Markdown rename listener remain unchanged. Production and physical iPhone acceptance remain the user's responsibility; production installation is a separate BRAT pull.
