# TPS Global Context Menu 10.3.0 — Simpler Records and daily-note recognition

A daily note with a general Kind value, including `kind: [note, entity]`, could be rejected before GCM checked its date filename. GCM now recognizes those notes through the configured Core Daily notes folder and complete date format. No Kind property or tag is required. Configured non-Daily record types, known task/event/Health identities, conflicting dates, companion files, process records and current-source creation safeguards still apply. An arbitrary frontmatter title or date prefix does not replace the filename check.

**Properties → Records** now starts with the effective daily-note filename and a button opening its owning Core Daily notes or Periodic Notes settings. Record mappings are separate from Custom fields. Choose one type to see its property summary; open **Edit record properties** for matching, subtype, creation and migration controls. **Add type** reveals its form on request. Base new-note routes stay on Records. Labels use **Subtype**, **Save for new notes**, and **Update existing notes**.

This is an additive minor release. Existing settings keys, defaults, migration actions and APIs remain compatible. There is no automatic note migration, new persisted UI state, watcher, cache, poller, repair service or file-open maintenance. The default destination remains **Properties → Custom fields**. Existing responsive navigation and native controls are reused; keyboard focus returns after Add/Cancel, including when no record types are configured.
