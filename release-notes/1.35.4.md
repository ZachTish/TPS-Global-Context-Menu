# TPS Global Context Menu 1.35.4

## Intent

Make right-click batch editing work predictably for selected note rows in both TPS List and TPS Table.

## Changes

- TPS Table note rows now participate in persistent modifier selection and exact right-click batch menus.
- Note and task selection remain separate domains, preventing note rows from entering task-line property changes or cross-plugin task drags.
- TPS List and TPS Table send the exact selected note files to GCM's menu builder without consulting ambient editor or file-explorer selection.
- Multi-note menus expose configured property changes, list/tag addition and removal, archive/conversion actions, and a batch **Link to Parent** action.
- Single-file-only actions stay hidden from multi-note menus.

## Compatibility and migration

- Backward-compatible patch; minimum supported Obsidian remains 1.10.0.
- No setting, Base, note, property schema, or public API migration is required.
- Existing task-row multi-selection and Notebook Navigator task dragging retain their prior behavior.

## Validation

- The complete declared `npm test` suite passed, including executable TPS List, TPS Table selection-domain, exact-file menu, batch-parent, task-drag containment, and Notebook Navigator bridge coverage.
- `npx tsc --noEmit --skipLibCheck` and `git diff --check` passed.
- A separate final `npm run build` succeeded and deployed the final 1.35.4 runtime to the isolated test vault.
- Test-vault UI smoke testing loaded the final Base runtime and rendered the exact synthetic note fixtures. The executable interaction harness verified modifier-selected note batches in both TPS List and TPS Table because the desktop QA driver cannot synthesize a held Command-click chord.
- The temporary Base and note fixtures were removed after verification.
- Source and deployed runtime artifacts match byte-for-byte.

## Known limitations

- A selection intentionally contains either note rows or task rows in TPS Table, never both. Bullet and heading rows retain their existing single-row menus.
- Batch child creation/unlinking remains single-target because its meaning is ambiguous across multiple parents; batch linking selected items to one parent is supported.
