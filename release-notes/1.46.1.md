# TPS Global Context Menu 1.46.1

GCM tag chips now prefer TPS Notebook Navigator when both navigator plugins are installed. This fixes the co-installation path that previously opened the upstream Notebook Navigator even though TPS Notebook Navigator owns the requested tag workflow.

Tag Canvas retains its existing precedence. When it is unavailable, GCM tries `tps-notebook-navigator` first and falls back to `notebook-navigator` only if the TPS navigation API is missing, rejects, or reports that it could not select the tag. After a successful TPS route, GCM clears TPS Notebook Navigator's active Filter Search; a filter-clear failure is logged without switching the already-selected tag into another navigator. Terminal failure produces one availability notice.

This is a backward-compatible integration fix. It changes no setting, note, record, schema, command, or public GCM API contract and retains minimum Obsidian 1.10.0.
