# TPS Global Context Menu 1.40.0

This backward-compatible feature release makes GCM's custom-field catalog describe the real TPS record model and consolidates native task identity around `tpsId`.

## Changes

- Every custom field supports logical-kind inclusion and exclusion rules. Authored note `kind` values take precedence over the structural note row type, while task, bullet, and heading line menus receive their exact structural kind.
- **Install TPS task and Health fields** installs task workflow fields and imports the Health 0.22.0 catalog when available. The action is explicit and idempotent.
- Task fields are limited to `kind: task`. Health fields are limited to their food, activity, workout-session, workout-exercise, exercise, workout-plan, or Daily Note owners. Shared keys are merged rather than duplicated.
- Stacked Properties no longer depends on floating inline menus being enabled. The stack can run alone in Reading View and Live Preview; strict Source mode remains free of injected UI.
- New promoted task records no longer store a redundant `sourceTaskId`. **Native records: Consolidate task identities** removes a matching legacy alias and fails closed when it conflicts with the record's `tpsId`.
- The canonical recurrence field is `recurrenceRule`; running the catalog installer migrates the old built-in `recurrence` field definition without rewriting note data.

## Compatibility and known limitations

- Existing custom-field settings and native records are not changed automatically. Run the install/refresh action and the optional identity command when ready.
- The identity command acts only on indexed native `kind: task` records. It does not alter inline task IDs, item-history entries, external provider IDs, or nested sub-item identities.
- TPS Health 0.22.0 or newer is required for the version-2 native Health field catalog. Older version-1 food/rollup catalogs remain import-compatible.
- Minimum Obsidian version: 1.10.0.
