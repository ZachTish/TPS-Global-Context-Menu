# TPS Global Context Menu 1.49.0

This release establishes the atomic TPS note contract and keeps generated Navigator presentation out of note properties.

- Public nativeRecords API v6 writes one fixed physical envelope: `tpsId`, `kind`, and `title`. Schema and file timestamps remain virtual compatibility values, while legacy property/tag profiles remain readable for explicit migration.
- `tpsId` uniqueness is global and case-insensitive across every recognized native kind. Every value under case-variant ID or legacy-tag keys reserves its identity; stale resolution refreshes from current Vault bytes, while current missing/ambiguous lookups avoid redundant rescans.
- Identity plans now bind create kind and re-identification source path/current ID as well as destination identity/path. Caller substitution between plan and apply fails before any note is changed.
- Timestamp synchronization and Navigator semantic title/tag automation recheck the current frontmatter inside their source-preserving mutation boundary. Valid or malformed TPS identity evidence blocks generic changes, preventing virtual timestamps from leaking back onto native notes during stale-cache races.
- Custom storage-key editors are retired from the primary settings surface. Consolidation remains explicit and preserves ordinary fields, meaningful tags, bodies, and paths.
- The new read-only Notebook Navigator presentation API v1 projects generated icon, color, and sort values without writing YAML. Navigator-rule mutations are limited to explicitly configured semantic tags and create-time ordinary-title repair.
- Generated visual seeding for new subitems is removed. Health's optional field import is compact by default and hides specialist fields from the context menu unless the user opts in.

Validation: focused native-record (68/68), timestamp/daily-note (61/61), source-preservation/no-YAML (17/17), presentation, rule, settings, Health-import, task, and subitem suites; the complete declared `npm test` workflow; TypeScript; and a mandatory separate production build. The first final build deployed the changed bundle to the isolated test runtime and the separate final build reported it byte-unchanged; prior integrated UI verification remains applicable to the unchanged settings/presentation surface. Minimum supported Obsidian: 1.10.0. Known limitation: legacy aliases remain readable until the explicit consolidation/vault migration is run; GCM does not rewrite notes merely because settings load.
