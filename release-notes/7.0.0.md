# TPS Global Context Menu 7.0.0 — Configurable list-valued kinds

**Rules & fields → Custom fields → Record classifications** now supports a configurable YAML-list property and nested value for each record type. Other supported writers remain a complete tag, a scalar property, and a parent/subkind property pair. Previous forms can be retained as explicit read aliases while notes are migrated. The editor can add or remove arbitrary record-type names and disable creation for an undecided type; removing a mapping requires confirmation and does not edit notes. Changing a writer does not automatically rewrite notes. The existing **Apply** action still previews and confirms a separate classification migration.

The Kind custom field can use a plain-text list editor; new defaults do so. Visibility scopes match exact values in a kind list. The new `frontmatterKinds` API v2 exposes effective definitions, read aliases, type-scoped matching and decoding, writer availability, and configured property keys to Finance, Health, and migration tools. Multiple internal types may share one visible path when a consumer already has a separate type signal; an ambiguous unhinted read preserves the authored list rather than guessing. Native record creation refuses disabled or unmapped writers before changing a note. No taxonomy paths are built into the writer, and no note repair or vault-wide scan runs automatically.

Create task no longer offers or writes an automatic Priority property. Existing priority properties and tag scopes are left for separately reviewed settings and note changes. This is a **major** release because the public kind codec advances to v2 and the default Kind editor changes from a scalar to a list. Minimum Obsidian remains **1.10.0**. Existing saved tag mappings remain readable until explicitly reconfigured; the TishOS v0.2 note/template/Base migration is a separate operation.
