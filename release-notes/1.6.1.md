# TPS Global Context Menu 1.6.1

This patch makes TPS List and TPS Table task visibility follow the effective Obsidian Base filters instead of imposing an open-task default.

## User-visible changes

- A whole-Base `kind == "task"` filter now includes every checkbox status, including completed and wont-do tasks.
- An active-view filter such as `status == "working"` narrows only that view. Switching to a sibling view without a status predicate immediately returns to all task statuses.
- TPS List and TPS Table expose checkbox-derived `status`/`checkboxStatus`, `open`/`isOpen`, and `done`/`isDone`/`completed`/`complete` query fields.
- Configured linked-subitem checkbox mappings and the shared status service remain authoritative for custom status aliases and done-state classification.
- View-specific filter caches no longer reuse a sibling view or allow an older asynchronous load to overwrite the currently selected view.
- TPS Table keeps synthesized query-only fields out of inferred default columns while still allowing explicitly configured status columns, grouping, and sorting.

## Compatibility and migration

- Minimum supported Obsidian version: 1.10.0. Desktop and mobile are supported.
- Existing Base definitions, settings, checkbox mappings, and stored task lines require no migration.
- Mixed note/task previews without a task-aware Base directive retain the existing legacy open-task preview behavior.
- GitHub Actions standalone builds remain unavailable because this contained layout imports the adjacent shared deployment helper.
