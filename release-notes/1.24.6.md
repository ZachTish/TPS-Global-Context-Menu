# TPS Global Context Menu 1.24.6

This patch fixes Calendar task status changes that were incorrectly rejected as stale on every attempt.

## Root cause and changes

- The shared task context menu updated its in-memory checkbox token to the newly selected destination before starting the atomic file write.
- The write guard then compared the source line's current token with that destination token. Every genuine transition therefore looked like an external edit and produced **That task changed before it could be updated**.
- Mapped and custom mapped status choices now pass an immutable snapshot of the pre-click token into the compare-and-swap guard while retaining the optimistic selected-menu feedback.
- Real concurrent edits, changed checkbox mappings, changed source tokens, ambiguous task identities, and invalid target mappings remain blocked.

## Compatibility and migration

- Minimum Obsidian version: 1.10.0.
- No settings, task syntax, public API, or note-schema migration is required.
- TPS Calendar Base does not require a companion release; it already uses GCM's supported task-menu capability.

## Validation

- Focused coverage reproduces the unchecked-to-complete optimistic-selection sequence and proves that the pre-click token, not the destination token, reaches the atomic guard.
- The complete declared suite, TypeScript check, mandatory separate production build, and focused optimistic-selection regression passed against the final versioned artifact.
- The active Obsidian window was verified as **Obsidian Plugin Test Vault**. GCM 1.24.6 deployed there and its `main.js`, `manifest.json`, and `styles.css` byte-match the release artifacts; runtime-owned `data.json` remained present. Computer Use could verify the active vault but could not focus Obsidian's Electron web content to drive a live Calendar menu click, so the exact transition is covered by the focused compare-and-swap regression rather than an automated UI mutation.
- Production was not inspected or modified.
