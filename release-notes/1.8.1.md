# TPS Global Context Menu 1.8.1

## What changed

- Mobile Base `+ New` controls mounted inside TPS List or TPS Table now remain owned by the active custom view, including compact icon-only plus buttons.
- Whole-Base and active-view filters continue to resolve additively. A production-shaped Shopping view now inherits `kind == task`, adds `task.tags.contains(shopping)`, and creates a matching checkbox task instead of falling through to Obsidian's native note creator.
- If mobile cannot recover the owning Base definition, line creation now fails closed rather than creating an unrelated note. Within a resolved Base, positive `task.*` runtime filters retain their unambiguous task intent without requiring a redundant kind predicate in that same filter root.
- With no filter write target and no saved fallback preference, TPS List and TPS Table now write to today's canonical Daily Note. Explicit **Require a filter** and **Specific note** selections remain authoritative, and invalid explicit targets never redirect to the fallback.
- Capture timestamps now live in the hidden `tps-inline-props` payload as `createdDate: YYYY-MM-DD HH:mm:ss`. Every contentful top-level line in one submission receives the same value, nested descendants receive no independent timestamp, and capture/TPS line editors hide and preserve the carrier.

## Compatibility and migration

- This is a backward-compatible patch release.
- Existing settings remain valid. Only an unset or invalid fallback mode adopts the new today-Daily-Note default; explicitly saved fallback modes are preserved.
- Existing visible time suffixes are not migrated because authored times cannot be distinguished safely.
- Minimum supported Obsidian version: 1.10.0.

## Validation

- All 354 declared tests passed, including production-shaped Shopping filter resolution, nested SVG/path mobile-plus activation, unrelated-plus rejection, unresolved-Base fail-closed behavior, fallback precedence, hidden metadata encoding/merge behavior, multi-line capture, nested descendants, and metadata-preserving editors.
- TypeScript and the required production-mode builds passed. The final separate build was byte-identical to the deployed 1.8.1 test artifact.
- Obsidian 1.12.7 loaded the final plugin in the isolated Obsidian Plugin Test Vault. The real **Capture: Today's Daily Note** command wrote two roots with the same hidden `createdDate`, left the nested child unstamped, and rendered all three lines without visible timestamps.
- Runtime-owned `data.json` retained SHA-256 `6f832cdce0a73ec7404c8a6f91f52cc8fb28b7199801fbec278d8d45ffae507d`. Synthetic QA files were moved directly to `_archive/GCM 1.8.1 QA`.
- Production was inspected read-only to confirm the Shopping Base shape and that both write-fallback setting keys were absent. No production note, setting, plugin artifact, or runtime file was changed.
- This release is ready for a BRAT pull.

## Known limitations

- Hidden `tps-inline-props` JSON is intentionally not exposed as an ordinary queryable Base property.
- Strict Source mode intentionally displays raw hidden carriers.
- Filters whose truth depends on unsupported runtime-only functions may still be unable to supply a deterministic creation default; creation fails closed when GCM cannot prove that the result will match.
