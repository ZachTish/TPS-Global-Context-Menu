# TPS Global Context Menu 3.6.3

Fix competing title/filename writers when naming a newly created note. This backward-compatible patch keeps minimum Obsidian **1.10.0**. No settings, schema or API migration.

## Changes

- Inline title rendering is now read-only. Rendering a cached title no longer queues a filename write that can undo the name just entered and trigger another round of downstream refreshes.
- The new-note preview displays and saves the semantic title through the same shared writer as Edit Title. Auto-rename controls ordinary filenames; native workflow filenames keep their existing protection. The preview has no separate filename writer.
- Pending body edits save before the title changes. Failed or rejected saves preserve input and keep the preview open. Rapid change/Enter/dismiss actions share the existing pending save; newer input saves once afterward.
- After its own successful title write, the preview advances its existing body revision only when the body still matches. This accommodates the shared writer's existing line-ending normalization while preserving external-edit conflict protection.

No new cache, watcher, retry, repair pass or automatic migration. Existing mismatched notes are not rewritten. Navigator's separate native filename Rename action and configured metadata-driven naming remain unchanged.

## Performance evidence and limits

These are foreground test-vault samples, not production or physical iPhone guarantees. No long tasks were observed in the before/after title captures. The ordinary Edit Title save remained approximately **237 ms before versus 239 ms after**; this patch does not demonstrate a general latency improvement for that dialog. Its filename-helper calls fell from three to two; the remaining debounced metadata path did not perform another rename.

The corrected preview save took approximately **247 ms**, now persisting both the title and the configured filename instead of making the former filename-only operation. A separate detailed title sample took 231 ms: approximately 123 ms awaited the authoritative source read for filename protection, 0.2 ms classified native identity, and 92 ms completed Obsidian's rename operation. Those overlapping diagnostic timings should not be added across all methods. Background automation remained disabled in the test vault. CPU profiling startup caused a timer delay without a corresponding long task; it is not treated as a UI freeze.

This fixes the reproduced conflicting writers and adds lifecycle regressions. It does not claim to resolve every remaining startup, rendering or production naming delay. Do not remove authoritative filename protection merely to hide its I/O cost.
