# TPS Global Context Menu 3.3.2

Opening a note on mobile/User devices bypassed GCM's existing background-automation authority check. It could append icon/color to one revision while the Controller independently appended the same fields to another. Obsidian's merge can retain both additions when the revisions also differ in timer metadata or body content, yielding duplicate-key YAML.

Automatic rule scheduling/execution now uses the existing Controller authority for file-open, create, rename, startup, metadata and integration-create paths. Execution rechecks the role after a queued delay. Read-only icon/color and virtual-sort projection remains available on mobile/User devices, and explicit Apply rules remains available everywhere. Controller automation owns persisted automatic updates. No additional settings, timers, retries, state or dependencies.

The automatic duplicate-repair helper and callback behavior introduced in 3.3.1 are removed. The shared frontmatter writer is identical to 3.3.0. Existing malformed notes remain untouched. The prevention change is two authority checks in the existing rule service; Health needs no runtime change.

## Validation

- 41 focused checks, all 1,232 full-suite checks and 160 additional checks passed; no failures or skips.
- Tests cover forced User/mobile creation/opening, all existing automatic reasons, authority changes after scheduling, Controller writes, explicit actions, read-only projection, and refusal to repair identical duplicates.
- Installed 3.3.1 reproduction, with repair disabled for the synthetic fixture: real User file-open and Controller create paths both wrote valid independent revisions. The installed Obsidian editor merged them into two icon/color pairs and invalid YAML.
- Installed 3.3.2 through the same sequence: User write returned false; Controller write returned true; merge retained one icon/color pair, valid YAML and local body edits. No repair was present or invoked.
- Installed User-role presentation returned `dumbbell` / `#dbab9f` without changing the file; automatic application returned false and explicit Apply returned true.
- Final TypeScript/build deployed only to Obsidian Plugin Test Vault; named plugin reload verified 3.3.2 and absence of the repair helper. All runtime files match the release artifacts byte-for-byte.
- Health/GCM settings stayed byte-identical. Synthetic fixtures were archived directly from Inbox to `_archive/QA-creation-cause-20260925`; failed-merge fixtures were restored to valid synthetic state after recording results. No production access, provider requests, timer activation or outbound automation.

This demonstrates the faulty competing-writer path and its prevention using the installed editor's real merge. Physical iPhone and Obsidian Sync transport were not exercised; the phone's exact installed build and original sync history remain unverified.

Patch release for corrected automatic-write ownership and removal of the unwanted recovery behavior. Minimum Obsidian 1.10.0. Tested in the test vault and ready for the user's BRAT pull; update GCM on participating devices, including iPhone. Publication is not production installation or user acceptance.
