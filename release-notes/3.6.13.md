# TPS Global Context Menu 3.6.13

Backward-compatible patch; minimum Obsidian **1.10.0**. Tested in Obsidian Plugin Test Vault; intended for the user's BRAT pull. Production installation and physical iPhone acceptance are separate.

## Changes

- Refresh the authored title when a title-driven filename rename completes. Core can replace the visible title with its sanitized filename after GCM has already handled fresh metadata; waiting for the periodic title pass caused delayed, changing text. The existing renderer now runs at the filename operation's completion for matching open views. No note-body rebuild, extra writer, timer, scan or retained cache is added.
- Restore ordinary filename-to-title synchronization on controller devices with **Auto-sync title from filename** enabled. The Markdown companion-bookkeeping branch previously returned before reaching the title writer. The committed rename now invokes that existing writer immediately, without activating unrelated delayed maintenance.
- Preserve title ownership: folder-only moves perform no title reads/writes; generated sanitized/date-prefixed filenames keep their authored titles; newer titles, settings, exclusions and source/path changes remain guarded at the atomic write boundary. Native records and Daily Notes retain their existing ownership. Existing alias behavior is preserved.

No setting/default/schema/public API changes or migration. User/mobile mode continues to suppress background filename-to-frontmatter synchronization; explicit GCM title editing works independently. This patch does not change global native-record identity verification or core backlink rewrites, and is not a claim that all performance issues are resolved.

## Validation

- 19 added regression cases, including actual rename-event dispatch, composed title→filename→display ownership, 100 unchanged/move calls, concurrent edits, disabled settings, exclusions/native ownership and repeated no-op renders. Seven cases reproduced the relevant failures before their corrections. Existing title renderer tests cover matching views, no disk writes/reads/timers, source mode, focused editing and unchanged DOM.
- Full declared suite: **1,344 passed**, zero failures/skips. Supplemental suite: **197 passed**, zero failures/skips. TypeScript and production-mode build passed using Node 24.19.0/npm 10.9.2. An existing source-shape assertion was updated to follow the renamed atomic-source variable; runtime alias-preservation regressions remain in place.
- The initial User-mode core Rename check is deliberately not a passing auto-sync test: its authority gate was false. It confirmed a fast ~41 ms core rename with old frontmatter still displayed, while the source regression establishes that controller-enabled rename dispatch was also incorrectly swallowed.
- Installed controller-path verification used real core Rename UI with a test-only authority override confined to the synchronous rename emission for synthetic Inbox files. All real device roles, async jobs, providers and settings stayed unchanged. A titled and a no-frontmatter note each made one title write; matching metadata arrived at 77/75 ms, without a later title reversal. This is a mocked authority boundary, not a real controller or production timing sample.
- The direct GCM title baseline used actual foreground UI without that override: one write/rename, writer 65 ms, authored title at 45 ms, filename-only text at 67 ms, authored title restored at 703 ms. Final completion-refresh verification is recorded below.

## Final installed result and artifacts

The final separate production build deployed only byte-changed runtime artifacts to Test. Named disable/loadManifest/enable loaded 3.6.13 with GCM data.json unchanged. Three foreground actual Edit Title saves retained punctuation throughout completion: title/filename/metadata agreed at **74/76/61 ms**, versus the 703 ms baseline reversal. Writers took 72/74/57 ms; each made exactly one modification and one filename rename, with no measured long tasks or outside-fixture note mutations. The shared sidebar was collapsed equally for the direct-title baseline and final samples, then restored. These are small instrumented warm desktop samples, not cold/mobile/production or native-parity guarantees.

Seven monitored plugin settings stayed byte-identical. Synthetic bodies were preserved, all probe hooks removed, previous leaf/sidebar restored and fixture folders moved directly to `_archive` with byte checks. The controller-boundary samples above preceded the final read-only completion-refresh addition; final-source regressions cover both branches. No real controller/provider automation was enabled.
