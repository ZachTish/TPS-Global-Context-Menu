# TPS Global Context Menu 1.3.2

This patch makes the `@@` inline-property autocomplete use the existing date picker for Scheduled and other configured datetime properties.

## User-visible changes

- Selecting **Scheduled** after typing `@@` immediately opens **Set Scheduled Date** instead of inserting `[scheduled:: ]` for manual typing.
- Saving updates `scheduled`, `timeEstimate`, and optional `allDay` inline fields without duplicating an existing value. Clear removes those fields.
- Other configured datetime properties open a date-only version of the picker; ordinary text and number properties keep the existing inline text insertion flow.
- The `@@` query is removed when the picker opens, so canceling does not leave a blank property behind.

## Reliability and compatibility

- The picker initializes from existing inline values on the selected line.
- Modal submission is guarded by the exact post-trigger-removal line revision. If the line changes while the picker is open, GCM refuses the write instead of overwriting concurrent edits.
- The shared inline-field updater supports checkbox tasks and ordinary/nested list lines while preserving their leading indentation.
- Minimum supported Obsidian version: 1.10.0.
- No settings or data migration is required.

## Validation

- Focused task-line and inline-property suite: 43/43.
- Complete declared release-snapshot suite: 267/267, including TypeScript and its build-only production bundle.
- A separate production-mode build deployed the exact isolated release snapshot to the test vault; all four source artifacts matched the runtime byte-for-byte.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**. On a disposable checkbox task, `@@sch` showed Scheduled, selecting it immediately opened **Set Scheduled Date** with All Day, Time Estimate, and End Time controls, and Save wrote `scheduled: 2026-07-21 09:30:00`, `timeEstimate: 45`, and `allDay: true` inline fields.
- A second picker invocation was canceled with Escape and left no `@@` trigger or empty property. A Priority control case retained the ordinary text insertion route and stored `[priority:: high]`.

## Known limitations

- UI validation is performed in the isolated macOS test app; mobile device confirmation remains separate.
