# TPS Global Context Menu 1.24.7

This patch stops ordinary task completions from being misrouted into recurring-task creation.

## Root cause and changes

- The shared completion follow-up validated the default recurrence checkbox mapping before determining whether the completed task was recurring.
- It also received the full note snapshot without the exact changed line, so a different recurring task elsewhere in the note could be selected as the recurrence target.
- Every checkbox completion route now passes its atomically resolved task-line index into the follow-up pipeline.
- Recurrence handling inspects that exact post-write task first and returns silently when it has no recurrence rule. Only then does it resolve and validate the new-instance mapping.
- The live write still re-resolves the same task and fails closed if its identity, recurrence metadata, checkbox mapping, or target becomes stale or ambiguous.

## Compatibility and migration

- Minimum Obsidian version: 1.10.0.
- No settings, task syntax, public API, or note-schema migration is required.
- TPS Calendar Base does not require a companion release; its Calendar status menu uses GCM's shared completion pipeline.

## Validation

- Focused completion, task API, and recurrence tests cover the false-notice sequence and exact task-line targeting.
- The complete declared suite, TypeScript check, and mandatory separate production build passed against the final versioned artifact.
- GCM 1.24.7 deployed to the isolated Obsidian Plugin Test Vault; release artifacts were verified against the deployed runtime while preserving runtime-owned state.
- Production was not inspected or modified.
