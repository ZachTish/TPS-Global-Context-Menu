# TPS Global Context Menu 1.11.10

This patch removes GCM's disabled Canvas-open monkeypatch from normal startup while preserving the complete saved opt-in guard.

## What changed

- When `enableCanvasOpenGuard` is false, GCM no longer replaces ten workspace methods or three `WorkspaceLeaf` prototype methods and no longer registers nine global drag-tracking listeners.
- The opt-in guard retains every existing recent-drag suppression route.
- Opt-in wrappers forward the original workspace receiver, arguments, and results after the drag window expires.
- Opt-in cleanup restores the exact captured workspace functions instead of bound substitutes and removes wrapper properties when the original method was inherited.
- Fallback leaf resolution calls captured originals directly and cannot recurse through GCM's own `getLeaf` wrapper when `getUnpinnedLeaf` is unavailable.
- Removed an unreachable native Base-open interception branch, two no-op helpers, two unused state fields, and an unregistered Canvas-click helper.

## Compatibility and migration

- This is a backward-compatible patch release.
- No command, setting key, public API, Canvas gesture, Base-preview workflow, note-data format, or stored value was removed or migrated.
- A saved `enableCanvasOpenGuard: true` value still enables the same thirteen suppression routes.
- Default and saved-false configurations now leave the relevant Obsidian host methods untouched.
- No settings or note-data migration is required.
- Minimum supported Obsidian version: 1.10.0.

## Measured effect

The compiled harness extracts the real install predicate, suppression predicate, and Canvas guard implementation from each source root.

- Exact 1.11.9 with the released false default: ten workspace replacements, three leaf-prototype replacements, and one guard check for every representative native dispatch.
- 1.11.10 with the same false default: zero workspace replacements, zero leaf-prototype replacements, zero global Canvas-guard listeners, and zero guard checks.
- Independent informational 14-million-call `getLeaf(false)` runs varied from roughly 5–16% lower dispatch-only time for the direct candidate path. This isolates synthetic dispatch overhead; the deterministic mutation, listener, and guard-check counts are the acceptance gates.

## Known limitations

- The saved opt-in Canvas guard still depends on wrapping Obsidian workspace and leaf methods because no complete public Canvas-drag/open suppression API is available.
- This release removes those unsupported mutations from the default path; it does not claim the opt-in compatibility layer is an official Obsidian extension point.
- If another plugin replaces one of the same host methods after the opt-in guard installs, GCM cleanup can still restore its earlier captured method over that later wrapper. This pre-existing compatibility risk is now confined to explicitly enabled guard configurations.
- The timing result is dispatch-only and is not a claim of a visible whole-application speedup.
