# TPS Global Context Menu 1.3.1

This patch keeps Notebook Navigator multi-selection and dragging native around Daily Notes, and stops the last-checkbox completion prompt from appearing on notes that do not have a status.

## User-visible changes

- Shift-range selection and the configured Cmd/Ctrl or Option/Alt multi-select gesture no longer let Daily Note Home replace the selection-only Markdown leaf.
- Starting a Notebook Navigator drag preserves the selected Daily Note as Markdown. A later unmodified click on that note clears the guard and opens its normal date-backed Home presentation.
- Resolving the final open checkbox offers the configured completion statuses only when the containing note already has a populated frontmatter `status`.

## Reliability and compatibility

- GCM observes capture-phase Navigator click/drag intent but never prevents or stops Notebook Navigator's events.
- Selection suppression is scoped to one exact workspace leaf and file path, persists across Home's periodic refresh, and clears when that leaf changes file or the note is later opened normally.
- Navigator quick actions, tags, properties, parent-folder reveal controls, right clicks, and middle clicks are ignored.
- Missing, null, empty, and whitespace-only note statuses do not prompt. Existing `complete` and `wont-do` statuses retain their no-prompt behavior.
- Minimum supported Obsidian version: 1.10.0.
- No settings or data migration is required.

## Validation

- Focused Notebook Navigator intent suite: 5/5.
- Focused task-menu/status routing suite: 5/5.
- Complete declared suite: 267/267, including TypeScript and its production-mode build/deploy.
- A separate final production-mode build passed after the documentation update and left the final test runtime current.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**. An ordinary Notebook Navigator click opened the requested Daily Note without a Controller-created tab; entering Reading View retained the normal date-backed Home route.
- Through GCM's real checkbox menu, a note with `status: todo` opened the configured completion-status chooser. The same action on a note without `status` opened no chooser and did not create the property.
- Both disposable QA notes were moved directly from `Inbox` to `_archive` after verification.
- Final source artifacts are byte-identical to the isolated test-vault runtime.

## Known limitations

- TPS Controller versions before 0.1.3 can still redirect a Navigator selection into a newly focused tab. GCM 1.3.1 prevents that selection-only Daily Note from becoming Home, while Controller 0.1.3 removes the remaining tab redirect.
- Modified-pointer behavior is covered by executable regression tests because the macOS Computer Use surface does not synthesize a modifier-held pointer click.
- UI validation is performed in the isolated macOS test app; mobile device confirmation remains separate.
