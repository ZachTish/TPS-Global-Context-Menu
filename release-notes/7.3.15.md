# TPS Global Context Menu 7.3.15

Backward-compatible patch for duplicate relationship metadata reads. Versioned
declared/supplemental gates, standalone TypeScript and installed TEST acceptance
pass. Production remains untouched; the public release is the user's BRAT
handoff, not a production installation.

## Change

The existing logical-frontmatter reader now provides one lazy, operation-local
metadata acquisition to the existing FileProperties companion classifier.
Ordinary relationship reindexing no longer runs an independent full classifier
first. Public one-argument companion classification remains current and
unchanged; managed paths and existing positive raw ownership still avoid reads.
Missing cache results use an explicit read flag, so they are not acquired again
within the same call. The next call acquires current metadata independently.

Legacy PDF/Canvas companions, case-insensitive moved markers, explicit owner
forgetting, ambiguous mappings, native Markdown asset properties and public
native-PDF cache-valued reads retain their existing contracts. Current-TFile
ownership, metadata/create/delete/rename behavior, ignore settings and
provisional resolution remain with their existing owners. No settings, public
API versions, note schema, writer, persistent cache/index, watcher, poller or
async seed is added. Minimum Obsidian remains **1.10.0**.

Seed telemetry counts actual cache acquisitions owned by Parent's local
reader. It is not a counter for every backend lookup performed by a legacy
companion reader or another service.

## Tests-first evidence

The unchanged published 7.3.14 source passes all 13 old Parent checks plus six
new semantic controls and fails six intended count/interface regressions:

- Ordinary reindex: three cache accesses rather than one.
- Public logical read: two accesses rather than one.
- Missing cache and forgotten companion ownership: three rather than one.
- 10,000 ordinary Markdown files: one inventory but 30,000 rather than 10,000
  metadata accesses.
- The optional supplied classifier reader is not yet consumed.

The corrected source passes all 25 Parent and 62 related FileProperties,
property-consumer and ignore-rule checks. The real classifier is composed with
the real Parent service. Actual catalog setup, resolution and rebuild owners
are guarded against unexpected requests. Source-body reads and mutations throw
at the modeled Vault boundary. Native service access also throws: Parent uses
stored native asset Markdown metadata, not an import/resolve API or an invented
native metadata overlay. Input object identity, fresh subsequent operations,
positive ownership, default public classification, PDF duplicate rejection and
current-file replacement are covered. Existing real legacy Canvas checks stay
intact.

## Installed TEST acceptance

The targeted warm reload pair verifies loaded 7.3.14 then 7.3.15 with all active
consumers enabled and the same 16,875 Markdown paths. Both samples retain
56,406 known files, four parents/five children and the same relationship digest,
2,733 GCM records and 182 Health records. All eight consumers' settings, saved
data and enabled state, the original workspace leaf and active-workout state
stay unchanged; instrumentation restores with no errors.

Application-wide metadata accesses fall from 84,708 to 50,913. Both samples
retain two Markdown inventories (one GCM, one Health), one GCM loaded-file
inventory, 37 cached/one raw source reads and zero source writes. The same
hidden, unfocused desktop host reports these one-shot descriptive timings:

- GCM reload return: 830.1 to 390.3 ms.
- GCM API readiness: 1,107.2 to 631.6 ms.
- Health readiness: 1,252.3 to 777.0 ms.
- Longest reload-phase Node heartbeat gap: 544.1 to 147.7 ms.

The standard 13-phase source Live Preview check passes six tab switches and
two remounts. Observed widgets include 24 food rows and 39 activity rows, with
zero phase/render errors, observed long tasks or note-mutation attempts. A
required Navigator-owned Markdown inventory occurs on first busy-combined
display; three normal adapter writes are scoped to workspace state, not notes.
All eight consumers' runtime artifacts/saved data and enabled state are
preserved. Three uniquely identified display fixtures are archived exactly;
the original leaf, GCM/Health settings and active-workout state are restored.

The final mandatory post-QA documentation build is verified separately before
publication. Byte-identical artifacts need no additional reload.

The seed remains synchronous and inventories all loaded files once. The measured
reload still has a 147.7 ms longest heartbeat gap; this patch does not attribute
or eliminate all remaining startup work. The samples do
not establish physical phone/Windows speed, foreground input-to-paint latency,
whole-process cold startup or overall UI performance. Reading-mode rendering,
provider actions, food/activity edits, expanded disclosures and active
workouts are not exercised by the Live Preview check. First display is warm
plugin use of a new note, not a cold application startup. Production remains
untouched; its installation is the user's BRAT pull.
