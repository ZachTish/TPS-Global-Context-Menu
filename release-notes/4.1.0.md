# TPS Global Context Menu 4.1.0 — Configurable record classification format

Record types already mapped in GCM can now switch between a complete tag and a `kind` plus subkind property/value in **Rules & fields → Custom fields → Record classifications**. The tag path and property pair are chosen in settings; GCM's existing `frontmatterKinds` contract continues to drive note creation, record recognition and consuming actions. Previously this screen could rename an existing tag but could not switch its storage format.

**Apply** uses the existing confirmed migration and recovery workflow. It previews exact matching frontmatter, rejects collisions (including case-variant property keys), stale notes, malformed matching YAML and concurrent configuration changes, and commits the new mapping only after the reviewed files are written. Encoding a future record rejects an occupied subkind field instead of overwriting it. IDs, note bodies and unrelated tags stay intact. TPS Finances 1.15.0 supplies exact-generated Base previews that join the same recovery batch. When Finances is enabled, GCM blocks Finance kind conversion until that preview API is available. Install Finance 1.15.0 before changing a Finance classification. Customized Bases, arbitrary custom rules and disabled consumers require manual review; legacy string-only record-key mappings are outside this selector. Nothing migrates on startup or note opening.

This is a backward-compatible **minor** release. Minimum Obsidian remains **1.10.0**. Tested in **Obsidian Plugin Test Vault** and ready for the user's BRAT pull; production was not modified.

## Validation

- Focused conversion tests cover tag→property, property→tag, tag rename, case-variant and future-field collisions, cancellation, stale previews, generated Base inclusion, older-Finance rejection, and recovery. The final supplemental suite passed **210/210** and the declared suite passed **1,446/1,446**, with no failures or skips. TypeScript and a separate final `npm run build` passed.
- The final build deployed GCM 4.1.0 to the Test vault. Finance 1.15.0's **Configure in GCM** button visibly opened GCM's Custom fields destination. The Test vault has no saved record-kind mappings, so its installed mode selector could not be exercised there; conversion and the settings source were checked by automated tests and build. No test-vault setting or note was converted during this UI check, and GCM `data.json` remained byte-identical.
- A narrow read-only check found **33 tag mappings** in TishOS v0.2, including Finance record kinds. No production setting, note or plugin artifact was changed. Actual conversion in that vault remains an explicit reviewed user action after BRAT installation. Physical-iPhone behavior remains unverified.
