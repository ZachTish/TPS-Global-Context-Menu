# TPS Global Context Menu 3.1.7

Reduce avoidable work during first-use native-record verification, including Health food saves. This patch does **not** claim to resolve the reported 30-second click-to-log delay: that exact delay was not reproduced, and the installed test did not show a material end-to-end first-save speedup.

- Run at most eight independent authoritative Vault reads concurrently instead of serializing the entire first scan. Subsequent saves retain the existing incremental source cache.
- Stop assigning new reads after a failure and drain in-flight work before another refresh starts. Unreadable files, malformed identity evidence, duplicate identities, uncertain reads and stale plans retain their safeguards.
- Skip conflict-map cleanup for ordinary or valid-record paths that never owned blocked identity evidence. Actual conflicting paths still clear their ownership without releasing other paths' conflicts.

## Compatibility and limits

Backward-compatible patch, minimum Obsidian **1.10.0**. No new setting, default, data migration or API-version change. Health remains **3.1.3**; no Health artifacts change.

First verification still reads every Markdown file. Disk/cloud-storage latency, parsing, other plugins and metadata activity can still delay it. Parallelism is bounded and does not bypass authoritative identity checks. Physical mobile testing and the user's installed versions remain unverified. A release being published does not prove the affected vault has installed it.

## Validation

- Focused native-record suite: **92 passed**, including simultaneous reads, the eight-read limit, failure draining, no record committed on failed verification, successful retry, edits during parallel reads, and cleanup limited to actual conflict owners.
- `npm run prepretest`: **151 passed**.
- `npm test`: **1,228 passed**, zero failures/skips, including TypeScript and build.
- Unchanged Health tray/modal regression suites: **39 passed**; cover the logging action, draft ownership, duplicate submission and partial failures.
- Mandatory separate final `npm run build`: passed and deployed only shipped artifacts to **Obsidian Plugin Test Vault**. Byte-identical final republish; explicit targeted disable/enable with refreshed manifest loaded **3.1.7**.
- Installed Health `logFood` was exercised with permanent-food persistence enabled and the complete test-vault source scan. Baseline GCM 3.1.6: **4,742 ms** first save (72 ms food lookup/creation; 4,630 ms identity verification; 8,821 reads), then **55 ms** for the next save. Final build: **4,824 ms** first save (288 ms food lookup/creation; 4,495 ms identity verification; 8,836 reads), then **56 ms** for the next save. Both final records stored the expected 100 calories for 50 g of a 100 g / 200 calorie food. These are separate noisy desktop samples, not evidence of improved end-to-end latency.
- Same-input conflict-cleanup component comparison on the final runtime, with the former unconditional traversal reinstated temporarily: before **1,316 / 1,213 / 1,186 ms**, after **1,203 / 1,195 / 1,164 ms**. Median improvement about **1.5%**. Serialized record and conflict-ownership hashes matched across all six runs. This is an indexing component comparison, not a food-button benchmark.
- A fresh installed tray-button QA attempt could not locate the test modal, so no click-to-close timing is claimed. The visible Obsidian window was another vault; UI interaction there was not attempted. The exact 30-second user report still requires device, food source and installed-version information.
- Temporary destinations/preferences were restored; synthetic notes were moved directly from Inbox to `_archive`. Existing pending tray and persisted Health/GCM settings were preserved byte-for-byte. Runtime wrappers and diagnostic globals were removed. No outbound provider requests or production mutations occurred.

Tested in the test vault and ready for the user's **BRAT pull** of exact numeric tag **3.1.7**. This is a bounded verification/cleanup improvement, not confirmation that the reported 30-second delay is fixed.
