# TPS Global Context Menu 1.35.0

TPS Global Context Menu 1.35.0 adds a narrow public Time Tracking contract for externally owned sessions that must not create a second notes workspace.

## Changes

- Added `startTimer(target, existingNotes, { notesMode: 'none', start })` for active sessions that reuse an external target and start time without generating Daily Note session notes.
- Added `stopTimerById(id, end)` so integrations stop one exact running session rather than another timer in the same file.
- Persisted no-workspace ownership through record normalization, pause, resume, status display, and target navigation.
- Opening the notes action for a no-workspace session opens the tracked target instead of lazily creating a workspace.

## Compatibility and migration

- Existing `startTimer` callers and workspace-backed sessions are unchanged.
- Existing records normalize to `notesMode: workspace`; the new field is optional and requires no settings or note migration.
- Minimum supported Obsidian version remains 1.10.0.

## Validation

- The complete declared suite passed with zero failures, including focused no-workspace, supplied-start, pause/resume, record-normalization, exact-stop, and unrelated-timer preservation regressions.
- A separate final production-mode build passed and deployed byte-identical `main.js` and `manifest.json` artifacts to the isolated test runtime; the unchanged complete `styles.css` remains the BRAT stylesheet.
- TPS Health Live Preview QA verified the consuming active-workout surface and its explicit group interactions. GCM time tracking was disabled in the test-vault settings during visual QA, so no real timer record or settings mutation was introduced; enabled-provider behavior is covered by the automated integration harness.
