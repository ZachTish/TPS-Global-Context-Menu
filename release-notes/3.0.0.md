# TPS Global Context Menu 3.0.0

Advanced now exposes one Record kind key. Apply previews and confirms frontmatter migration, then updates known matching mappings in enabled TPS plugins. Explicit record consolidation confirms before using historical identifiers. Duplicate-ID protection remains active. Shared migrations pause native writes and Controller calendar sync; active Health workouts must finish first. Recovery retains original notes and changed settings until success.

Major release: normal readers no longer accept previous integration or native-identity mappings. Existing settings routes, defaults, disclosures and commands remain. No migration runs automatically on upgrade; no fallback alias editor is added.

## Migration and compatibility

Enable/update TPS Global Context Menu 3.0.0 before applying shared Controller or Calendar key changes. Enable participating TPS plugins before a shared rename. Use the explicit reviewed migration to consolidate historical notes before relying on their old fields. Cancel preserves both mappings and notes. Conflicting destination properties and stale previews stop the change. Historical names are used only for explicit migration or identity protection, not ordinary data reads.

Changes cover Markdown frontmatter, including archives and templates. Bodies are preserved. Inline fields, Base formulas, per-view Base mappings and disabled plugins are not automatically rewritten. Health uses guarded rollback; GCM retains a temporary private recovery copy. Neither can make a vault-wide transaction atomic across a process crash or simultaneous edits on another device. Repair potentially relevant malformed frontmatter before migrating.

Minimum Obsidian: **1.10.0**. GCM and Health major versions intentionally remove legacy read compatibility.
