# TPS Global Context Menu 7.2.0 — Configurable native Base New routes

Choose a GCM record type for New in an exact native Base file and view. GCM creates the complete native record with the current classification and shared-path identity in one operation, then uses the existing preview/open/stay setting. Unrouted Base views keep Obsidian New. Invalid configured routes fail visibly before creation, so a core `Untitled` draft is not left behind when the record writer is unavailable.

Configure routes under **Rules & fields → Custom fields → Base new-note routes**. The saved `nativeBaseCreateRoutes` array contains `{basePath, viewName, recordKind}`. The record type is an internal mapping name; kind paths, tags, and identity values continue to come from **Record classifications**. Destination uses **Advanced → Atomic note root/layout**. Routed views cannot use a Base new-note template, and Base filter defaults do not become record properties automatically. No route is enabled by default; existing notes and Base files are unchanged. Other domains with owner-specific IDs or required fields need their own creation path.

This is a backward-compatible settings and creation feature; minimum Obsidian remains **1.10.0**. It was tested in the Obsidian Plugin Test Vault and is ready for the user's BRAT pull. Production and physical-iPhone behavior are not claimed.
