# TPS Global Context Menu 8.1.1

Clicking a note title now opens Obsidian's native file rename dialog. Obsidian owns the filename input, validation, cancellation and link updates; GCM propagates a committed filename change through its existing title-sync owner.

This is a backward-compatible patch. Minimum Obsidian remains **1.10.0**. Tested in **Obsidian Plugin Test Vault** on macOS with Obsidian **1.14.4**, and ready for the user's BRAT pull. It is not installed in production by this release workflow.

## Changes

- Replace the custom Title modal with the exact-file core rename prompt for inline titles, GCM menu title actions and the existing `rename-active-note-title` command. Its ID remains unchanged; it now renames the filename rather than directly editing a property.
- Remove the duplicate-prompt time gate and Backspace/Delete frontmatter mutation. Opening or canceling the core prompt does not write or refresh the note.
- Keep projected frontmatter titles for display. Pointer activation opens the dialog; keyboard focus restores the filename before Obsidian's inline editor receives focus, preventing a no-input blur from renaming the file to its displayed property.
- Cover existing and newly opened detached windows through the same component-owned DOM handlers and cross-window node checks.
- Propagate committed renames with the existing `autoSyncTitleFromFilename` setting in the User role and on mobile. Native records use their configured title key and existing atomic selected-source writer. Identity, conflict, template, Daily Note, exclusion, superseded-path and current-source safeguards remain.
- Skip internal record/import filename maintenance using its existing synchronous ownership guard. Folder-only moves do not become title changes.

No settings key, default, stored schema, migration, additional vault watcher, scheduler, retry or repair loop is introduced. Explicit property editing retains its current owner and optional filename synchronization.

## Validation

- **1,706** declared-suite checks and **322** supplemental checks pass, with no failures or skips. TypeScript and the mandatory separate ordinary production-mode build pass; deployment targets the test vault only.
- Focused regressions cover exact targets, no-I/O prompting/cancellation/focus, pointer and keyboard ordering, detached documents, configured title keys, role/mobile eligibility, internal workflow ownership, folder moves, same-path and changed-exclusion guards, authoritative conflicts and superseded edits.
- The native propagation source owner uses **one authoritative read and one atomic process**, with zero inventories or extra renames. **100 unchanged** propagations perform no I/O or writes. Source tests mock the host storage/core prompt boundaries.
- Targeted plugin reload verified **8.1.1** with Navigator **8.2.6** and all eight active TPS consumers enabled; background automation remained disabled. Actual inline-title Save and Navigator Rename Save each opened one native **Note title** dialog, committed one filename rename and one native-record title update, with no custom title action. Combined-consumer counts were respectively **4 raw / 9 cached / 4 inventories** and **4 raw / 8 cached / 2 inventories**, with one atomic process each. These include downstream consumers and are separate from owner-only regression counts.
- Actual title cancellation and detached-window cancellation each performed zero source reads, writes and inventories. Keyboard focus restored the filename; blur without typing preserved source and filename. Newly created ordinary `Untitled.md` renamed and propagated correctly; creation used the vault API, followed by actual native-dialog input.
- Note bodies survived, diagnostic hooks were removed, the original note/dashboard were restored and the two owned fixtures were archived byte-identically. All runtime settings remained byte-identical except Navigator's existing version acknowledgement. No outbound automation or production data was used.

## Limitations

The exact-file core prompt is an internal Obsidian method rather than a public TypeScript API. It is feature-detected; an unavailable method shows a notice without substituting an active-note command or custom editor. Physical iPhone and minimum-version acceptance remain pending. These checks establish correctness, not overall latency or production performance.

Obsidian rename events have no actor: unmarked external or third-party filename changes also follow the existing title-sync setting. Imported calendar titles remain provider-owned; a later external sync may restore its provider title and filename. No provider-title override is added.
