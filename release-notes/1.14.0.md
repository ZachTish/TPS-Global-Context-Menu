# TPS Global Context Menu 1.14.0

## Intent

Make TPS Base rows behave like first-class Base records without pretending that unsupported native behavior succeeded. This release centralizes formula and line-metadata semantics, makes Kind identity additive, and restores typed checkbox controls.

## User-visible changes

- TPS Table and TPS List evaluate top-level Base formulas for synthesized checkbox tasks, bullets, headings, and inline-property records. Formula values can drive configured display columns, filters, search, sorting, grouping, and totals.
- Custom checkbox/boolean properties render as accessible native checkbox controls instead of literal `true`/`false` text. Notes persist real YAML booleans; line items persist explicit lowercase inline boolean values.
- TPS Table now resolves the visible title of unordered and ordered checkbox tasks through the same canonical parser used by every synthetic line surface. Markdown formatting, wiki-link aliases, tags, inline fields, native block IDs, and hidden TPS carriers no longer leak into the title column.
- TPS Table uses one native two-axis scroll owner, does not intercept wheel/pointer gestures, and restores both axes after safe rerenders. TPS List gives note, task, bullet, and heading rows the same semantic leading slot, removing checkbox-dependent indentation from file rows while preserving real task checkboxes and nesting.
- Bare Kind matching is additive. Every checkbox row is structurally a task, notes may independently declare `kind: task`, and a checkbox with an explicit project identity belongs to both task and project sets.
- Entity pickers that accept Kind `task` now include structural checkbox rows as well as explicitly identified notes/lines. Choosing a line materializes and stores a normal Obsidian block link only after the guarded selection succeeds.

## Shared contracts and reliability

- `plugin.api.formulas` version 1 is the single bounded, compiled evaluator used by GCM and compatible TPS consumers.
- `plugin.api.lineMetadata` version 1 is the single read-only, single-bundle parser contract for nested inline fields, semantic tags, plain visible line titles, missing-versus-blank values, and scalar/comma/bracket list normalization that preserves wikilink commas.
- `plugin.api.entityIndex` version 3 adds explicit `entityTypes` and structural `lineKinds` query scopes. Block-aware readiness is complete-or-error: bounded source-read failures reject with `entity-index-incomplete` and failed paths rather than publishing a partial result as authoritative.
- Native note rows keep Obsidian's native formula results. Synthetic rows expose explicit row/note/file/task/line/heading/external contexts and share one frozen `now` per refresh.
- Formula fields are read-only. Missing/incompatible APIs, unsupported operations, cycles, invalid results, stale prospective lines, and every evaluated formula failure—including inside `not` or before a later true `or` branch—fail closed with deduplicated diagnostics. Filter branches use stored-order short-circuiting, so unreachable work is not evaluated.
- GCM emits the supported `tps:gcm-api-changed` workspace event on API installation/removal, allowing Calendar and Kanban to clear caches and rerender without polling or private lifecycle hooks.
- Version-1 `configuration`, `taskLines`, and `taskCheckboxes` capabilities expose the exact cross-plugin decisions and task UI/mapping operations Calendar and Kanban need. Consumers no longer read GCM's private settings, service fields, development-folder aliases, or Obsidian plugin registry.
- Standalone TPS Table and TPS List instances resolve their exact owning `.base` through public workspace-leaf, `View.containerEl`, and `FileView.file` contracts. Split panes no longer depend on the globally active file or guessed controller fields; GCM-owned embeds retain their exact stamped source, and an unresolved source-dependent operation fails closed.
- Public Obsidian ListValue, ObjectValue, RegExpValue, DateValue, DurationValue, LinkValue, FileValue, BooleanValue, NumberValue, and string-like wrappers have explicit adapters. Unknown or opaque Value subclasses fail instead of being formatted as a misleading `{}`.
- Formula execution uses no `eval`, `Function`, private Bases evaluator, temporary-note evaluation, global monkeypatch, or same-name-property fallback.

## Compatibility and migration

- This is a backward-compatible minor release.
- Minimum supported Obsidian remains 1.10.0.
- Existing settings, commands, note data, native-note formula behavior, and stored entity links need no data migration. Cross-plugin block consumers must require Entity Index version 3; Calendar and Kanban releases using this contract require GCM 1.14.0 or newer and fail closed when it is absent or incomplete.
- Formula authors should use `row.kinds.contains("task")` for additive identity. `row.kind`, `row.itemKind`, and `row.itemType` intentionally remain structural; `row.explicitKind` exposes only the explicit custom identity.
- Inline Markdown property values intentionally remain strings. Use explicit interpretation such as `number(points)`, `date(scheduled)`, `allDay == "true"`, `labels.split(",")`, or `link(owner)`; documented `list(value)` only wraps a scalar. This release does not infer types without an authoritative property schema.

## Supported and intentionally unsupported formula behavior

- The deterministic subset covers documented arithmetic, comparisons, booleans, dependencies, dates/durations, strings, numbers, lists including bounded map/filter/reduce, objects, regular expressions, local file metadata, and links.
- `random()`, `file()`, `html()`, `image()`, `icon()`, backlinks/embeds, and link target resolution remain explicitly unsupported for synthetic rows because their results cannot be reproduced from the supplied row snapshot alone.
