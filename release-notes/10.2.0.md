# TPS Global Context Menu 10.2.0 — Flat kind lists and subtype properties

Kind-list classifications now accept a flat value such as `entity` or `transaction`, using the existing configurable shared-path identity property for a subtype such as `entityKind: recipe` or `transactionKind: investment`. Property names and values are configurable; no taxonomy is hardcoded. Existing nested paths, tags, property mappings, IDs and defaults remain compatible.

The existing classification settings explain that a list value can be flat. No controls were removed. Existing discrimination, ambiguity checks and atomic write boundaries remain; a parent alone cannot choose a shared subtype. This adds no scan, watcher, timer, cache or automatic migration. The existing list writer preserves unrelated root values. App import formats must independently support the same mapping before a live vault is migrated.

## Validation

- Full versioned `npm test`: **1,964 passed**, zero failures/skips, including its build. Focused classification and native-record suites cover create/resolve/cold discovery for accounts, holdings, foods, recipes, meals, financial/investment transactions, food/activity entries, workouts, tasks, projects and collections.
- Existing configurations and reserved/unsafe keys retain regression coverage. Missing/contradictory subtype fields remain rejected or unresolved rather than guessed.
- Final separate production build and stable test deployment completed. The test plugin was explicitly reloaded as **10.2.0**. An installed public-API inspection recognized a synthetic flat transaction plus configured food-entry subtype; its temporary in-memory mapping was restored. Runtime-owned settings were preserved. This is nonvisual classification validation; no new visual control was introduced.
- No production code/settings/notes were deployed or migrated by this release. Physical iPhone acceptance is unverified. No timing improvement is claimed.

## Compatibility

Minimum Obsidian **1.10.0**. Additive minor release. No schema migration. Source and BRAT artifacts are published; installation in production remains the user's BRAT pull.
