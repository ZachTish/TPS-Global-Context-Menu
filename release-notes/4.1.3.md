# TPS Global Context Menu 4.1.3 — Index whole-note child navigation

Opening a parent note no longer inspects every loaded file to find child notes. GCM seeds a transient reverse index from the configured whole-note parent property outside navigation, updates affected entries on existing file/metadata/companion events, and refreshes mounted note menus once when the index is ready. Native whole-note mode also stops scanning body lines for the top Children button. Legacy mode keeps body-only child links, and the independent child-link checkbox presentation remains configurable. The context menu now labels each child removal row **Unlink** followed by the child title; the open row keeps the child title, and the child count remains one per relationship. No note content, settings schema, writer, public API, or compatibility requirement changes. Minimum Obsidian remains **1.10.0**.

This index is a read-only view of current frontmatter, not a second authority or recovery system. A parent-key or architecture change rebuilds it once; ignore rules remain live display checks. Explicit relationship pickers and the full relationship panel may still enumerate candidates. The legacy companion catalog can read Markdown during startup. If index seeding fails, GCM logs an error and leaves child navigation pending without a background retry or per-open fallback.

## Validation

- A synthetic 10,003-file seed made one loaded-file inventory and 10,003 direct metadata lookups in 15.7 ms on a desktop test harness. Fifty repeated empty-parent renders through the real persistent-navigation methods then made **zero** vault inventories, metadata lookups, body reads, and writes. This is an operation-count regression, not an installed or physical-iPhone latency measurement.
- Focused coverage includes a parent opened before index readiness, single-pass cold and mounted menu refreshes, parent links that retarget during final metadata resolution, metadata and file lifecycle events, same-path TFile replacement, unresolved bare paths, folder rename, companion-backed files, Canvas JSON edits, confirmed migration events, native/legacy mode switches, ignore rules, startup failure, and unload during legacy initialization. Native top Children lookup makes no body scan; legacy body-only children remain available.
- A focused menu regression verifies that one indexed child produces a **Link Children (1)** badge, one open row, one distinctly labeled unlink row, and the original action targets. The focused menu suite passes **22/22** checks.
- The complete versioned declared `npm test` workflow passed **1,472/1,472** checks across 57 groups with zero failures or skips, including TypeScript and a build with runtime deployment suppressed. The separate `npm run build` deployed the final bundle to the Test vault; source and installed artifact hashes match, and the installed GCM plugin was disabled and re-enabled there. In the reloaded Test-vault UI, an archived parent with one child showed **Link Children (1)**, one child-opening row, and a distinct **Unlink** row. Selecting the opening row displayed the intended child note. The plugin's Test-vault `data.json` remained byte-identical. Physical-iPhone latency was not measured.
