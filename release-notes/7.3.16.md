# TPS Global Context Menu 7.3.16

Backward-compatible patch that lets initial parent/child relationship indexing
release host tasks when its existing elapsed-work budget reaches 8 ms. Tested in
Obsidian Plugin Test Vault on a focused, visible Mac window with all eight active
TPS consumers enabled. This is a BRAT testing handoff; production installation
and user acceptance remain separate.

## Change

The initial relationship owner now cooperates without adding another inventory.
The atomic inventory cost counts toward the budget, and folder entries cannot
bypass checkpoints. Cheap work below the budget does not require a task yield.
MessageChannel and timer fallbacks release actual tasks; the browser scheduler
branch retains its existing feature detection.

Readiness is published only after the complete relationship graph and accepted
create/edit/delete/file/folder rename events have settled against current files.
Settings changes and unload revoke superseded owners. Provisional resolution,
legacy companion prerequisites, failure handling and joined settings callers
retain their protections. No additional writer, persistent metadata cache,
poller, watcher, repair, setting, API version or stored-note migration is added.
Minimum Obsidian remains **1.10.0**.

## Limits and artifacts

Explicit/settings relationship rebuilds remain synchronous. The 8 ms budget is
a cooperation threshold; it cannot preempt an atomic operation, inventory,
garbage collection or host scheduling delay. Native `scheduler.yield()` is
absent in this Obsidian host; installed task evidence uses MessageChannel.
Whole-renderer CPU deltas include other threads and are not isolated Parent CPU.
Physical iPhone, Windows, whole-process cold startup and input-to-paint latency
remain unverified. No production deployment or production-ready claim is made.
