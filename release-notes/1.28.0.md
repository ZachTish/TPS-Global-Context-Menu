# TPS Global Context Menu 1.28.0

TPS Global Context Menu `1.28.0` makes the Daily Note task-move source behavior configurable and lays a privacy-bounded local history foundation for a future per-item history modal.

## Daily Note task moves

- **Workflows → Tasks → After moving a task from a Daily Note** offers **Keep a migrated marker** and **Remove the source block**. The migrated marker remains the compatibility-preserving default.
- The remove choice deletes the complete source task block only after the destination write is confirmed. The moved destination retains the task's stable identity; no bulk note migration runs when the setting changes.
- Task API v3 adds `sourcePolicy: configured-daily-note`. Existing explicit `remove` and `migrate-if-daily-note` requests retain their previous semantics.
- GCM context-menu and drag moves use the configured policy. TPS Controller 0.4.2 also uses it for the notification sidebar's explicit reminder move and refuses that action with an older Task API rather than risk legacy source removal.

## Local item history foundation

- **Keep local item history** records confirmed direct-user task actions in a vault-scoped IndexedDB journal on the current device. It defaults on and can be disabled without deleting retained events.
- Tracked actions include task creation, status/priority/tag/checkbox updates, other text edits as a generic changed event, moves and Daily Note migrations, and deletion across GCM's task menu, Create task, TPS Home, TPS List, TPS Table, rendered inline-property, checkbox, and drag surfaces. Task API v3 callers participate only when they pass an explicit user cause.
- A surviving tracked task adopts or receives `tpsId` in the same guarded content mutation. Pending intent is stored first; the immutable event and current/deleted entity state are committed only after content success. No-op, cancel, stale, ambiguous, rolled-back, or unconfirmed outcomes do not become successful history. Strong post-crash evidence is reconciled on startup; uncertain intent expires after 24 hours.
- Stored state is an allowlist: canonical checkbox token, status, priority, redacted tags, action/cause, timestamps, stable ID, vault-relative source/destination locator, and move disposition. Those locators can contain note filenames, but raw task lines, task titles/content, note bodies, arbitrary inline properties, external/recurrence identities, and links or URLs are never stored. Other confirmed text changes use the sentinel `[changed]` rather than the text.
- Retention defaults to 90 days, with a one-year hard maximum, 25,000 events per vault, and 200 events per task. Pruning is bounded and asynchronous after mutations. History failure is fail-open for content: it is logged once and never rolls back an otherwise valid task edit.
- `plugin.api.history` v1 exposes entity resolution, stable timestamp-and-event-ID cursor pagination, bounded query, stats, prune, and clear operations for the future modal. The history surface remains queryable and clearable while new recording is off.

## Compatibility and limitations

- This is a backward-compatible minor release. It adds settings and optional Task API arguments without changing existing call shapes or legacy source policies.
- Reloading GCM while TPS Home is open now initializes Home action routing before Obsidian restores the persisted view, avoiding the transient unavailable-action crash found during final test-vault QA.
- Existing notes are not scanned or bulk-tagged with identities. A surviving task receives history identity only in its first tracked mutation.
- History v1 covers task-line entities and explicit user causes. Whole-note/frontmatter history, AI-assisted task creation and background automation, time-tracking session bookkeeping, raw editor typing and editor-only line commands without a durable vault-write confirmation, synchronized cross-device history, and the visual history modal are intentionally outside this release.
- Minimum supported Obsidian version remains `1.10.0`.
